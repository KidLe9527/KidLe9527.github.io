#### 1. 迭代器的使用

> ### 核心结论
>
> 迭代器**不是必须**只用 `->`，用 `.` 还是 `->` 取决于你拿到的是**迭代器对象本身**还是**迭代器的指针 / 引用**；迭代器的行为**非常类似指针**（可以理解为 “封装版的智能指针”），但本质是对象而非原生指针。
>
> ### 一、迭代器的两种访问方式（`.` vs `->`）
>
> 迭代器是一个**对象**，但它重载了 `*`（解引用）和 `->`（成员访问）运算符，模拟指针的行为。访问迭代器指向元素的成员时，有两种等价写法：
>
> | 访问方式  |    语法格式    |        适用场景        |
> | :-------: | :------------: | :--------------------: |
> | 箭头 `->` |  `it->member`  | 直接通过迭代器对象访问 |
> |  点 `.`   | `(*it).member` | 先解引用迭代器，再访问 |

#### 3. 哈希表遍历

```cpp
// 假设哈希表 m 的定义：unordered_map<string, vector<string>> m;
vector<vector<string>> ans;  // 定义最终要返回的结果数组
ans.reserve(m.size());       // 预分配内存空间，优化性能
for (auto& [_, value] : m) {
            ans.push_back(value); // 哈希表的 value 保存分组后的结果
        }
```

**C++17 结构化绑定语法**：遍历哈希表 `m` 的每一个键值对（`pair<string, vector<string>>`），并直接解构为两个变量：

- `_`：代表哈希表的 Key（排序后的字符串，比如 `"eilnst"`），用下划线表示 “这个变量不需要使用”，是编程中的约定俗成写法。
- `value`：代表哈希表的 Value（一组异位词，比如 `vector<string>{"listen", "silent"}`）。
- `auto&`：使用引用避免拷贝（`value` 是 `vector<string>`，拷贝成本高，引用直接指向原数据）。

**等价的传统写法（C++17 之前）**：

```cpp
for (auto& pair : m) {
    vector<string>& value = pair.second; // pair.first 是 Key，pair.second 是 Value
    ans.push_back(value);
}
```



#### 4.`unordered_set`不可以被引用

```cpp
unordered_set<int> st(nums.begin(), nums.end()); // 把 nums 转成哈希集合
for (int x : st) { // 遍历哈希集合✅
          }

for(int& x : st) {} //❌ set集合底层是红黑树（二叉排序树），因此值是不允许修改的，否则这棵树将不再是排序树
```

> unordered_set（包括所有 C++ 标准库的 “集合” 容器，如 `set`）的设计原则是：**元素一旦插入，就不允许被修改**（否则会破坏哈希表 / 红黑树的结构，导致查找、遍历等操作出错）。
>
> 因此，`unordered_set` 对外暴露的迭代器是**常量迭代器（const_iterator）**，遍历得到的元素本身是 “只读的”，无法绑定到非 const 引用（`int&`）上。
