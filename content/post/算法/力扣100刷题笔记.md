1. 迭代器的使用

> ### 核心结论
>
> 迭代器**不是必须**只用 `->`，用 `.` 还是 `->` 取决于你拿到的是**迭代器对象本身**还是**迭代器的指针 / 引用**；迭代器的行为**非常类似指针**（可以理解为 “封装版的智能指针”），但本质是对象而非原生指针。
>
> ### 一、迭代器的两种访问方式（`.` vs `->`）
>
> 迭代器是一个**对象**，但它重载了 `*`（解引用）和 `->`（成员访问）运算符，模拟指针的行为。访问迭代器指向元素的成员时，有两种等价写法：
>
> | 访问方式  |    语法格式    |        适用场景        |
> | :-------: | :------------: | :--------------------: |
> | 箭头 `->` |  `it->member`  | 直接通过迭代器对象访问 |
> |  点 `.`   | `(*it).member` | 先解引用迭代器，再访问 |

#### 3. 哈希表遍历

```cpp
// 假设哈希表 m 的定义：unordered_map<string, vector<string>> m;
vector<vector<string>> ans;  // 定义最终要返回的结果数组
ans.reserve(m.size());       // 预分配内存空间，优化性能
for (auto& [_, value] : m) {
            ans.push_back(value); // 哈希表的 value 保存分组后的结果
        }
```

**C++17 结构化绑定语法**：遍历哈希表 `m` 的每一个键值对（`pair<string, vector<string>>`），并直接解构为两个变量：

- `_`：代表哈希表的 Key（排序后的字符串，比如 `"eilnst"`），用下划线表示 “这个变量不需要使用”，是编程中的约定俗成写法。
- `value`：代表哈希表的 Value（一组异位词，比如 `vector<string>{"listen", "silent"}`）。
- `auto&`：使用引用避免拷贝（`value` 是 `vector<string>`，拷贝成本高，引用直接指向原数据）。

**等价的传统写法（C++17 之前）**：

```cpp
for (auto& pair : m) {
    vector<string>& value = pair.second; // pair.first 是 Key，pair.second 是 Value
    ans.push_back(value);
}
```



#### 4.`unordered_set`不可以被引用

```cpp
unordered_set<int> st(nums.begin(), nums.end()); // 把 nums 转成哈希集合
for (int x : st) { // 遍历哈希集合✅
          }

for(int& x : st) {} //❌ set集合底层是红黑树（二叉排序树），因此值是不允许修改的，否则这棵树将不再是排序树
```

> unordered_set（包括所有 C++ 标准库的 “集合” 容器，如 `set`）的设计原则是：**元素一旦插入，就不允许被修改**（否则会破坏哈希表 / 红黑树的结构，导致查找、遍历等操作出错）。
>
> 因此，`unordered_set` 对外暴露的迭代器是**常量迭代器（const_iterator）**，遍历得到的元素本身是 “只读的”，无法绑定到非 const 引用（`int&`）上。



#### 5. 字符串的find函数

> `std::string::find` 是 `string` 类的成员函数，核心作用是：**在当前字符串中查找指定的字符 / 子串，返回其第一次出现的起始下标；若未找到，返回特殊常量 `string::npos`**。🔥注意和容器的find函数区别！
>
> 简单说，就是 “在字符串里找目标，找到返回位置，找不到返回一个特殊值”。
>
> ### 二、函数重载（4 种常用形式）
>
> `find` 有多个重载版本，适配不同的查找目标，参数和用法如下（优先级从常用到少见）：
>
> |                         函数原型                          |                           功能说明                           |
> | :-------------------------------------------------------: | :----------------------------------------------------------: |
> |       `size_t find(char c, size_t pos = 0) const;`        |     从下标 `pos` 开始，查找单个字符 `c` 第一次出现的位置     |
> |   `size_t find(const string& s, size_t pos = 0) const;`   |      从下标 `pos` 开始，查找字符串 `s` 第一次出现的位置      |
> |    `size_t find(const char* s, size_t pos = 0) const;`    |  从下标 `pos` 开始，查找 C 风格字符串 `s` 第一次出现的位置   |
> | `size_t find(const char* s, size_t pos, size_t n) const;` | 从下标 `pos` 开始，查找 C 风格字符串 `s` 的前 `n` 个字符第一次出现的位置 |
>
> #### 关键参数说明：
>
> - `pos`：查找的起始位置，默认值为 `0`（从字符串开头找），类型是 `size_t`（无符号整数，不能传负数）；
> - `n`：仅最后一个重载使用，指定要查找的 C 风格字符串的前 `n` 个字符；
> - 返回值：`size_t`（无符号整数），找到则返回起始下标，未找到返回 `string::npos`。
>
> ### 四、关键细节（避坑核心）
>
> #### 1. 返回值：`size_t` 和 `string::npos`
>
> - `size_t` 是无符号整数类型（对应系统的 `unsigned int`/`unsigned long long`），**不能用 `int` 接收返回值**（否则 `npos` 会被转成负数，导致判断错误）；
> - `string::npos` 是 `string` 的静态常量，值为 `size_t` 类型的最大值（如 32 位系统是 `4294967295`），是 “未找到” 的唯一判断依据；
> - 错误写法：`if (pos < 0)` / `if (pos == -1)`（无符号数永远不会小于 0）；
> - 正确写法：`if (pos == string::npos)`（未找到）/ `if (pos != string::npos)`（找到）。
>
> #### 2. 查找规则
>
> - `find` 是**大小写敏感**的：`str.find("world")` 找不到 `"World"`；
> - 查找的是 “连续的子串”：`str = "abcde"`，`find("ace")` 会返回 `npos`（因为 ace 不连续）；
> - 起始位置 `pos` 超过字符串长度：直接返回 `npos`（比如 `str="test"`，`find('t', 10)` 返回 `npos`）。
>
> #### 3. 与其他查找函数的区别（拓展）
>
> `find` 是 “从左到右找第一次出现”，C++ 还提供了其他方向的查找函数，可按需使用：
>
> - `rfind`：从右到左找最后一次出现的位置；
> - `find_first_of`：找目标中**任意一个字符**第一次出现的位置；
> - `find_last_of`：找目标中**任意一个字符**最后一次出现的位置。

##### `substr()`函数：

#### 6. 题型思路：连续子数组求和 🔥

> * 在求连续字数组和等问题时，如果数组值非负数，可以考虑滑动窗口思路；
> * 但是如果存在负数值，那么滑动窗口就不太方便，因为要考虑缩小窗口的方向，因为滑动窗口需要保持单调性
> * 这时候可以考虑前缀和思想，将求字数组的和转化为求两个前缀和的减法，这其实就是求两数之和-> 然后还可以通过右枚举，左维护的思路，
> * 结合哈希查找，进一步优化查询的效率。

1. **特性决定基础方法**：数组全非负→滑动窗口（单调性），含负数→前缀和（无单调性，数学转化更通用）；
2. **数学转化降维**：将「子数组和」转化为「两个前缀和的差」，本质是「两数之和」的变形；
3. **哈希优化提效**：右枚举 + 左哈希维护，将 O (n²) 的暴力解法优化为 O (n)，是这类问题的最优解思路。

这个思路不仅适用于「和为 k 的子数组数」，还能迁移到「最长子数组和为 k」「和为 k 的最短子数组（非负）」等同类问题，是解决连续子数组和问题的核心方法论。





#### 7. 题型思路：滑动窗口极值

> ### 一、先明确：单调队列是什么？
>
> 单调队列（Monotonic Queue）本质是对「双端队列（deque）」的**规则化使用**：
>
> - 队列内的元素（通常是下标，或对应的值）严格遵守「单调递增」或「单调递减」的顺序；
> - 插入新元素时，会主动移除队列中破坏单调性的元素，保证队列始终满足规则；
> - 队列的头部 / 尾部可以快速获取「极值」（最大值 / 最小值）。
>
> > 注意：单调队列不是 C++/Java 等语言提供的内置容器，而是开发者根据需求自定义的「逻辑结构」，底层依赖双端队列实现。
>
> #### 2. 关键性质（4 个核心）
>
> |  性质  |                             解释                             |
> | :----: | :----------------------------------------------------------: |
> | 单调性 | 队列内元素对应的值严格单调（递增 / 递减），是所有性质的基础  |
> | 极值性 | 队列头部一定是当前窗口 / 区间内的「极值」（递减队列→最大值，递增队列→最小值） |
> | 时效性 | 队列内只保留「可能成为后续窗口极值的候选元素」，无效元素被提前剔除，无冗余 |
> | 高效性 | 每个元素最多入队、出队各一次，整体时间复杂度 O (n)（暴力是 O (nk)） |
>
> ### 单调队列的使用技巧（避坑指南）
>
> 1. **存储下标而非值**：
>
>    - 原因：① 方便判断元素是否超出窗口范围（如 `dq.front() <= i-k`）；② 处理重复值时不会出错（比如窗口内有多个相同最大值）；
>
>    
>
> 2. **区分「严格单调」和「非严格单调」**：
>
>    - 严格递减：`nums[i] > nums[q.back()]`，适合需要「严格最大值」的场景；
>    - 非严格递减：`nums[i] >= nums[q.back()]`，适合有重复值的场景（避免漏算）；
>
>    
>
> 3. **先清「过期元素」，再维护单调性**：
>
>    - 错误顺序：先维护单调性，再清过期元素 → 可能导致队列头部是过期元素，获取错误极值；
>    - 正确顺序：先移除超出窗口的头部元素，再移除尾部破坏单调性的元素，最后加入当前元素。



**单调队列的实现逻辑（通用模板）**

以「滑动窗口极值」为例，给出通用实现模板（C++），记住这个模板就能解决 80% 的单调队列问题：

```cpp
vector<int> monotonicQueueTemplate(vector<int>& nums, int k) {
    vector<int> ans;
    deque<int> dq; // 存储下标，而非值（关键！）
    
    for (int i = 0; i < nums.size(); ++i) {
        // 步骤1：移除「超出窗口范围」的头部元素（窗口左边界：i-k）
        if (!dq.empty() && dq.front() <= i - k) {
            dq.pop_front();
        }
        
        // 步骤2：维护队列单调性（以递减队列为例）
        while (!dq.empty() && nums[i] >= nums[dq.back()]) {
            dq.pop_back(); // 移除破坏单调性的尾部元素
        }
        
        // 步骤3：加入当前元素下标
        dq.push_back(i);
        
        // 步骤4：窗口形成后，收集结果（i >= k-1 时窗口成型）
        if (i >= k - 1) {
            ans.push_back(nums[dq.front()]); // 头部是极值
        }
    }
    return ans;
}
```

**模板关键解读**：

1. 存储「下标」而非「值」：方便判断元素是否超出窗口范围（`dq.front() <= i-k`）；
2. 「先清过期，再维护单调」：先移除窗口外的无效元素，再维护单调性，顺序不能反；
3. 窗口成型后收集结果：只有当 `i >= k-1` 时，窗口才是完整的，此时头部才是有效极值。



#### 8. 关于vector容器的一个误区

`std::vector` 的设计规则：

> `vector` 的**对象本身**（比如函数参数 `vector<int>& nums`）如果是局部变量，会存在栈上；但 `vector` 内部存储元素的**动态数组**，**永远分配在堆上**。
>
> `vector` 作为一个局部变量，它的 “管理结构”（比如指向数据的指针、容量、大小等）会存在栈里；`vector` 内部会通过 `new`（或类似动态分配方式）在堆区开辟连续内存，用来存实际的数据 ---> 它管理的**数据存储在堆区**，这也是它能支持动态扩容、灵活调整大小的关键（堆区适合大 / 动态内存分配）。
>
> ### 例外情况：什么时候数组不在堆上？
>
> 只有一种情况你的函数操作的不是堆内存 —— 当函数参数是**普通数组（栈数组）**
>
> ` int arr[3] = {1,2,3}; // 普通数组，存储在栈上`

> - 空间复杂度：`O(1)`（原地反转，无额外内存分配）；
> - 原地操作：直接修改原容器的元素顺序，不会创建副本。

> 由于链表长度不同，数位不一定对齐，所以灵神的思路是：反转链表，就是上一题链头是最低位，链尾是最高位，直接加和修改链长更长的节点值--->反转链表 + 链表的两数之和
>

>
> ```cpp
> /**
>  * Definition for singly-linked list.
>  * struct ListNode {
>  *     int val;
>  *     ListNode *next;
>  *     ListNode() : val(0), next(nullptr) {}
>  *     ListNode(int x) : val(x), next(nullptr) {}
>  *     ListNode(int x, ListNode *next) : val(x), next(next) {}
>  * };
>  */
> class Solution {
> public:
>     // 计算链表长度
>     int getListLength(ListNode* head) {
>         int len = 0;
>         while (head != nullptr) {
>             len++;
>             head = head->next;
>         }
>         return len;
>     }
> 
>     // 主函数：对外接口，处理最终剩余进位
>     ListNode* addTwoNumbers(ListNode* l1, ListNode* l2) {
>         // 1. 计算两个链表的长度，确定哪个链表更长（作为承载结果的链表）
>         int len1 = getListLength(l1);
>         int len2 = getListLength(l2);
>         // 让 longList 指向更长的链表，shortList 指向更短的链表，方便后续原地修改
>         ListNode* longList = (len1 >= len2) ? l1 : l2;
>         ListNode* shortList = (len1 >= len2) ? l2 : l1;
>         int lenLong = max(len1, len2);
>         int lenShort = min(len1, len2);
> 
>         // 2. 定义进位（引用捕获给 lambda）
>         int carry = 0;
> 
>      // 3. 递归式 lambda（DFS）：从后往前计算，原地修改 longList 的值
>         // 注意：C++17 及以上支持 this auto&& 实现递归 lambda
>         auto dfs = [&](this auto&& dfs, ListNode* lLong, ListNode* lShort, int lenLong, int lenShort) -> void {
>             // 递归终止条件：遍历到 longList 的末尾
>             if (lLong == nullptr) {
>                 return;
>             }
> 
>             // 步骤1：先递归到链表末尾（从后往前计算，先处理后续节点的进位）
>             if (lenLong > lenShort) {
>                 // longList 更长，shortList 无对应节点，递归处理 longList 的下一个节点
>                 dfs(lLong->next, lShort, lenLong - 1, lenShort);
>                 // 回溯时计算：当前 longList 节点值 + 后续节点产生的进位
>                 int sum = lLong->val + carry;
>                 lLong->val = sum % 10;    // 原地修改 longList 节点值
>                 carry = sum / 10;         // 更新进位
>             } else {
>                 // 两个链表长度对齐（lenLong == lenShort），递归处理两个链表的下一个节点
>                 dfs(lLong->next, lShort->next, lenLong - 1, lenShort - 1);
>                 // 回溯时计算：longList 值 + shortList 值 + 后续节点产生的进位
>                 int sum = lLong->val + lShort->val + carry;
>                 lLong->val = sum % 10;    // 原地修改 longList 节点值
>                 carry = sum / 10;         // 更新进位
>             }
>         };
> 
>         // 4. 调用 DFS，传入长链表、短链表及其长度

> 
>         // 5. 处理最终剩余的进位（若有，需在长链表头部新增节点）
>         if (carry > 0) {
>             ListNode* newHead = new ListNode(carry);
>             newHead->next = longList;
>             return newHead;
>         }
> 
>         // 6. 无剩余进位，直接返回修改后的长链表
>         return longList;
>     }
> };
> ```

#### 23.[链表排序](https://leetcode.cn/problems/sort-list/description/?envType=study-plan-v2&envId=top-100-liked) 🔥

> 这题的难度完全取决于要求的**空间复杂度**。要求O(n)就是简单题, O(logn)就是中等题, O(1)就是困难题
>
> * O(n) ： 遍历链表，用一个数组存储节点值，然后ranges::sort排序（快排和归并排序的优化版本，时间 O(nlogn)），然后再遍历一遍链表，给每个节点**赋值**，没错赋值，不要求节点值不能改，大意了，用了unordered_multimap作为哈希发现太麻烦了
> * O(logn)：递归 + 归并排序
> * O(1)：迭代法 + 归并排序，仅了解，太☹️了
>
> ```cpp
> // 第二种做法，递归 + 归并
> class Solution {
> public:
>     ListNode* sortList(ListNode* head) {
>         if(!head || !head->next)    return head;
> 
>         ListNode *dummy = new ListNode(0, head);
>         ListNode *pre = dummy;
>         // 找到链表的中间节点，分成两条链表
>         ListNode *slow = head, *fast = head;
>         while(fast && fast->next){
>             pre = slow; // 用pre记录slow的前驱节点
>             slow = slow->next;
>             fast = fast->next->next;
>         }
> 
>         ListNode *List1 = dummy->next;
>         ListNode *List2 = slow;
>         pre->next = nullptr;	// ⚠️ 必须断开两个子链表的连接
>     
>         List1 = sortList(List1);	// 接收递归调用函数的返回值，找到子链表的头节点，作为下一次合并的头节点
>         List2 = sortList(List2); 
>         return mergeTwoLists(List1, List2);
>     }
>   
> 		// 辅助函数，合并两个链表-->要求返回值是新链表的头节点
>     ListNode* mergeTwoLists(ListNode* l1, ListNode* l2){
>         ListNode *dummy = new ListNode(0);
>         ListNode *pre = dummy;
>         while(l1 || l2){
>             int v1 = l1 ? l1->val : INT_MAX;
>             int v2 = l2 ? l2->val : INT_MAX;
>             if(l2 && v1 >= v2){
>                 pre->next = l2;
>                 l2 = l2->next;
>             }else{
>                 pre->next = l1;
>                 l1 = l1->next;
>             }
>             pre = pre->next;
>         }
>         return dummy->next;
>     }
> };
> ```

>   class Solution {
>       // 合并从 lists[i] 到 lists[j-1] 的链表
>       ListNode* mergeKLists(vector<ListNode*>& lists, int i, int j) {
>           int m = j - i;
>           if (m == 0) {
>               return nullptr; // 注意输入的 lists 可能是空的
>           }
>           if (m == 1) {
>               return lists[i]; // 无需合并，直接返回
>           }
>           auto left = mergeKLists(lists, i, i + m / 2); // 合并左半部分
>           auto right = mergeKLists(lists, i + m / 2, j); // 合并右半部分
>           return mergeTwoLists(left, right); // 最后把左半和右半合并
>       }
>   
>   public:
>       ListNode* mergeKLists(vector<ListNode*>& lists) {
>           return mergeKLists(lists, 0, lists.size());	// ⚠️这里区间左闭右开，刚好覆盖所有节点不会越界❗️
>       }
>   };
>   ```
>

>
>   ```cpp
>   ListNode* mergeKLists(vector<ListNode*>& lists) {
>           int m = lists.size();
>           if (m == 0) {
>               return nullptr;
>           }
>           for (int step = 1; step < m; step *= 2) {	// 这里的step是每次归并的步长
>               for (int i = 0; i < m - step; i += step * 2) {
>                   lists[i] = mergeTwoLists(lists[i], lists[i + step]);
>               }
>           }
>           return lists[0];
>       }
>

>   链接：https://leetcode.cn/problems/merge-k-sorted-lists/solutions/2384305/liang-chong-fang-fa-zui-xiao-dui-fen-zhi-zbzx/
>   来源：力扣（LeetCode）

>   ```
>
> * 使用堆的数据结构，因为堆支持
>
>   * 从数据结构中找到并移除最小节点。
>   * 插入节点（如果一条链表的头节点是当前所有链表的最小节点，那么下一个可能的最小节点是其他的链头节点或者当前的头节点的下一个节点）

>   class Solution {
>   public:
>       ListNode* mergeKLists(vector<ListNode*>& lists) {
>           auto cmp = [](const ListNode* l1, const ListNode* l2){ 
>               return l1->val > l2->val; 
>           };
>           // 优先队列作最小堆
>           std::priority_queue<ListNode*, vector<ListNode*>, decltype(cmp)> pq(cmp); 
>     
>           for(auto& head : lists){
>               if(head){
>                   pq.push(head);	// 把所有非空链表的头节点入堆

>           }
>     
>           ListNode dummy{};
>           ListNode *cur = &dummy;

>               ListNode *node = pq.top();
>               pq.pop();
>               if(node->next){
>                   pq.push(node->next);	// 当前最小节点的下一节点f

##### morris算法和迭代栈解法

> * 最简单的就是递归，但是空间开销最大，取决于递归的栈深度，一般是On
>
> * 然后是利用迭代法模拟栈，也是On的空间复杂度
>
>   * 后续遍历的迭代栈需要记录遍历节点的前驱节点，因为不知道当前节点（如果左右子节点都有）是否遍历过其右子树
>
>   ```cpp
>   // 中序遍历的迭代栈
>   class Solution {
>   public:
>       vector<int> inorderTraversal(TreeNode* root) {
>           vector<int> ans;
>           stack<TreeNode*> stk;
>           while(root || !stk.empty()){
>               // 首先遍历树的左子树，加入栈，直到遇到空节点，说明到头了～
>               while(root){
>                   stk.push(root);
>                   root = root->left;
>               }
>               // 这时的栈顶节点就是没有左子树的节点，在中序遍历中是下一个访问节点
>               root = stk.top();
>               stk.pop();
>               ans.emplace_back(root->val);
>               // 访问完左 中 接下来访问右
>               root = root->right;
>           }
>   
>           return ans;
>       }
>   };
>   ```
>
> * 最好的是morris算法，空间复杂度为O1 ~~难哭了吓哭了蠢哭了~~
>
>   ```cpp
>   // 中序遍历的morris的核心是找到当前节点的前驱节点：即其左子树的最右节点 ⭐️
>   class Solution {
>   public:
>       vector<int> inorderTraversal(TreeNode* root) {
>           vector<int> ans;
>     
>           while (root) {
>               if (root->left) {
>                   // 找 root 的前驱 pre：在中序遍历中，root 的上一个节点
>                   // 从 root->left 开始，一直向右走，直到走到尽头，或者遇到指向 root 的线索（回到 root 的路）
>                   TreeNode* pre = root->left;
>                   while (pre->right && pre->right != root) {
>                       pre = pre->right;
>                   }
>     
>                   // root 的左子树尚未访问
>                   if (pre->right == nullptr) {
>                       pre->right = root; // 建立线索（回到 root 的路），相当于把 pre->right 当作栈
>                       root = root->left; // 访问左子树
>                       continue;
>                   }
>     
>                   // root 的左子树访问完毕，去掉线索，恢复原样
>                   pre->right = nullptr; // 注：如果调用完 inorderTraversal 不再使用这棵二叉树，这行代码可以去掉
>               }
>     
>               // root 的左子树访问完毕
>               ans.push_back(root->val); // 记录当前节点的值
>               root = root->right; // 如果有右子树就访问右子树，没有就顺着线索回到指向的节点
>           }
>     
>           return ans;
>       }
>   };
>   ```

#### 30. [验证二叉搜索树](https://leetcode.cn/problems/validate-binary-search-tree/description/?envType=study-plan-v2&envId=top-100-liked)

> **有效** 二叉搜索树定义如下：
>
> - 节点的左子树只包含 **严格小于** 当前节点的数。
> - 节点的右子树只包含 **严格大于** 当前节点的数。
> - 所有左子树和右子树自身必须也是二叉搜索树。
>
> ---
>
> * ⚠️ 二叉搜索树的根节点的值要大于整个 左子树的所有节点的值，小于所有右子树的值，在我第一次做的时候，就犯了错
> * 😭 不是~~左节点小于根节点小于右节点~~就行了
>
> 思路：
>
> 1. 首先想的是递归，每次比较当前节点和其左右子节点的值，理所当然的掉进陷阱里.......所以，附带当前节点允许的范围，每次递归缩小范围｜没想到哇，这种先访问（判断条件）当前节点再递归左右子🌲的方法，叫做<u>先序遍历</u>
>
>    ```cpp
>    class Solution {
>    public:
>        bool isValidBST(TreeNode* root) {
>            return isInRanges(root, LONG_MIN, LONG_MAX);
>        }
>    
>        bool isInRanges(TreeNode* root, long left, long right){
>            if(!root)   return true;
>            if(left >= root->val || root->val >= right) return false;
>            return isInRanges(root->left, left, root->val) && isInRanges(root->right, root->val ,right);
>        }
>    };
>    ```
>
> 2. 中序遍历 （左～中～右）天然契合BST性质，只需要判断当前节点值严格大于上一个访问的节点值
>
> 3. 后序遍历（左～右～中）跟先序遍历反着来，自底向上传递取值范围，如果节点为空，范围就是正无穷到负无穷～反的！
>
>    ```cpp
>    // 后序遍历验证二叉搜索树 ～有点小复杂😡
>    class Solution {
>        pair<long long, long long> dfs(TreeNode* node) {
>            if (node == nullptr) {
>                return {LLONG_MAX, LLONG_MIN};	// 注意空节点是左边最大，右边最小：这样可以保证被非空节点处理
>            }
>            auto[l_min, l_max] = dfs(node->left);
>            auto[r_min, r_max] = dfs(node->right);
>            long long x = node->val;
>            // 也可以在递归完左子树之后立刻判断，如果发现不是二叉搜索树，就不用递归右子树了
>            if (x <= l_max || x >= r_min) {
>                return {LLONG_MIN, LLONG_MAX};
>            }
>          	// 这里返回的是以当前节点为根节点的子树的节点值范围（最小值只可能是其左子树的最小值或者当前值～～）
>            return {min(l_min, x), max(r_max, x)};
>        }
>       
>    public:
>        bool isValidBST(TreeNode* root) {
>            return dfs(root).second != LLONG_MAX;	// 或者前驱不等于LLONG_MIN
>        }
>    };
>    ```



#### 31.[二叉搜索树中第k小的值](https://leetcode.cn/problems/kth-smallest-element-in-a-bst/description/?envType=study-plan-v2&envId=top-100-liked)

> 思路：利用中序遍历（左～中～右）和二叉树左子树小于根节点小于右子树的性质，**递归**解决问题
>
> 注意访问第k个节点的时候是先减k还是先判断条件，这里写法不同但是都可以｜如果先判断条件`if(k == 1)`再减k，那么在返回前必须改k值，不然后续全是true
>
> ```cpp
> int kthSmallest(TreeNode* root, int& k) {
>     if(!root)   return -1;
>     int left_val = kthSmallest(root->left, k);
>     --k;	// 先减k再判断，表示当前根节点被访问过☝️
>     if(k == 0)  return root->val;
>     int right_val = kthSmallest(root->right, k);
>     return left_val == -1 ? right_val : left_val;
> }
> 
> int kthSmallest(TreeNode* root, int& k) {
>         if (root == nullptr)	return -1; // 空节点，无意义返回（实际不会走到）
>    
>         // 1. 先遍历左子树，找更小的元素
>         int leftRes = kthSmallest(root->left, k);
>         // 左子树找到目标，直接向上返回，终止递归
>         if (leftRes != -1) {
>             return leftRes;
>         }
>         // 2. 遍历根节点，k减1，若k=0则当前根是目标
>          if (k == 1) {
>             return root->val;
>         }
>         k--;
>         // 3. 左子树和根都没找到，遍历右子树
>         return kthSmallest(root->right, k);
>     }
> ```
>
> 思考题：如果求第k大，那么从左中右改成右中左！！



#### 32.[从前序和中序遍历构造二叉树](https://leetcode.cn/problems/construct-binary-tree-from-preorder-and-inorder-traversal/description/?envType=study-plan-v2&envId=top-100-liked)

> 前序（中～左～右）、中序（左～中～右）：前序第一个是根节点，根据在中序中的位置，划分出左右子树的区间
>
> #### 🔥 正确的区间分割推导（必须掌握）易错❗️😡划分先序左右区间不能用`rootIdx`区分❗️ 
>
> 设当前递归：
>
> - 前序区间：`[pleft, pright)`，首元素`preorder[pleft]`是当前根节点；
> - 中序区间：`[ileft, iright)`，根节点在中序的下标为`rootIdx`；
>
> 则：
>
> 1. **左子树的节点数**：`leftSize = rootIdx - ileft`（中序中根左侧的元素数量）；
> 2. **左子树的前序区间**：`[pleft+1, pleft+1+leftSize)`（根后紧跟的`leftSize`个元素）；
> 3. **左子树的中序区间**：`[ileft, rootIdx)`（根左侧的所有元素）；
> 4. **右子树的前序区间**：`[pleft+1+leftSize, pright)`（左子树后剩余的元素）；
> 5. **右子树的中序区间**：`[rootIdx+1, iright)`（根右侧的所有元素）。
>
> 你的代码错误地将左 / 右子树的前序结束 / 起始写为`index+1`，完全忽略了`ileft`的偏移，当递归到非根节点的子树时，区间会彻底错位。（即`ileft`非0时这种巧合将不再存在）
>
> ⚡️ 优化思路：
>
> 1. 用`auto it = std::find(inorder.begin()+ileft, inorder.end()+iright, rootval);`查找根节点在中序的下标，可以只在给定的中序数组范围中查找，因为不可能超出这个范围
>
> 2. find的时间复杂度还是太高了（On2），可以用哈希表存储对应的中序数组的下标和值的映射
>
> 3. 就算不优化，老弟你还是忘记了牛逼plus的范围库了
>
>    `int left_size = ranges::find(inorder, preorder[0]) - inorder.begin(); // 左子树的大小`
>
> ```cpp
> // 哈希表优化最佳版本 //只传入inorder的左边界以便求出左子树长度
> class Solution {
> private:
>     unordered_map<int, int> inoMap; // 中序值->下标映射
>     TreeNode* build(vector<int>& pre, int pL, int pR, int iL) {
>         if (pL >= pR) return nullptr;
>         int rootVal = pre[pL];
>         TreeNode* root = new TreeNode(rootVal);
>         int rootIdx = inoMap[rootVal]; // O(1)查找
>         int leftSize = rootIdx - iL;
>         // 左子树：pre[pL+1, pL+1+leftSize)，中序[iL, rootIdx)
>         root->left = build(pre, pL+1, pL+1+leftSize, iL);
>         // 右子树：pre[pL+1+leftSize, pR)，中序[rootIdx+1, iL+(pR-pL))
>         root->right = build(pre, pL+1+leftSize, pR, rootIdx+1);
>         return root;
>     }
> public:
>     TreeNode* buildTree(vector<int>& preorder, vector<int>& inorder) {
>         // 初始化哈希表
>         for (int i = 0; i < inorder.size(); ++i) inoMap[inorder[i]] = i;
>         return build(preorder, 0, preorder.size(), 0);
>     }
> };
> ```





#### 33. [二叉树展开为链表](https://leetcode.cn/problems/flatten-binary-tree-to-linked-list/description/?envType=study-plan-v2&envId=top-100-liked)

> 题目：将二叉树按照<u>先序遍历</u>（中～左～右）的顺序排成链表，每个节点的左孩子置空，右孩子是后继链表节点
>
> 思路：
>
> 1. 最简单，用数组存储先序遍历的所有节点，然后再遍历一遍串起来，注意左孩子置空，空间复杂度On
> 2. 头插法，既然按尾插会破坏当前节点向后遍历，那么从后向前构建链表（头插法），需要按照<u>右～左～中</u>（反过来）的顺序遍历树，每次将当前节点作为头节点插入已存在的链表，为此需要初始化第一个链头是nullptr；注意将左孩子置空
> 3. 分治法：根 -> 左子树的链表 -> 右子树的链表， 递归。 看灵神题解，效率同2
> 4. morris遍历，空间复杂度降到O1 ｜ 找出cur的左节点的最右节点，把cur的右子树接到最右节点的右边，将左子树移动到右子树位置，再把cur的左子树置空，然后cur=cur.right处理下一个节点！！！
>
> ```java

>     public void flatten(TreeNode root) {
>         TreeNode cur=root;
>         while(cur!=null){
>             if(cur.left!=null){
>                 TreeNode predecessor = cur.left;
>                 while(predecessor.right!=null){
>                     predecessor=predecessor.right;
>                 }
>                 predecessor.right=cur.right;
>                 cur.right=cur.left;
>                 cur.left=null;
>             }
>             cur=cur.right;
>         }
>     }
> }
> ```

#### 35.[二叉树的最近公共祖先](https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-tree/description/?envType=study-plan-v2&envId=top-100-liked)

> 一开始的思路是层序遍历二叉树存入数组，通过父节点跟子节点的关系推出公共父节点，但是❗️这个关系只在完全二叉树中体现，非完全二叉树的父子节点关系不是2倍，而且还要考虑到空节点作为子树的情况，所以这个方法是不可行的
>
> 思路：递归，将p和q在归的过程中向上传递，直到相遇即最近的公共父节点

>    - 当前节点是空节点 ｜ p｜ q → 直接返回当前节点
>

>    - 递归查找左子树，得到结果 `left`
>    - 递归查找右子树，得到结果 `right`
>
> 3. **根据子树结果分类**：
>
>    - 左右子树都找到（`left` 和 `right` 都不为空）：返回当前节点 🤫
>    - 只有左子树找到（`left` 不为空）：返回递归左子树的结果 
>    - 只有右子树找到（`right` 不为空）：返回递归右子树的结果
>    - 左右子树都没有找到：返回空节点
>
>    如果左子树非空，不能直接返回左子树，因为可能右子树也非空，这时候当前节点就是父节点



#### 36.[二叉树中的最大路径和](https://leetcode.cn/problems/binary-tree-maximum-path-sum/?envType=study-plan-v2&envId=top-100-liked) ⭐️

> 🥹 关于二叉树的一些概念没有弄清，所以做起来比较吃力😥
>
> 二叉树的路径被定义为一条节点序列，序列中每对相邻节点之间都存在一条边。同一个节点在一条路径序列中 **至多出现一次** 。该路径 **至少包含一个** 节点，且不一定经过根节点。**路径和** 是路径中各节点值的总和。
>
> - **链和（单分支路径和）**：以当前节点为**终点**的「单向路径」的最大和（只能选左子树的一条链 或 右子树的一条链，不能同时选左右，否则路径会分叉）。
>   - 比如节点 `A` 的左孩子是 `B`、右孩子是 `C`，那么 `A` 的链和只能是 `A+B` 或 `A+C`（如果和为负则舍弃，取 0）。
> - **路径和（分叉路径和）**：以当前节点为**顶点**的「分叉路径」的最大和（左子树链和 + 当前节点值 + 右子树链和）。
>   - 比如上面的例子，`B+A+C` 就是以 `A` 为顶点的路径和，这是可能的最大路径和候选。
>
> 思路：枚举所有节点，假设当前节点是最大路径的拐点
>
> 易错：
>
> 1. 对于当前节点，可能的<u>最大路径和</u>就是左右子树最大链和+当前节点值
> 2. 然后递归当前节点的返回值是当前节点的最大链和：可能是当前节点值+左右链和中的较大值，🤫然而这个加和可能是负数，那么就意味着当前节点的最大链和都是负数，对于上一层递归，也就是其子树链和事负数，对父节点的路径和无贡献，因此优化成返回0，表示不选择当前节点形成的链和
>
> ```cpp
> // 关键步骤1：更新全局最大路径和
> // 以当前节点为顶点的分叉路径和 = 左链和 + 右链和 + 当前节点值
> // 这是唯一能形成「分叉路径」的情况，必须和全局最大值比较
> ans = max(ans, l_val + r_val + node->val); 
> 
> // 关键步骤2：返回当前节点的「链和」
> // 逻辑：选左/右链中较大的那个 + 当前节点值；如果结果为负，返回0（舍弃这条链，因为负数链对父节点无贡献）
> return max(max(l_val, r_val) + node->val, 0); 	// 返回当前节点的「链和」（供父节点使用）保证子链和非负☝️
> ```



#### 37.[路径总和Ⅲ](https://leetcode.cn/problems/path-sum-iii/description/?envType=study-plan-v2&envId=top-100-liked)

> 概念同上一题，但是本题要求路径方向必须是向下，也就是没有拐点
>
> 思路：这一类求和的问题，可以转化成求两个**前缀和的差值**的问题，由于是二叉树，可以用一个**哈希表来存储** <u>前缀和->对应前缀和路径长度的数量</u>（二叉树滑动窗口不适用）
>
> 注意：⚠️
>
> 1. `unordered_map<long long, int> cnt = {{0, 1}};**` 哈希表的初始化**，前0节点的路径之和为0，数量为1
> 2. `long long x = sum - targetSum;    // x是被减去的前缀和`
>    * 对于当前前缀和sum，找到其前缀和x，那么sum - x的值就是要求值，即这是达到要求路径和的一种情况
>    * 注意，本题路径和可能超出int范围了，所以用long long类型，这里的x也必须是🐲🐲类型，由于**类型提升**，sum - targetSum的返回值是一个long long 类型，如果用int类型接受，就可能会导致**精度丢失**（这是我第一次做错的原因）😡
> 3. `cnt[s]--; // 恢复现场（撤销 cnt[s]++）`：对于存入哈希表的映射对，在返回本次递归的时候记得撤销**恢复现场**
>    * 二叉树的遍历一般是先左子树再右子树，如果不撤销每次访问的哈希映射，那么当访问右子树时，哈希表里还有左子树的前缀和，但是不可能和右子树的节点组成路径->结果错误～
