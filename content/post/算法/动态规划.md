# 动态规划

## 条件转移方程

* 为什么状态转移方程有时候不一样

| 对比维度            | 当前代码的逻辑（`memo[i]`对应`a[0]~a[i]`） | 你提到的转移方程逻辑（`memo[i]`对应`sum[0]~sum[i-1]`） |
| ------------------- | ------------------------------------------ | ------------------------------------------------------ |
| `memo[i]`定义       | 前`i+1`个元素（`a[0]~a[i]`）的最大收益     | 前`i`个元素（`sum[0]~sum[i-1]`）的最大收益             |
| 转移方程            | `max(dfs(i-1), dfs(i-2)+a[i])`             | `max(dfs(i-1), dfs(i-2)+sum[i-1])`                     |
| 对应`a`/`sum`的元素 | 选`a[i]`时加`a[i]`                         | 选`sum[i-1]`时加`sum[i-1]`                             |

* 值域打家劫舍https://leetcode.cn/problems/maximum-total-damage-with-spell-casting/solutions/2812389/tao-lu-da-jia-jie-she-pythonjavacgo-by-e-p9b5/

  

* 我注意到一个点：

  * 就是记忆化搜索中的memo数组如果和房子的长度一样，memo(n, -1)，memo[i] 的意思就是包括第i间房子在内的 0 ~ i 的 i + 1 间房子的最大值；
  * memo(n + 1, -1) 的话memo[i] 就是0 ～ i-1 的房子的最大值，即前i间房子的最大值



## 难题

1. [3393. 统计异或值为给定值的路径数目](https://leetcode.cn/problems/count-paths-with-the-given-xor-value/)

```cpp
class Solution {
public:
    int countPathsWithXorValue(vector<vector<int>>& grid, int k) {
        const int MOD = 1'000'000'007;
        int m = grid.size(), n = grid[0].size();
        vector<vector<int>> memo(m, vector<int>(n, -1));

        auto dfs = [&](this auto&& dfs, int i, int j, int x) -> int {
            if(i < 0 || j < 0)  return 0;
          	if(i == 0 && j == 0 && x == grid[i][j])    return 1;
          
            int& res = memo[i][j];
            if(res != -1)   return res;

            return res = (dfs(i - 1, j, x ^ grid[i][j]) + dfs(i, j - 1, x ^ grid[i][j])) % MOD;
        };
        return dfs(m - 1, n - 1, k);
    }
};
```

这段代码存在几个逻辑和实现上的问题，主要体现在记忆化存储和递归终止条件上：

1. **记忆化存储问题**：

   当前代码使用`memo[i][j]`存储结果，但忽略了`x`（当前异或值）这个关键参数。相同的`i`和`j`位置，不同的`x`会产生不同结果，所以记忆化应该考虑`x`的值。

   ---> 同一个地点（i,j）的不同异或值（x）对应不同的路径状态，**二维数组无法区分这些状态**，会导致错误。

2. **递归终止条件问题**：

   起始条件判断`i == 0 && j == 0 && x == grid[i][j]`不正确，因为从起点 (0,0) 到自身的异或路径就是它自己的值。

   * 解释：
     * 原代码的逻辑是：
       - 只有当 `i==0 && j==0` **且** `x == grid[0][0]` 时，才返回 1；
       - 若 `i==0 && j==0` **但** `x != grid[0][0]`，则**不会进入该条件**，会继续执行后续代码（比如检查 `memo` 或递归计算）。
     * 而修正后的逻辑是：
       - 只要 `i==0 && j==0`，就直接判断 `grid[0][0]` 与 `x` 的关系：相等返回 1，不相等返回 0；
       - 不会执行后续代码，避免了错误的逻辑延续。

3. **递归方向问题**：

   代码从终点 (m-1,n-1) 往起点 (0,0) 递归，但起始条件判断的是起点状态，逻辑上不一致。

   * 原因同2， 在判断终点`if(i == 0 && j == 0 && x == grid[i][j])    return 1;`这一句，x == grid[i][j]从逻辑上来说是正向推导在终点判断的条件

```cpp
// 好难🤯
class Solution {
public:
    int countPathsWithXorValue(vector<vector<int>>& grid, int k) {
        const int MOD = 1'000'000'007;

        int mx = 0;
        for(auto& row : grid){
            mx = max(mx, std::ranges::max(row));    // 计算网格中的最大值
        }
        int u = 1 << bit_width((unsigned)mx);// 计算mx所需的位数，再左移1位得到范围
        if (k >= u) {
            return 0;   // 提前排除 “异或结果不可能等于 k” 的情况 ---》 位运算
        }

        int m = grid.size(), n = grid[0].size();
        vector<vector<vector<int>>> memo(m, vector<vector<int>>(n, vector<int>(u, -1))); // 三维数组

        auto dfs = [&](this auto&& dfs, int i, int j, int x) -> int {
            if(i < 0 || j < 0)  return 0;
            if(i == 0 && j == 0){
                return x == grid[i][j];  // 这里x的值的判断不能放到if里，if判断的是递归终止的条件
            }

            int& res = memo[i][j][x];
            if(res != -1)   return res;

            return res = (dfs(i - 1, j, x ^ grid[i][j]) + dfs(i, j - 1, x ^ grid[i][j])) % MOD;
        };
        return dfs(m - 1, n - 1, k);
    }
};
```
