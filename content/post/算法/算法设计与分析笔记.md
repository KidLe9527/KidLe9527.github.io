

## 查找算法辨析

查找算法是在一组数据中**寻找指定目标元素**的算法，核心评价指标包括**查找效率（时间复杂度）、数据预处理要求、稳定性（对重复元素的处理）、适用数据结构**等。

我们先明确查找算法的核心分类，再从关键维度进行全面辨析，覆盖算法设计与分析的常考点。

### 一、核心概念界定

查找算法根据**数据是否有序**、**是否依赖额外数据结构**，可分为两大类别：

1. **无序表查找**：数据无序，无需预处理，直接遍历或匹配
2. **有序表查找**：数据必须有序，可利用有序性优化查找效率
3. **树结构查找**：基于树（二叉搜索树、平衡树等）的查找，属于动态查找
4. **哈希查找**：基于哈希表的查找，通过哈希函数映射位置，属于高效查找

### 二、关键评价指标（常考点）

| 指标             | 含义                                                   |
| ---------------- | ------------------------------------------------------ |
| **时间复杂度**   | 成功查找、失败查找的平均 / 最坏时间复杂度              |
| **预处理要求**   | 是否需要排序、是否需要构建额外数据结构（如哈希表、树） |
| **空间复杂度**   | 算法执行所需的额外存储空间                             |
| **适用数据结构** | 数组、链表、树、哈希表等                               |
| **稳定性**       | 对重复元素的查找是否能返回指定位置（如第一个匹配元素） |
| **动态性**       | 是否支持高效的插入、删除操作（动态查找 vs 静态查找）   |

### 三、主流查找算法全面辨析

| 查找算法                     | 基本思想                                                     | 预处理要求                                        | 时间复杂度（平均 / 最坏）                     | 空间复杂度                            | 适用场景                                   | 稳定性                            | 动态性                   |
| ---------------------------- | ------------------------------------------------------------ | ------------------------------------------------- | --------------------------------------------- | ------------------------------------- | ------------------------------------------ | --------------------------------- | ------------------------ |
| **顺序查找（线性查找）**     | 从数据一端开始，逐个比较元素，直到找到目标或遍历结束         | 无（数据可无序）                                  | 成功：\(O(n)\)失败：\(O(n)\)                  | \(O(1)\)                              | 小规模数据、无序数据、链表结构             | 稳定（可返回第一个匹配元素）      | 高（插入删除无需预处理） |
| **折半查找（二分查找）**     | 数据有序，取中间元素与目标比较，缩小查找范围，递归 / 迭代执行 | 数据必须**有序**（数组）                          | 成功：\(O(logn)\)失败：\(O(logn)\)            | \(O(1)\)（迭代）\(O(logn)\)（递归栈） | 大规模有序数组、静态数据（插入删除成本高） | 稳定（可控制返回左 / 右匹配元素） | 低（插入删除需重新排序） |
| **插值查找**                 | 折半查找的优化，根据目标值与边界值的比例计算查找位置，更接近目标 | 数据必须**有序且均匀分布**                        | 成功：\(O(loglogn)\)最坏：\(O(n)\)            | \(O(1)\)（迭代）                      | 大规模均匀有序数组（如学号、分数）         | 稳定                              | 低                       |
| **斐波那契查找**             | 基于斐波那契数列划分查找区间，用加法替代折半的除法，减少计算量 | 数据必须**有序**                                  | 成功：\(O(logn)\)失败：\(O(logn)\)            | \(O(1)\)                              | 硬件除法效率低的场景（如嵌入式）           | 稳定                              | 低                       |
| **二叉搜索树（BST）查找**    | 左子树元素 < 根节点 < 右子树，递归查找目标元素               | 构建二叉搜索树                                    | 平均：\(O(logn)\)最坏：\(O(n)\)（退化为链表） | \(O(n)\)（树结构存储）                | 动态数据（频繁插入删除）                   | 不稳定（重复元素位置不固定）      | 高                       |
| **平衡二叉树（AVL 树）查找** | 二叉搜索树的改进，保证左右子树高度差≤1，避免退化             | 构建 AVL 树（自动平衡）                           | 平均 / 最坏：\(O(logn)\)                      | \(O(n)\)                              | 动态数据、对查找效率要求严格               | 不稳定                            | 高                       |
| **红黑树查找**               | 近似平衡二叉树，通过颜色约束保证树的高度，平衡效率高于 AVL 树 | 构建红黑树                                        | 平均 / 最坏：\(O(logn)\)                      | \(O(n)\)                              | 大规模动态数据（如 C++ map、Java TreeMap） | 不稳定                            | 高                       |
| **哈希查找**                 | 通过哈希函数计算目标元素的存储位置，直接访问查找             | 构建哈希表，处理哈希冲突（链地址法 / 开放定址法） | 平均：\(O(1)\)最坏：\(O(n)\)（冲突严重）      | \(O(n)\)（哈希表存储）                | 大规模数据、对查找速度要求极高             | 不稳定（冲突处理影响位置）        | 高                       |

### 四、高频易混点总结

1. **折半查找的核心限制**
   - 必须基于**随机访问结构**（如数组），**链表无法实现**（链表不能直接取中间元素）。
   - 数据必须有序，静态数据更适用；若频繁插入删除，维护有序的成本高于查找收益。
2. **插值查找 vs 折半查找**
   - 折半查找的中间位置是固定的 `mid = (low+high)/2`，适合**任意有序数据**。
   - 插值查找的中间位置是 `mid = low + (target - arr[low])*(high-low)/(arr[high]-arr[low])`，适合**均匀分布的有序数据**（如等差数列），极端情况下（数据分布不均）效率退化为 \(O(n)\)。
3. **树结构查找的效率差异**
   - 普通二叉搜索树最坏情况退化为链表，时间复杂度 \(O(n)\)；AVL 树和红黑树通过平衡机制保证 \(O(logn)\) 效率。
   - AVL 树的平衡要求更严格（高度差≤1），插入删除的旋转次数更多；红黑树平衡要求宽松，插入删除效率更高，实际应用更广泛。
4. **哈希查找的核心是冲突处理**
   - 哈希查找的平均效率 \(O(1)\) 是理想情况，**哈希冲突**是影响效率的关键。
   - 链地址法：冲突元素存储在链表中，适合频繁插入删除；开放定址法（线性探测、二次探测）：冲突元素寻找下一个空位置，适合小规模数据。
5. **静态查找 vs 动态查找**
   - 静态查找：数据不常变化，优先选**折半查找**（空间复杂度低）。
   - 动态查找：数据频繁增删，优先选**红黑树**或**哈希查找**（增删查效率均衡）。

### 五、查找算法的选择策略

1. 数据无序 + 小规模 → **顺序查找**
2. 数据有序 + 静态 + 数组 → **折半查找**
3. 数据有序 + 均匀分布 → **插值查找**
4. 频繁增删 + 大规模 → **红黑树 / 哈希查找**
5. 嵌入式 / 低算力场景 → **斐波那契查找**

## 排序算法辨析

### 一、核心概念界定

1. **排序算法**

   

   是将一组无序的数据元素，按照指定的顺序（升序或降序）重新排列的算法。根据核心操作的不同，可分为：

   - 插入类：直接插入排序、折半插入排序、希尔排序
   - 交换类：冒泡排序、快速排序
   - 选择类：简单选择排序、堆排序
   - 归并类：二路归并排序
   - 基数类：基数排序

2. **插入算法（插入排序）**

   

   属于排序算法的一个子类，核心思想是

   将待排序元素逐个插入到已排序序列中的合适位置，最终形成有序序列。

### 二、关键评价指标（常考点）

在辨析排序算法前，先明确几个核心评价维度：

| 指标           | 含义                                                         |
| -------------- | ------------------------------------------------------------ |
| **稳定性**     | 若待排序序列中，两个相等元素的相对位置在排序后保持不变，则为**稳定排序**；否则为**不稳定排序**。 |
| **时间复杂度** | 最好情况：有序或接近有序序列的排序效率最坏情况：逆序序列的排序效率平均情况：随机序列的排序效率 |
| **空间复杂度** | 算法执行过程中需要的额外存储空间，分为**原地排序**（\(O(1)\)）和**非原地排序**（如 \(O(n)\)、\(O(logn)\)） |
| **适用场景**   | 适合小规模数据、大规模数据、有序 / 逆序数据等不同场景        |

### 三、主流排序算法全面辨析

| 排序算法         | 基本思想                                                     | 稳定性 | 时间复杂度（最好 / 最坏 / 平均）             | 空间复杂度            | 适用场景                                   |
| ---------------- | ------------------------------------------------------------ | ------ | -------------------------------------------- | --------------------- | ------------------------------------------ |
| **直接插入排序** | 逐个将待排序元素插入到已排序序列的合适位置                   | 稳定   | \(O(n)\) / \(O(n^2)\) / \(O(n^2)\)           | \(O(1)\)              | 小规模数据、基本有序的数据                 |
| **折半插入排序** | 用折半查找确定插入位置，减少比较次数                         | 稳定   | \(O(n)\) / \(O(n^2)\) / \(O(n^2)\)           | \(O(1)\)              | 小规模数据、对比较次数敏感的场景           |
| **希尔排序**     | 分组进行直接插入排序，逐步缩小增量，最终增量为 1             | 不稳定 | \(O(n^{1.3})\) / \(O(n^2)\) / \(O(n^{1.3})\) | \(O(1)\)              | 中等规模数据，比直接插入排序效率高         |
| **冒泡排序**     | 相邻元素两两比较，逆序则交换，每轮将最大元素 “冒泡” 到末尾   | 稳定   | \(O(n)\) / \(O(n^2)\) / \(O(n^2)\)           | \(O(1)\)              | 小规模数据、基本有序的数据                 |
| **快速排序**     | 选基准元素，将序列划分为 “小于基准” 和 “大于基准” 两部分，递归排序子序列 | 不稳定 | \(O(nlogn)\) / \(O(n^2)\) / \(O(nlogn)\)     | \(O(logn)\)（递归栈） | 大规模随机数据，实际应用中最快的排序之一   |
| **简单选择排序** | 每轮选择未排序序列中的最小元素，与未排序序列的首元素交换     | 不稳定 | \(O(n^2)\) / \(O(n^2)\) / \(O(n^2)\)         | \(O(1)\)              | 小规模数据，交换次数少                     |
| **堆排序**       | 构建大顶堆，每次取出堆顶元素（最大），调整堆结构，重复操作   | 不稳定 | \(O(nlogn)\) / \(O(nlogn)\) / \(O(nlogn)\)   | \(O(1)\)              | 大规模数据，对空间要求严格的场景           |
| **二路归并排序** | 分治法，将序列分成两个子序列，分别排序后合并为有序序列       | 稳定   | \(O(nlogn)\) / \(O(nlogn)\) / \(O(nlogn)\)   | \(O(n)\)辅助数组      | 大规模数据，需要稳定排序的场景             |
| **基数排序**     | 按低位到高位（或高位到低位）依次对元素进行分配和收集         | 稳定   | \(O(d(n+r))\)（d 为位数，r 为基数）          | \(O(n+r)\)            | 整数、字符串等可按位划分的数据，大规模数据 |

### 四、高频易混点总结

1. **稳定性的核心判断**

   - 稳定排序：直接插入、折半插入、冒泡、归并、基数排序
   - 不稳定排序：希尔、快速、简单选择、堆排序
   - 关键原因：不稳定排序的核心操作会破坏相等元素的相对位置，例如：
     - 简单选择排序：交换操作可能跨位置交换相等元素；
     - 快速排序：基准元素的划分可能打乱相等元素的顺序。

2. **时间复杂度的特殊情况**

   - 直接插入、冒泡排序的**最好时间复杂度为 \(O(n)\)**，当序列基本有序时效率极高；
   - 快速排序的**最坏时间复杂度为 \(O(n^2)\)**，当序列有序或逆序时，基准选择不当会导致划分失衡；
   - 堆排序、归并排序的时间复杂度**无最好最坏之分**，始终为 \(O(nlogn)\)。

3. **空间复杂度的区分**

   - 原地排序（\(O(1)\)）：直接插入、希尔、冒泡、简单选择、堆排序；
   - 非原地排序：归并排序（\(O(n)\)）(辅助数组）、基数排序（\(O(n+r)\)）。桶排序（基数排序变种）

   > 特例：快速排序（递归栈 \(O(logn)\)）虽然空间复杂度非O1，但是这是**递归调用栈空间**，辅助的空间复杂度就是O1，几个变量，所以快排算是原地排序

### 五、插入排序与其他排序的核心差异

1. **插入排序 vs 选择排序**
   - 相同点：时间复杂度平均为 \(O(n^2)\)，空间复杂度 \(O(1)\)，适合小规模数据；
   - 不同点：插入排序稳定，选择排序不稳定；插入排序比较次数与数据有序度相关，选择排序比较次数固定。
2. **插入排序 vs 快速排序**
   - 相同点：都基于 “逐步构建有序序列” 的思想；
   - 不同点：插入排序是**增量式构建**，快速排序是**分治式构建**；快速排序平均效率远高于插入排序，适合大规模数据。
3. **插入排序 vs 归并排序**
   - 相同点：都属于稳定排序；
   - 不同点：归并排序时间复杂度更优（\(O(nlogn)\)），但需要额外 \(O(n)\) 空间；插入排序原地排序，适合小规模数据。

#include <iostream>
#include <vector>
#include <algorithm> // 用于 std::min

using namespace std;

int editDistance(const string& s1, const string& s2) {
    int m = s1.size(), n = s2.size();
    // 创建 (m+1) x (n+1) 的二维 DP 数组，初始化为 0
    vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));
    
    // 初始化边界条件
    for (int i = 0; i <= m; ++i) {
        dp[i][0] = i; // s1 前 i 个字符转为空串，需删除 i 次
    }
    for (int j = 0; j <= n; ++j) {
        dp[0][j] = j; // 空串转 s2 前 j 个字符，需插入 j 次
    }
    
    // 动态填充 DP 数组
    for (int i = 1; i <= m; ++i) {
        for (int j = 1; j <= n; ++j) {
            if (s1[i-1] == s2[j-1]) {
                // 字符相同，无需操作，继承左上角的值
                dp[i][j] = dp[i-1][j-1];
            } else {
                // 字符不同，取插入、删除、替换的最小值 + 1
                dp[i][j] = min({dp[i-1][j], dp[i][j-1], dp[i-1][j-1]}) + 1;
            }
        }
    }
    
    return dp[m][n]; // 返回最终结果
}

int main() {
    string s1 = "kitten", s2 = "sitting";
    cout << "Minimum edit distance: " << editDistance(s1, s2) << endl;
    return 0;
}
