# Thread 类成员变量与成员函数作用总结

## 一、成员变量

| 变量名        | 类型 / 相关常量                                              | 作用                                                         | 初始化 / 赋值时机                                            |
| ------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `started_`    | `bool`（布尔类型）                                           | **标记 Thread 对象对应的线程是否已启动**：`false`为未启动，`true`为已启动 | 构造函数中初始化为`false`；`start()`函数中置为`true`（标记线程启动） |
| `joined_`     | `bool`（布尔类型）                                           | **标记 Thread 对象对应的线程是否已调用`join()`**：`false`为未 join，`true`为已 join | 构造函数中初始化为`false`；`join()`函数中置为`true`（标记线程已等待回收） |
| `tid_`        | 隐含为整型（结合`CurrentThread::tid()`，存储线程真实 tid 值） | 存储当前 Thread 对象对应线程的真实**线程 ID**（区别于 std::thread 的 id） | `start()`函数中，新线程执行体中通过`CurrentThread::tid()`获取并赋值（需通过信号量同步，确保主线程获取到 tid 后再返回） |
| `func_`       | `ThreadFunc`（可调用对象类型，如函数指针 / 仿函数 /lambda）  | **存储线程要执行的核心任务函数**，是线程的执行逻辑载体       | 构造函数中通过`std::move(func)`移动赋值（减少拷贝开销）；新线程启动后执行`func_()` |
| `name_`       | `std::string`（字符串类型）                                  | **标识线程的名称**，方便调试与日志排查                       | 构造函数中调用`setDefaultName()`初始化：若传入`name`为空则自动生成格式为`Thread{num}`的名称；若传入非空则使用传入值 |
| `numCreated_` | `std::atomic_int`（原子整型，类静态成员）                    | **全局计数**已创建的 Thread 对象数量，用于生成默认线程名     | 程序启动时默认初始化为 0；`setDefaultName()`函数中通过`++numCreated_`原子自增（保证多线程安全） |
| `thread_`     | `std::shared_ptr<std::thread>`（智能指针，管理 std::thread 对象） | 托管底层 std::thread 对象，利用智能指针自动管理线程对象生命周期 | `start()`函数中创建`std::thread`实例并赋值，析构函数中若线程已启动且未 join，通过`detach()`让线程后台运行并自动回收 |

## 二、成员函数

按功能分类，并明确调用条件、时机与核心逻辑：

### （一）构造 / 析构函数：生命周期管理

| 函数名                                             | 调用时机                                   | 核心作用                                                     | 注意事项                                                     |
| -------------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `Thread(ThreadFunc func, const std::string &name)` | 创建 Thread 对象时（传入线程 函数与名称）  | 1. 初始化状态变量`started_=false`、`joined_=false`、`tid_=0`；2. 移动赋值线程执行函数`func_`；3. 初始化线程名`name_`；4. 调用`setDefaultName()`生成默认名称（若传入 name 为空） | 使用`std::move`处理`func`，避免拷贝大体积可调用对象；静态变量`numCreated_`原子自增保证多线程安全 |
| `~Thread()`                                        | Thread 对象销毁时（超出作用域 / 手动析构） | 1. 检查线程状态：若已启动（`started_=true`）且未 join（`joined_=false`）；2. 调用`thread_->detach()`将线程设为分离态，让线程运行结束后自动销毁（非阻塞，避免主线程阻塞） | 仅对 “已启动且未 join” 的线程执行 detach；分离态线程无法再调用 join () |

> * `thread_`的类型是`std::shared_ptr<std::thread>`，**智能指针的默认构造函数会自动将其初始化为空（指向`nullptr`）**，因此无需在构造函数初始化列表中显式初始化 —— 这是 C++ 智能指针的特性（`std::shared_ptr`默认构造时管理的指针为`nullptr`，引用计数为 0）。
> * `Thread`类的设计逻辑是：**构造函数仅完成线程 “元信息”（回调函数、名称、状态标记）的初始化，而非实际创建操作系统线程**。线程的实际创建（即`std::thread`对象的实例化）被延迟到`start()`方法中，这是典型的 “延迟初始化” 设计，原因如下：
>   - 符合 <u>“按需创建”</u> 原则：构造`Thread`对象不代表立刻启动线程，用户可在构造后、`start()`前修改线程配置（若扩展该类）；
>   - 避免构造函数中创建线程带来的异常风险：`std::thread`构造时会立刻启动线程，若构造函数中抛出异常，可能导致线程资源泄漏；
>   - 解决`tid_`的竞争问题：线程 ID（`tid_`）需要在线程运行时获取，若构造函数中创建线程，`tid_`的赋值可能存在竞争条件（主线程与新线程的执行顺序不确定）。

### （二）核心线程操作：start/join

#### 1. start（启动线程）

| 调用时机                                                    | 调用条件                                              | 核心作用                                                     | 分支逻辑                                                     |
| ----------------------------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 外部调用 Thread 对象的`start()`方法时（需启动线程执行任务） | 线程未启动（`started_`初始为`false`），且仅能调用一次 | 1. 标记`started_=true`，标记线程启动；2. 初始化信号量`sem`（非进程间共享）；3. 创建`std::thread`对象，线程执行体逻辑：   - 获取线程真实 tid 并赋值给`tid_`；   - 发送信号量`sem_post`（通知主线程 tid 已获取）；   - 执行线程任务`func_()`；4. 主线程调用`sem_wait`等待 tid 赋值完成（同步保证）；5. 用智能指针`thread_`托管 std::thread 对象 | 无分支逻辑，核心是 “信号量同步获取 tid”+“启动线程执行 func_”；信号量保证主线程拿到 tid 后再返回，避免 tid 未赋值就被访问 |

> 这个函数的核心作用是**启动一个新线程**，并通过信号量同步确保主线程（调用`start()`的线程）能获取到新线程的`tid`（线程 ID）后，再继续执行。详细解释见后面
>
> **在新线程里，把新线程自己的 tid，赋值给外面这个 Thread 对象的 tid_ 成员。**

#### 2. join（等待线程结束）

| 调用时机                                                   | 调用条件                                                  | 核心作用                                                     | 分支逻辑                                                     |
| ---------------------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 外部调用 Thread 对象的`join()`方法时（需阻塞等待线程结束） | 线程已启动（`started_=true`）且未 join（`joined_=false`） | 1. 标记`joined_=true`（标记已执行 join）；2. 调用`thread_->join()`阻塞主线程，直到该线程执行完毕并回收资源 | 无分支逻辑，仅封装 std::thread 的 join 操作；调用后线程变为 join 态，析构函数不再执行 detach |

### （三）辅助函数：setDefaultName

| 调用时机                              | 调用条件                                    | 核心作用                                                     | 细节                                                         |
| ------------------------------------- | ------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 构造函数中，初始化线程名`name_`时调用 | 若传入的`name`为空字符串（`name_.empty()`） | 1. 原子自增静态变量`numCreated_`（计数已创建的 Thread 数量）；2. 格式化生成默认线程名：`Thread{num}`（num 为自增后的值）；3. 将生成的名称赋值给`name_` | 仅当线程名为空时生成默认名；若构造时传入非空 name，直接使用传入值，不执行默认名生成逻辑 |

## 三、核心调用链路与时机总结

1. **初始化阶段**：创建 Thread 对象 → 构造函数初始化状态变量、移动赋值`func_`、调用`setDefaultName()`生成线程名 → 完成 Thread 对象初始化；

2. **线程启动阶段**：调用`start()` → 标记`started_=true` → 初始化信号量 → 创建 std::thread 并执行`func_` → 信号量同步获取`tid_` → 线程开始执行任务；✅

3. **线程回收阶段**：

   - 主动回收：调用`join()` → 标记`joined_=true` → 阻塞等待线程结束并回收资源；
   - 自动回收：未调用`join()`，析构函数触发 → 检查`started_=true`且`joined_=false` → 调用`detach()`让线程后台运行，结束后自动销毁；

   

4. **命名逻辑**：构造时传入名称则直接使用 → 未传入则`setDefaultName()`生成`Thread{num}`格式名称（num 为原子自增计数）。

## 四、设计亮点与容错逻辑

1. **线程安全计数**：使用`std::atomic_int`类型的静态变量`numCreated_`，保证多线程环境下线程名生成的计数安全；
2. **tid 同步机制**：通过信号量`sem`同步主线程与新线程，确保主线程调用`start()`返回时已获取到新线程的真实 tid，避免空值访问；
3. **资源管理**：利用`std::shared_ptr`托管`std::thread`对象，避免手动管理内存导致的泄漏；析构时对未 join 的线程执行`detach()`，保证线程资源正常回收；
4. **状态标记**：通过`started_`/`joined_`标记线程状态，避免重复启动、重复 join 等非法操作；
5. **移动语义优化**：构造函数中对`func_`使用`std::move`，减少可调用对象的拷贝开销，提升性能。

## 补充：start函数详细解释

> ### `Thread::start()` 函数完整解析
>
> 这个函数的核心作用是**启动一个新线程**，并通过信号量同步确保主线程（调用`start()`的线程）能获取到新线程的`tid`（线程 ID）后，再继续执行。以下是逐行拆解说明：
>
> #### 1. 标记线程已启动
>
> ```cpp
> started_ = true;
> ```
>
> `started_`是`Thread`类的成员变量（布尔类型），用于标记当前`Thread`对象对应的线程是否已经启动，避免重复启动。
>
> #### 2. 信号量初始化
>
> ```cpp
> sem_t sem;  // 定义一个信号量，用于线程同步，确保线程创建后获取到tid值
> sem_init(&sem, false, 0);  // false指的是 不设置进程间共享
> ```
>
> - `sem_t`：系统提供的信号量类型，用于多线程 / 多进程同步；
> - `sem_init`：初始化信号量的函数，参数说明：
>   - 第一个参数`&sem`：要初始化的信号量对象；
>   - 第二个参数`false`：表示信号量**仅在当前进程的线程间共享**（若为`true`则支持进程间共享）；
>   - 第三个参数`0`：信号量的初始值为 0（初始无可用资源，调用`sem_wait`会阻塞）。
>
> #### 3. 创建并启动新线程
>
> ```cpp
> thread_ = std::shared_ptr<std::thread>(new std::thread([&]() {
>     tid_ = CurrentThread::tid();  // 获取线程的tid值
>     sem_post(&sem);
>     func_();  // 开启一个新线程 专门执行该线程函数
> }));
> ```
>
> - `std::thread`：C++11 提供的线程类，<u>构造时传入的 lambda 表达式</u>是新线程要执行的逻辑；
> - `std::shared_ptr<std::thread>`：用智能指针管理`std::thread`对象，避免内存泄漏；
> - lambda 表达式（新线程的执行逻辑）：
>   - `[&]()`：捕获外部作用域的变量（按引用），确保能访问`tid_`、`sem`、`func_`等成员 / 局部变量；
>   - `tid_ = CurrentThread::tid();`：`CurrentThread::tid()`是工具函数，用于获取**当前执行线程**（即新创建的线程）的真实 tid，并存入`Thread`对象的`tid_`成员变量；
>   - `sem_post(&sem);`：信号量值 + 1（释放资源），唤醒主线程中阻塞的`sem_wait`；
>   - `func_();`：执行线程的核心业务逻辑（`func_`是`Thread`类的成员变量，类型为`ThreadFunc`，即线程要执行的函数对象）。
>
> #### 4. 主线程等待新线程的 tid 初始化完成
>
> ```cpp
> // 这里必须等待获取上面新创建的线程的tid值
> sem_wait(&sem);
> sem_destroy(&sem); // 销毁信号量，释放资源
> ```
>
> - `sem_wait(&sem)`：尝试获取信号量资源 —— 若信号量值为 0，则**阻塞当前线程（主线程）**，直到信号量值被`sem_post`增加；
> - 这一步是核心同步逻辑：确保主线程必须等新线程执行完`tid_ = CurrentThread::tid()`（即`tid_`已正确赋值）后，才能继续执行，避免主线程提前操作`tid_`导致值未初始化。
>
> ### 核心设计思路 & 解决的问题
>
> 为什么需要信号量同步？
>
> - 新线程的创建和执行是异步的：主线程调用`std::thread`构造函数后，新线程会被系统调度执行，但主线程不会等待新线程的`tid_`赋值完成；
> - 如果没有信号量，主线程可能在新线程还没执行`tid_ = CurrentThread::tid()`时，就继续执行后续逻辑，此时`tid_`还是初始值（0），导致获取的线程 ID 错误；
> - 信号量`sem`初始值为 0，主线程`sem_wait`阻塞，直到新线程执行`sem_post`（信号量 + 1），主线程才会被唤醒，此时`tid_`已确保赋值完成。
>
> ### 补充注意事项
>
> 1. 信号量的生命周期：`sem`是主线程`start()`函数的局部变量，新线程的 lambda 通过引用捕获`sem`，但由于`sem_wait`确保主线程会等待新线程执行`sem_post`后才继续，因此`sem`不会提前销毁（避免野引用）；
> 2. 线程资源管理：`thread_`是`std::shared_ptr<std::thread>`类型，确保线程对象的生命周期与`Thread`对象绑定，避免悬空指针；
> 3. 异常安全：若`func_()`执行抛出异常，新线程会终止，但信号量已通过`sem_post`释放，主线程不会永久阻塞。
>
> ### 总结
>
> **`Thread::start()`的核心逻辑是：**
>
> **创建新线程 → 新线程初始化自身 tid → 通过信号量通知主线程 tid 已就绪 → 主线程唤醒后继续执行 → 新线程执行业务逻辑**。
>
> 通过信号量同步，解决了 “主线程获取新线程 tid 时可能存在的竞态条件” 问题，保证了线程 ID 的正确获取。
>
> 先调用Thread的构造函数构造一个Thread类对象，初始化除了`thread_`的其他所有成员变量，tid_ = 0，然后对这个对象调用start函数，创建新线程赋值给对象的`thread_`，然后执行lambda即新线程的逻辑部分。用信号量保证创建的新线程在主线程调用之前已经对`tid_`进行了赋值，防止主线程阻塞～～
