# Buffer 类 成员变量 & 成员函数 作用总结

### 一、成员变量

#### 1. 缓冲区尺寸常量（静态常量）

| 变量名          | 作用                                                         | 调用 / 生效时机                                              |
| --------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `kCheapPrepend` | 缓冲区头部固定预留的 “前置空间” 大小（8 字节），用于在不移动数据的前提下，快速插入协议头 / 长度字段等前置数据 | 构造函数初始化缓冲区大小时，作为前置空间基准；`makeSpace()`扩容 / 整理空间时，作为数据搬迁的目标起始位置 |
| `kInitialSize`  | 缓冲区初始可写空间的默认大小（1024 字节），决定了无参构造时缓冲区的基础容量 | 无参构造`Buffer`时，作为初始可写空间大小；构造函数中`buffer_`总初始容量 = `kCheapPrepend + kInitialSize` |

#### 2. 缓冲区核心状态与存储相关

| 变量名         | 作用                                                         | 调用 / 生效时机                                              |
| -------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `buffer_`      | 底层存储载体（`std::vector<char>`），封装了连续的内存空间，支持动态扩容，兼具 “前置空间 + 可读数据 + 可写空间” 三段式结构 | 构造函数初始化容量；`makeSpace()`中`resize()`扩容或`std::copy()`整理数据；`append()`/`readFd()`/`writeFd()`中读写数据；全生命周期承载缓冲区数据 |
| `readerIndex_` | 可读数据的起始下标（指向缓冲区中第一个未读取的字节），初始值为`kCheapPrepend` | 构造函数初始化；`retrieve()`/`retrieveAll()`中向后移动（消费数据）；`makeSpace()`中向前搬迁数据时重置；`peek()`/`readFd()`/`writeFd()`中作为可读数据起始位置 |
| `writerIndex_` | 可写数据的起始下标（指向缓冲区中第一个可写入的字节），初始值为`kCheapPrepend` | 构造函数初始化；`append()`/`readFd()`中向后移动（写入数据）；`makeSpace()`中搬迁数据时重置；`ensureWritableBytes()`/`beginWrite()`中作为可写数据起始位置 |

### 二、成员函数

#### 1. 构造 / 析构函数

| 函数名                                     | 作用                                                         | 调用时机                                                     |
| ------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `Buffer(size_t initalSize = kInitialSize)` | 初始化 Buffer 核心资源：1. 初始化`buffer_`容量为`kCheapPrepend + initalSize`，预留前置空间；2. 重置`readerIndex_`和`writerIndex_`为`kCheapPrepend`（初始无数据） | 创建 Buffer 实例时调用（如 TcpConnection 初始化读写缓冲区、网络库接收数据时） |
| `~Buffer()`                                | 释放 Buffer 资源：依赖`std::vector<char>`的析构自动释放内存，无额外自定义逻辑 | Buffer 实例生命周期结束时调用（如 TcpConnection 析构时释放读写缓冲区） |

> #### 构造函数核心设计：
>
> - 三段式缓冲区结构：`[kCheapPrepend 前置空间] + [readerIndex_ ~ writerIndex_ 可读数据] + [writerIndex_ ~ buffer_.size() 可写空间]`；
> - 初始状态下`readerIndex_ == writerIndex_`，表示无可读数据，可写空间为`kInitialSize`。
>
> #### 析构函数默认原因：
>
> * `Buffer` 中的 `std::vector<char> buffer_` 会在 `Buffer` 对象析构时，由 `vector` 析构函数自动释放底层内存，无需手动管理；
> * 代码中 `static const size_t` 属于整数类型静态常量，类内直接初始化是合法的（C++11+）；非整数类型静态常量则必须类外初始化（一般在.cpp 文件中）。

#### 2. 缓冲区状态查询（只读）

| 函数名                     | 作用                                                         | 调用时机                                                     | 内部逻辑 / 触发后续操作                                      |
| -------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `readableBytes() const`    | 返回当前缓冲区中**可读数据的长度**                           | 读取数据前校验是否有数据（如`retrieveAsString()`、`writeFd()`发送数据前）；扩容 / 整理空间时计算数据量 | 直接返回`writerIndex_ - readerIndex_`，无其他逻辑            |
| `writableBytes() const`    | 返回当前缓冲区中**可写数据的剩余长度**                       | 写入数据前校验空间是否足够（如`append()`、`readFd()`读取数据前）；`ensureWritableBytes()`中判断是否需要扩容 | 直接返回`buffer_.size() - writerIndex_`，无其他逻辑          |
| `prependableBytes() const` | 返回当前缓冲区中**前置可用空间的总长度**（含已读数据腾出的空间） | `makeSpace()`中判断是否需要扩容时调用；仅内部 / 调试场景使用 | 直接返回`readerIndex_`，无其他逻辑（前置空间 = 从缓冲区起始到`readerIndex_`的长度） |
| `peek() const`             | 返回缓冲区中**可读数据的起始地址**（const 版本，保证只读）   | 读取数据时获取数据起始指针（如`retrieveAsString()`、`writeFd()`发送数据）；外部解析协议时直接访问缓冲区数据 | 直接返回`begin() + readerIndex_`，无其他逻辑（` const char *`表示数组元素的地址） |

#### 3. 数据消费（重置可读区间）

| 函数名                         | 作用                                                         | 调用时机                                                     | 内部逻辑 / 触发后续操作                                      |
| ------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `retrieve(size_t len)`         | 消费指定长度的可读数据（移动`readerIndex_`，不实际删除数据） | 读取部分数据后调用（如解析协议时读取固定长度头后）；`retrieveAsString()`内部调用 | 1. 若`len < 可读数据长度`：仅`readerIndex_ += len`（剩余数据仍可读）；2. 若`len >= 可读数据长度`：调用`retrieveAll()`重置所有索引 |
| `retrieveAll()`                | 消费所有可读数据（重置`readerIndex_`和`writerIndex_`到初始状态） | 读取全部数据后调用（如`retrieveAllAsString()`、连接关闭前清空缓冲区）；`retrieve(len)`中消费全部数据时调用 | 直接将`readerIndex_`和`writerIndex_`重置为`kCheapPrepend`，无数据拷贝 / 删除，仅修改索引 |
| `retrieveAllAsString()`        | 消费所有可读数据并转换为`std::string`返回                    | 读取完整数据时调用（如`onMessage`回调中读取全部缓冲区数据）  | 调用`retrieveAsString(readableBytes())`，间接消费全部数据并返回字符串 |
| `retrieveAsString(size_t len)` | 消费指定长度的可读数据并转换为`std::string`返回              | 读取指定长度数据时调用（如解析固定长度协议字段）             | 1. 基于`peek()`和`len`构造`std::string`；2. 调用`retrieve(len)`消费数据；3. 返回构造的字符串 |

> #### 核心设计：“浅消费” 而非 “深删除”
>
> - `retrieve`系列函数仅修改`readerIndex_`/`writerIndex_`，不实际删除 / 覆盖`buffer_`中的数据，避免频繁内存操作；
> - 数据真正被覆盖 / 释放，是后续`append()`写入新数据或`makeSpace()`搬迁数据时。

#### 4. 数据写入（确保空间 + 拷贝数据）

| 函数名                                   | 作用                                                         | 调用时机                                                     | 内部逻辑 / 触发后续操作                                      |
| ---------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `ensureWritableBytes(size_t len)`        | 确保缓冲区有至少`len`字节的可写空间，不足则触发扩容 / 整理   | 写入数据前必调（如`append()`、`readFd()`读取数据到缓冲区前） | 若`writableBytes() < len`，调用`makeSpace(len)`；否则无操作  |
| `append(const char *data, size_t len)` 🔥 | 将`[data, data+len]`的内存数据写入缓冲区可写区间             | 上层写入数据到缓冲区时调用（如发送数据前封装协议、接收数据后追加到缓冲区） | 1. 调用`ensureWritableBytes(len)`确保空间；2. 调用`std::copy`将数据拷贝到`beginWrite()`指向的地址；3. `writerIndex_ += len`（移动可写指针） |
| `char* beginWrite()`                     | 返回缓冲区<u>可写区间的起始地址</u>（非 const 版本，支持写入） | `append()`中拷贝数据时调用；`readFd()`中直接写入缓冲区时调用 | 直接返回`begin() + writerIndex_`；                           |
| `const char *beginWrite() const`         | 返回缓冲区可写区间的起始地址（const 版本，只读）             | 调试 / 校验可写地址时调用，无实际业务场景                    | 直接返回`begin() + writerIndex_`，无其他逻辑；const 版本仅用于读取可写地址，无写入操作 |

> ### 1. beginWrite () 非 const 重载函数
>
> **作用**：返回缓冲区中可写数据起始地址（writerIndex_位置）的普通 char * 指针，支持通过该指针修改缓冲区数据；
>
> **调用时机**：当 Buffer 对象为非 const 类型，需要获取可写地址并修改缓冲区数据时调用。
>
> ### 2. beginWrite () const 重载函数
>
> **作用**：返回缓冲区中可写数据起始地址的 const char * 指针，仅允许读取地址指向的数据，禁止修改；
>
> **调用时机**：当 Buffer 对象为 const 类型（或调用场景要求 const 保护），仅需读取可写地址而不修改数据时调用。
>
> ### 核心区别
>
> 两者均返回可写起始地址，但非 const 版本允许修改缓冲区数据，仅用于非 const Buffer 对象；const 版本禁止修改数据，用于 const Buffer 对象，保证数据只读性。

#### 5. 底层内存操作（私有辅助）

| 函数名                      | 作用（私有成员函数，仅内部调用）                     | 调用时机                                                     | 内部逻辑 / 触发后续操作                                      |
| --------------------------- | ---------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `char* begin()`             | 返回`buffer_`底层数组的起始地址（非 const 版本）     | 所有需要访问缓冲区内存的函数内部调用（如`peek()`、`beginWrite()`、`makeSpace()`） | 直接返回`&*buffer_.begin()`（`vector`的`begin()`返回迭代器，解引用后取地址） |
| `const char *begin() const` | 返回`buffer_`底层数组的起始地址（const 版本）        | 只读场景下访问缓冲区内存时调用（如`peek() const`）           | 直接返回`&*buffer_.begin()`，无其他逻辑                      |
| `makeSpace(size_t len)`     | 扩容 / 整理缓冲区空间，确保能容纳`len`字节的可写数据 | `ensureWritableBytes()`中检测到可写空间不足时调用            | 分两种场景：1. **扩容**：若`可写空间 + 前置可用空间 < len + kCheapPrepend`（无法通过整理腾出空间），调用`buffer_.resize(writerIndex_ + len)`直接扩容；2. **整理空间**：否则将`[readerIndex_, writerIndex_]`的**可读数据**搬迁到`kCheapPrepend`起始位置，重置`readerIndex_ = kCheapPrepend`、`writerIndex_ = kCheapPrepend + 可读数据长度`，腾出连续可写空间 |

> * 两个版本的`begin()`函数设计原因同`beginWrite()`；
> * `&*buffer_.begin()` 这个表达式的意思是先获取vector底层数组的迭代器（`buffer_.begin()`），然后解引用这个迭代器得到数组的第一个元素（`*buffer_.begin()`），最后取这个元素的地址（`&*buffer_.begin()`）。这样就得到了vector底层数组的起始地址。💥	
>   * 原因：迭代器的行为类似指针，但本身不是原生指针（是一个封装的对象），因此不能直接用 `&` 取地址来获取底层数组地址。
> * C++11 及以上标准中，`std::vector` 提供了 `buffer_.data()` 成员函数，可直接返回底层数组的首地址（`char*`），等价于 `&*buffer_.begin()`。✅

> #### `makeSpace()`核心设计：
>
> - 优先整理空间（数据搬迁），避免频繁扩容：利用已读数据腾出的前置空间，将可读数据前移，形成连续可写区间；
> - 扩容仅在整理后仍不足时触发，减少内存分配开销；尽量复用现有空间，不盲目扩容
> - 数据搬迁使用`std::copy`，保证内存操作的高效性（`vector`内存连续，拷贝效率高）。
>
> #### 为什么不用 vector 1.5/2 倍自动扩容：
>
> 1. Buffer 是**双指针网络缓冲区**，有业务语义，vector 不懂
> 2. 自动扩容**不可控、浪费内存**
> 3. Buffer 优先**挪移数据复用空间**，而不是无脑扩容
> 4. 网络库要求**精确、稳定、可预测**的空间控制

#### 6. 网络 IO 操作（读写文件描述符）

| 函数名                            | 作用                                              | 调用时机                                                     | 内部逻辑 / 触发后续操作                                      |
| --------------------------------- | ------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `readFd(int fd, int *saveErrno)`  | 从指定文件描述符（如套接字 fd）读取数据到缓冲区   | 套接字可读事件触发时调用（如 TcpConnection 的`handleRead()`） | 1. 确保可写空间（结合`readv`分散读，优先用缓冲区可写空间，不足则临时分配栈内存）；2. 调用`::readv`读取数据，将数据写入缓冲区或临时内存；3. 若临时内存有数据，追加到缓冲区；4. 更新`writerIndex_`，保存错误码到`saveErrno`；5. 返回读取的字节数 |
| `writeFd(int fd, int *saveErrno)` | 将缓冲区可读数据写入指定文件描述符（如套接字 fd） | 套接字可写事件触发时调用（如 TcpConnection 的`handleWrite()`） | 1. 调用`::write`写入`peek()`指向的可读数据；2. 若写入成功，调用`retrieve(len)`消费对应长度数据；3. 保存错误码到`saveErrno`；4. 返回写入的字节数 |

> #### IO 操作核心优化：
>
> - `readFd`使用`readv`分散读：减少系统调用次数，优先利用缓冲区空间，避免小数据频繁扩容；
> - `writeFd`直接写入缓冲区数据：无需拷贝到临时内存，减少内存开销；
> - 错误码通过`saveErrno`传出：避免覆盖全局`errno`，保证错误信息准确。

### 补充说明

1. **核心设计逻辑**：
   - 三段式内存结构：通过`readerIndex_`/`writerIndex_`分离可读 / 可写区间，无需频繁分配 / 释放内存，兼顾效率与灵活性；
   - 按需扩容 + 空间整理：优先整理已读数据腾出的空间，仅在必要时扩容，减少内存碎片和分配开销；
   - 非侵入式数据消费：仅修改索引而非删除数据，降低内存操作成本，符合网络库 “高效读写” 的核心诉求。
2. **异常处理细节**：
   - `makeSpace()`中`std::copy`是内存连续拷贝，无边界越界风险（依赖`readableBytes()`计算有效数据长度）；
   - `readFd()`/`writeFd()`中处理`EAGAIN`/`EWOULDBLOCK`（非阻塞 IO 正常中断）：仅返回已读写字节数，不视为错误；
   - 缓冲区扩容时`vector::resize`会自动初始化新内存为 0，避免脏数据。
3. **与其他组件的协作**：
   - Buffer 是 TcpConnection 的核心成员：每个 TcpConnection 持有`inputBuffer_`（读缓冲区）和`outputBuffer_`（写缓冲区）；
   - 与 Channel/EventLoop 联动：`readFd()`在 Channel 读事件回调中调用，`writeFd()`在 Channel 写事件回调中调用，数据读写均在对应 EventLoop 线程执行；
   - 协议解析适配：`peek()`/`retrieve()`支持按需读取数据，适配自定义协议（如固定长度、分隔符协议）的解析逻辑。

### 扩展：分散读/写

> ### 分散读（readv）& 集中写（writev）核心总结表
>
> 以下表格从**函数功能、原型、核心参数、行为规则、典型场景、核心优势**等维度，完整梳理 `readv`/`writev` 这对对称的系统调用，方便你对比记忆和实际开发使用。
>
> |            维度            |                       分散读（readv）                        |                       集中写（writev）                       |
> | :------------------------: | :----------------------------------------------------------: | :----------------------------------------------------------: |
> |        **核心功能**        | 从**单个文件描述符**读取数据，分散写入到**多个不连续缓冲区** | 从**多个不连续缓冲区**读取数据，集中写入到**单个文件描述符** |
> |        **函数原型**        | `c<br>#include <sys/uio.h><br>ssize_t readv(int fd, const struct iovec *iov, int iovcnt);<br>` | `c<br>#include <sys/uio.h><br>ssize_t writev(int fd, const struct iovec *iov, int iovcnt);<br>` |
> |        **参数说明**        | - `fd`：待读取的文件描述符（socket / 文件 / 管道等）- `iov`：`iovec` 结构体数组，描述多个接收缓冲区- `iovcnt`：缓冲区数量（≤ 系统限制 `IOV_MAX`） | - `fd`：待写入的文件描述符（socket / 文件 / 管道等）- `iov`：`iovec` 结构体数组，描述多个发送缓冲区- `iovcnt`：缓冲区数量（≤ 系统限制 `IOV_MAX`） |
> |      **iovec 结构体**      | `c<br>struct iovec {<br>  void *iov_base; // 数据接收起始地址<br>  size_t iov_len;  // 接收缓冲区最大长度<br>};<br>` | `c<br>struct iovec {<br>  void *iov_base; // 待发送数据起始地址<br>  size_t iov_len;  // 待发送数据长度<br>};<br>` |
> |      **核心行为规则**      | 1. 按 `iov` 数组顺序填充缓冲区，先填 `iov[0]` 再填 `iov[1]`2. 读完数据 / 缓冲区满则停止3. 返回实际读取的字节数 | 1. 按 `iov` 数组顺序读取数据，先发 `iov[0]` 再发 `iov[1]`2. 写完数据 / 内核缓冲区满则停止3. 返回实际写入的字节数 |
> |         **返回值**         | - 成功：实际读取字节数（≤ 总缓冲区长度）- 失败：-1，设置 `errno`（如 `EINTR`/`EBADF`） | - 成功：实际写入字节数（≤ 总缓冲区长度）- 失败：-1，设置 `errno`（如 `EAGAIN`/`EBADF`） |
> |      **典型应用场景**      | 1. 网络 IO：TCP 读取数据时，用「内置 Buffer + 栈临时缓冲区」避免数据丢失（如 muduo 库的 `Buffer::readFd`）2. 文件读取：一次性读取数据到多个内存区域，无需拼接 | 1. 网络 IO：TCP 发送数据时，拼接「固定头 + 可变体」数据，无需拷贝2. 文件写入：一次性写入多个分散内存区域的数据，减少系统调用 |
> |        **核心优势**        | 1. 减少系统调用次数（1 次 `readv` = N 次 `read`），降低用户态 / 内核态切换开销2. 无需提前拼接缓冲区，适配动态内存布局 | 1. 减少系统调用次数（1 次 `writev` = N 次 `write`），降低用户态 / 内核态切换开销2. 避免数据拷贝，直接发送分散内存数据 |
> |        **注意事项**        | 1. 非阻塞场景下可能只读取部分数据，需上层处理剩余数据2. `iovcnt` 不能超过系统限制（Linux 默认 `IOV_MAX=1024`） | 1. 非阻塞场景下可能只写入部分数据，需上层记录进度并重试2. `iovcnt` 不能超过系统限制（Linux 默认 `IOV_MAX=1024`） |
> | **与普通 read/write 对比** |     适合「数据长度不确定 + 多缓冲区接收」场景，效率更高      |   适合「多缓冲区数据拼接发送」场景，避免内存拷贝，效率更高   |
>
> ### 补充：实战关键要点
>
> 1. **非阻塞 IO 处理**：无论 `readv` 还是 `writev`，非阻塞场景下都可能返回「部分读写」（返回值 >0 但 < 总长度），需上层根据返回值记录已处理字节数，下次继续操作剩余数据；
> 2. **指针移动**：在网络库中，`readv` 读取数据后需移动 Buffer 的 `writerIndex_`，`writev` 写入数据后需上层手动移动 `readerIndex_`；
> 3. **内存安全**：栈缓冲区（如 64KB `extrabuf`）配合 `readv` 使用时，需确保栈空间足够（Linux 默认栈大小 8MB），避免栈溢出。
>
> ### 总结
>
> `readv`/`writev` 是高性能网络 / 文件 IO 的核心系统调用，核心价值是**减少系统调用次数 + 适配分散内存布局**，是 muduo、libevent 等高性能网络库的标配用法。记住「`readv` 分散读、`writev` 集中写」的核心逻辑，以及「非阻塞场景需上层处理部分读写」的关键规则，就能快速落地到实际开发中。
