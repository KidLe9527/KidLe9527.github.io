# Logger 类 成员变量 & 成员函数 作用总结

### 一、成员变量

| 变量名      | 作用                                                         | 调用 / 生效时机                                              |
| ----------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `logLevel_` | 标识 Logger 当前生效的日志级别（INFO/ERROR/FATAL/DEBUG），仅输出**大于等于该级别**的日志（注：代码未显式做级别过滤，需结合 log 方法实现） | 构造时默认初始化（未显式指定，通常为 INFO）；调用`setLogLevel()`时更新；`log()`方法输出日志时，可基于该值判断是否输出 |

### 二、宏定义（日志快捷调用入口）

Logger 核心通过宏封装日志调用逻辑，降低上层使用成本，宏是外部使用 Logger 的主要方式：

| 宏名        | 作用                                                         | 调用时机                                                     | 内部逻辑 / 关键细节                                          |
| ----------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `LOG_INFO`  | 输出 INFO 级别日志，支持格式化字符串 + 可变参数              | 业务代码中需要打印普通运行信息时调用（如 “服务启动成功”“连接建立”） | 1. 获取 Logger 单例；2. 设置日志级别为 INFO；3. 通过`snprintf`格式化日志内容；4. 调用`log()`输出；5. `do-while(0)`包裹保证宏在分支 / 循环中语法合法 |
| `LOG_ERROR` | 输出 ERROR 级别日志，支持格式化字符串 + 可变参数             | 业务代码中捕获到可恢复错误时调用（如 “连接超时”“参数错误”）  | 逻辑同`LOG_INFO`，仅设置级别为 ERROR                         |
| `LOG_FATAL` | 输出 FATAL 级别日志，支持格式化字符串 + 可变参数，输出后**强制退出程序** | 业务代码中捕获到不可恢复致命错误时调用（如 “监听端口失败”“核心资源初始化失败”） | 逻辑同`LOG_INFO`，设置级别为 FATAL；输出日志后**调用`exit(-1)`终止进程** |
| `LOG_DEBUG` | 输出 DEBUG 级别日志，支持格式化字符串 + 可变参数，**仅在 MUDEBUG 宏定义时生效** | 开发 / 调试阶段打印详细调试信息（如 “函数入参”“循环次数”），生产环境编译时自动失效 | 1. 定义`MUDEBUG`时：逻辑同`LOG_INFO`，设置级别为 DEBUG；2. 未定义`MUDEBUG`时：宏为空，编译阶段直接剔除，无运行时开销 |

> #### 宏设计关键细节：
>
> 1. `##__VA_ARGS__`：兼容 “无可变参数” 的场景（如`LOG_INFO("服务启动")`），避免编译报错；
> 2. 固定 1024 字节缓冲区：`char buf[1024]`限制单条日志最大长度，超出部分会被截断，需注意格式化字符串长度；
> 3. 单例复用：所有宏均通过`Logger::instance()`获取唯一实例，保证日志配置（如级别、输出目标）全局统一。

### 三、枚举（日志级别定义）

| 枚举名  | 作用             | 对应场景                                                     |
| ------- | ---------------- | ------------------------------------------------------------ |
| `INFO`  | 普通信息级别     | 常规运行日志，如启动 / 停止、连接建立 / 断开、配置加载等     |
| `ERROR` | 错误信息级别     | 非致命错误，如网络超时、参数校验失败、文件读取失败等可恢复场景 |
| `FATAL` | 核心崩溃信息级别 | 致命错误，如端口绑定失败、内存耗尽、核心组件初始化失败等不可恢复场景 |
| `DEBUG` | 调试信息级别     | 开发阶段的详细日志，如函数入参 / 出参、循环状态、临时变量值等 |

### 四、成员函数

#### 1. 单例控制（核心访问入口）💥

| 函数名                      | 作用                                                   | 调用时机                                                     | 内部逻辑 / 设计考量                                          |
| --------------------------- | ------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `static Logger &instance()` | 获取 Logger 唯一实例（单例模式），保证全局日志配置统一 | 所有日志宏（LOG_INFO/ERROR 等）内部调用；外部也可直接调用获取实例 | 1. 单例实现：通常为 “局部静态变量” 模式（线程安全，C++11 后）；2. 返回引用而非指针：避免空指针风险，简化调用；3. 单例设计：保证日志级别、输出目标等配置全局唯一 |

> 1. **`static Logger logger`**
>
>    静态局部变量 → **只创建一次，全局唯一，程序结束才销毁**。
>
> 2. **返回 `Logger&`**
>
>    返回引用 → **不拷贝、不产生新对象，保证单例，安全好用**。
>
> 3. **`static Logger& instance()`**
>
>    静态成员函数 → **不用创建对象就能调用，是获取单例唯一入口**。同时单例**不让外部创建对象**（构造函数是私有的）
>
> 4. **整个函数的目的**
>
>    保证整个程序**永远只有一个 Logger 对象**。
>
>    > Q：关于第2点，为什么不返回指针？
>    >
>    > A：指针暴露后可被`delete`，是因为指针是 “地址容器”，语法允许`delete 指针`；引用是 “对象别名”，语法禁止`delete 引用`，因此单例模式（如你的`Logger`）返回引用更安全； （`instance`在oop中是实例的概念）

#### 2. 日志级别控制

| 函数名                        | 作用                                                         | 调用时机                                                     | 内部逻辑 / 触发后续操作                                      |
| ----------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `void setLogLevel(int level)` | 设置 Logger 当前的日志级别，后续仅输出该级别及以上的日志（需结合 log 方法实现） | 1. 日志宏内部自动调用（如 LOG_INFO 调用时设置为 INFO）；2. 外部可主动调用（如程序启动时设置为 DEBUG 级别） | 直接将成员变量`logLevel_`赋值为传入的`level`（枚举值）；无其他逻辑，仅更新级别标识 |

#### 3. 日志输出核心逻辑

| 函数名                      | 作用                                                         | 调用时机                                                     | 内部逻辑 / 扩展说明                                          |
| --------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `void log(std::string msg)` | 日志输出的核心方法，接收格式化后的日志字符串并输出（如控制台 / 文件） | 所有日志宏格式化完成后调用；外部也可直接调用（需手动格式化字符串） | 1. 核心逻辑：实现日志的实际输出（代码未展示具体实现，通常包括：时间戳拼接、级别前缀添加、输出到控制台 / 文件 / 网络等）；2. 扩展：可结合`logLevel_`做级别过滤（如当前级别为 INFO 时，不输出 DEBUG 日志）；3. 线程安全：生产环境需保证该方法线程安全（如加锁），避免多线程输出日志错乱 |

#### 4. 构造 / 析构函数（隐式，代码未显式定义）

| 函数名      | 作用                                                         | 调用时机                                   | 补充说明                                                     |
| ----------- | ------------------------------------------------------------ | ------------------------------------------ | ------------------------------------------------------------ |
| `Logger()`  | 初始化 Logger 核心资源：1. 将`logLevel_`初始化为默认值（如 INFO）；2. 初始化日志输出相关资源（如文件句柄、锁等，代码未展示） | 首次调用`instance()`时创建单例实例时调用   | 私有构造函数（单例模式要求）：禁止外部通过`new`创建实例，保证全局唯一，实例只能由 `instance()` 方法创建 |
| `~Logger()` | 释放 Logger 资源：1. 关闭日志输出相关资源（如文件句柄）；2. 释放锁等同步资源（代码未展示） | 程序退出时，单例实例生命周期结束时自动调用 | 私有析构函数（单例模式要求）：禁止外部手动析构， 保证实例的销毁完全由程序生命周期控制，避免误操作导致的崩溃 / 异常； |

> #### 单例模式补充：
>
> Logger 继承`noncopyable`：禁用拷贝构造和赋值运算符，从语法上保证实例无法被拷贝，强化单例的唯一性。

> ⚠️ 默认构造和析构函数都是公有属性，单例模式中必须手动声明为`private`，防止外部直接创建 / 销毁实例，保证实例只能通过`instance()`获取；（本项目省略了这些细节）～
>
> 当`Logger`继承`noncopyable`后：
>
> ​	编译器会默认让`Logger`的拷贝构造、赋值运算符也被禁用（因为父类的拷贝 / 赋值被禁用，子类无法继承这两个函数，且编译器不会为子类生成默认的拷贝 / 赋值）；

### 补充说明

1. **核心设计逻辑**：
   - 极简封装：通过宏屏蔽日志级别设置、字符串格式化、单例获取等细节，上层仅需调用`LOG_XXX`即可输出日志；
   - 条件编译：`LOG_DEBUG`通过`MUDEBUG`宏控制，实现 “调试日志按需编译”，生产环境无性能损耗；
   - 职责分离：Logger 类仅负责 “级别管理 + 日志输出”，格式化由宏结合`snprintf`完成，符合 “单一职责” 原则。
2. **使用注意事项**：
   - 日志长度限制：宏中固定 1024 字节缓冲区，超长日志会被截断，需避免单条日志内容过长；
   - 线程安全：`log()`方法若未做线程安全处理，多线程同时输出日志会导致内容错乱，生产环境需添加互斥锁；
   - 级别过滤：代码中仅定义了`logLevel_`，但未在`log()`方法中实现级别过滤，需补充逻辑（如：若当前级别为 INFO，忽略 DEBUG 日志）。
3. **异常处理细节**：
   - `snprintf`格式化失败：若格式化字符串非法（如占位符与参数不匹配），会返回负数，宏中未做错误处理，可能导致日志为空；
   - `LOG_FATAL`强制退出：调用`exit(-1)`会直接终止进程，需确保仅在真正致命的场景使用，避免误调用导致程序异常退出。
4. **与其他组件的协作**：
   - 无外部依赖：仅依赖`noncopyable.h`（禁用拷贝）和标准库，可独立集成到任意模块；
   - 全局复用：所有业务模块（如 Acceptor、TcpServer、TcpConnection）均可通过`LOG_XXX`宏使用同一 Logger 实例，保证日志格式 / 级别全局统一。
5. **可扩展方向**：
   - 日志输出目标：当前`log()`方法未实现具体输出逻辑，可扩展为输出到控制台、文件、日志服务器等；
   - 日志格式化：可在`log()`方法中添加时间戳、进程 ID、线程 ID、日志级别前缀等；
   - 动态级别调整：可添加接口支持运行时修改日志级别（如通过配置文件、信号），无需重启程序。
