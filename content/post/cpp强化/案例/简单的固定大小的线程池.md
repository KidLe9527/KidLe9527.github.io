# 线程池实现1

* 一个完整的线程池至少包含一个主线程，一个线程池，，一个任务队列

```cpp
#include <iostream>
#include <queue>
#include <thread>
#include <mutex>
#include <condition_variable>
#include <future>
#include <functional>
#include <vector>

// 任务队列：存储“带返回值的任务”（包装成 std::packaged_task）
using Task = std::function<void()>; // 包装 packaged_task 的无参函数

class ThreadPool {
private:
    std::queue<Task> task_queue_;   // 任务队列, 存储待执行任务，每个任务会设置对应的 future 结果，包装成无参函数，为了统一处理
    std::mutex mtx_;
    std::condition_variable cv_;    // 条件变量，通知工作线程有新任务，等待任务或停止信号
    std::vector<std::thread> workers_; // 工作线程池，消费者线程，负责取任务执行
    bool stop_ = false; // 停止标志，用于析构时停止线程池

public:
    ThreadPool(size_t n) { // n：工作线程数量
    for (size_t i = 0; i < n; ++i) { // 循环创建n个线程
        workers_.emplace_back([this]() { // 每个线程的执行逻辑（lambda表达式）
            while (true) { // 线程核心循环：持续处理任务
                Task task; // 存储取出的任务（Task = std::function<void()>）
                { // 代码块：限制互斥锁的作用域（自动释放锁）
                    // 1. 加锁 + 等待条件（任务队列非空 或 线程池停止）
                    std::unique_lock<std::mutex> lock(mtx_);
                    cv_.wait(lock, [this]() { return stop_ || !task_queue_.empty(); });

                    // 2. 退出条件：线程池停止 + 任务队列空（无任务可执行）
                    if (stop_ && task_queue_.empty()) return;

                    // 3. 从队列取出任务（移动语义，避免拷贝）
                    task = std::move(task_queue_.front());
                    task_queue_.pop();
                } // 锁自动释放（unique_lock析构）

                // 4. 执行任务（无锁，并发执行）
                task(); 
            }
        });
    }
}

    // 提交任务，返回 future（供主线程获取结果）
    template <typename F, typename... Args>
    auto submit(F&& f, Args&&... args) -> std::future<decltype(f(args...))> {
        // 包装任务为 packaged_task（关联 future）
        using ReturnType = decltype(f(args...));
        auto task = std::make_shared<std::packaged_task<ReturnType()>>(
            std::bind(std::forward<F>(f), std::forward<Args>(args)...)
        );
        std::future<ReturnType> fut = task->get_future();

        // 把 packaged_task 放入队列（包装成无参 Task）
        {
            std::lock_guard<std::mutex> lock(mtx_);
            task_queue_.emplace([task]() { (*task)(); });
        }
        cv_.notify_one(); // 唤醒工作线程

        return fut;
    }

    // 析构：停止线程池
    ~ThreadPool() {
        {
            std::lock_guard<std::mutex> lock(mtx_);
            stop_ = true; // 设置停止标志，通知所有线程退出，准备关闭线程池
        }
        cv_.notify_all();   // 唤醒所有线程，准备退出
        for (auto& worker : workers_) {
            worker.join();  // 等待所有线程结束
        }
    }
};

// 示例任务：计算平方
int square(int x) {
    std::this_thread::sleep_for(std::chrono::milliseconds(200));
    return x * x;
}

int main() {
    ThreadPool pool(2); // 2 个工作线程（消费者）

    // 提交 3 个任务（生产者），获取 future
    std::future<int> fut1 = pool.submit(square, 2);
    std::future<int> fut2 = pool.submit(square, 3);
    std::future<int> fut3 = pool.submit(square, 4);

    // 获取每个任务的结果（future 的核心作用）
    std::cout << "2² = " << fut1.get() << std::endl;
    std::cout << "3² = " << fut2.get() << std::endl;
    std::cout << "4² = " << fut3.get() << std::endl;

    return 0;
}
```

## 解释

### 核心类型定义--无参无返回值

```cpp
using Task = std::function<void()>; // 包装 packaged_task 的无参函数
```

线程池的任务队列统一存储**无参无返回值的函数**，这是为了让不同返回值、不同参数的任务能被统一管理 —— 所有任务都会被包装成 `void()` 类型，内部再调用实际的 `packaged_task`。

* 这行代码是 C++11 引入的**类型别名（type alias）**，核心是给复杂的类型 `std::function<void()>` 起一个简洁的名字 `Task`
* 线程池的核心需求是：能接收**任意参数、任意返回值**的任务，`std::function<void()>` 就是这个 “固定格式”：无论原任务有多少参数、返回值是什么，都可以通过包装（比如绑定参数、封装返回值）转换成 “无参、无返回值” 的函数，最终存入队列。
  * **为什么无参数**：任务的参数在提交时已经通过 `std::bind` 绑定（比如 `submit(square, 2)` 会把参数 `2` 绑定到 `square` 上），因此执行任务时不需要再传参，天然是无参接口；
  * **为什么无返回值**：任务的返回值通过 `std::packaged_task` + `std::future` 管理（返回值会被存储到 `future` 中，主线程通过 `future.get()` 获取），因此任务执行时对外不需要返回值，只需要 “内部处理返回值”。

| `using`         | C++11 定义类型别名的关键字（替代旧的 `typedef`，更直观、支持模板）；对比 `typedef` 写法：`typedef std::function<void()> Task;`，效果完全一致，但 `using` 更易读。 |
| --------------- | ------------------------------------------------------------ |
| `std::function` | C++11 提供的**通用函数包装器**（头文件 `<functional>`），可以包装任意可调用对象：普通函数、lambda 表达式、函数指针、成员函数、仿函数（重载 `operator()` 的类）等。 |



### 构造函数代码解释

```cpp
ThreadPool(size_t n) { // n：工作线程数量
    for (size_t i = 0; i < n; ++i) { // 循环创建n个线程
        workers_.emplace_back([this]() { // 每个线程的执行逻辑（lambda表达式）
            while (true) { // 线程核心循环：持续处理任务
                Task task; //（Task = std::function<void()>）/ 声明一个空的Task，用于存储从队列取出的任务
                { // 代码块：限制互斥锁的作用域（自动释放锁）
                    // 1. 加锁 + 等待条件（任务队列非空 或 线程池停止）
                    std::unique_lock<std::mutex> lock(mtx_); 
                    cv_.wait(lock, [this]() { return stop_ || !task_queue_.empty(); });

                    // 2. 退出条件：线程池停止 + 任务队列空（无任务可执行）
                    if (stop_ && task_queue_.empty()) return;

                    // 3. 从队列取出任务（移动语义，避免拷贝）
                    task = std::move(task_queue_.front());
                    task_queue_.pop();
                } // 锁自动释放（unique_lock析构）

                // 4. 执行任务（无锁，并发执行）
                task(); 
            }
        });
    }
}
```

* 这段代码是线程池的**构造函数**，核心作用是创建指定数量的工作线程，并为每个线程定义 “持续从任务队列取任务、执行任务，直到线程池停止” 的核心逻辑。

```cpp
workers_.emplace_back([this]() { ... });
```

- `workers_` 是 `std::vector<std::thread>` 类型，存储所有工作线程；

- `emplace_back`：直接在 vector 尾部构造线程（比 `push_back` 更高效，避免拷贝线程对象）；

- `std::thread` 的构造函数接收一个**可调用对象**（这里是 lambda 表达式），线程启动后会立即执行这个 lambda；

- `[this]()`：lambda 表达式的捕获列表 + 参数列表：

  - `[this]`：捕获当前 `ThreadPool` 对象的指针，**让 lambda 能访问类的成员**（如 `task_queue_`、`mtx_`、`cv_`、`stop_`）；
  - `()`：lambda 无参数（符合线程函数的默认要求）。

  

- ⚠️  **创建线程对象后，for 循环的当前迭代就完成了**（`emplace_back` 执行完，循环变量 `i` 就会自增）

  - 循环的 “迭代过程” 只负责**创建线程对象**（耗时极短）；
  - 线程的 “执行逻辑”（lambda 里的 `while(true)` 循环、取任务、执行任务）是**操作系统调度的异步操作**，和 for 循环的迭代过程完全分离 —— 哪怕 lambda 里的代码执行几秒钟，for 循环也早就完成了所有迭代（因为创建线程对象的动作是瞬间的）。



```cpp
std::unique_lock<std::mutex> lock(mtx_); 
cv_.wait(lock, [this]() { return stop_ || !task_queue_.empty(); });
```

1. std::unique_lock<std::mutex> lock(mtx_);  ----> 自动上锁
2. cv_.wait(lock, [this]() { return stop_ || !task_queue_.empty(); });
   * 首先立刻释放mutex并阻塞线程，直到其他线程唤醒
   * 唤醒后重新获得锁，枷锁并检查条件
   * 如果条件符合就退出等待，执行后续的代码；false就释放锁然后继续阻塞直到下一次唤醒
   * 这里的条件是当线程池停止或者任务队列非空 --> 这时候就需要 取任务执行



```cpp
if (stop_ && task_queue_.empty()) return;
```

这是线程退出循环的唯一条件，含义是：

- `stop_ = true`：线程池已触发析构，要求停止；
- `task_queue_.empty()`：任务队列已空，没有剩余任务需要执行；
- 两个条件同时满足时，线程执行 `return`，退出 lambda 表达式，线程随之结束。

**为什么要检查 “任务队列空”？**

避免线程池停止时，队列中还有未执行的任务被丢弃 —— 线程会先执行完队列中所有任务，再退出。



```cpp
task = std::move(task_queue_.front());
task_queue_.pop();
```

- `task_queue_.front()`：获取队列头部的任务（待执行）；
- `std::move`：**移动语义**，将队列中的任务 “转移” 到 `task` 变量中（`std::function` 是可移动但不可拷贝的类型，必须用 `move`）；
- `task_queue_.pop()`：移除队列头部的任务（已取出，避免重复执行）；
- 整个操作在锁保护下完成，保证线程安全（多个线程同时取任务不会冲突）。



### 提交任务代码解释

```cpp
    // 提交任务，返回 future（供主线程获取结果）
    template <typename F, typename... Args>
    auto submit(F&& f, Args&&... args) -> std::future<decltype(f(args...))> {
        // 包装任务为 packaged_task（关联 future）
        using ReturnType = decltype(f(args...));
        auto task = std::make_shared<std::packaged_task<ReturnType()>>(
            std::bind(std::forward<F>(f), std::forward<Args>(args)...)
        );
        std::future<ReturnType> fut = task->get_future();

        // 把 packaged_task 放入队列（包装成无参 Task）
        {
            std::lock_guard<std::mutex> lock(mtx_);
            task_queue_.emplace([task]() { (*task)(); });
        }
        cv_.notify_one(); // 唤醒工作线程

        return fut;
    }
```

* 这段代码是线程池的核心接口 `submit` 方法，作用是**接收任意参数、任意返回值的任务，将其包装后放入线程池的任务队列，并返回一个 `future` 对象供主线程获取任务执行结果**。

#### 线程池的 `submit` 要解决 3 个核心问题

1. **通用性**：能接收任意类型的函数（比如 `int square(int)`、`std::string get_name()`、`void print()`）和任意数量的参数；
2. **结果可获取**：主线程提交任务后，能通过一个 “句柄”（`future`）获取异步执行的结果；
3. **线程安全**：将任务放入队列的过程要加锁，避免多线程提交任务时冲突。



```cpp
template <typename F, typename... Args>
auto submit(F&& f, Args&&... args) -> std::future<decltype(f(args...))> {
```

这是 C++11 引入的**可变参数模板** + **尾返回类型推导**，是实现 “通用任务提交” 的基础 🔥🔥

* 可变参数
* 尾返回类型
* `decltype` 自动推导函数类型

| 语法部分                                  | 含义                                                         |
| ----------------------------------------- | ------------------------------------------------------------ |
| `template <typename F, typename... Args>` | 模板参数：- `F`：任务函数的类型（比如 `int(*)(int)`，即 `square` 的类型）；- `Args...`：**可变参数**包，接收任务函数的所有参数类型（比如 `square(2)` 的参数类型是 `int`）。 |
| `F&& f, Args&&... args`                   | 函数参数：- `&&` 是**万能引用**（既能接收左值，也能接收右值）；- `f` 是传入的任务函数（比如 `square`）；- `args...` 是传入的任务参数（比如 `2`、`3`）。 |
| `auto ... -> 尾返回类型`                  | 尾返回类型推导：先执行函数体的类型计算，再确定返回值类型（避免返回值类型写在前面的冗余）。 |
| `std::future<decltype(f(args...))>`       | 返回值类型：- `decltype(f(args...))`：推导任务函数执行后的返回类型（比如 `square(2)` 的返回值是 `int`，则这里是 `std::future<int>`）；- `std::future`：异步结果的 “句柄”，主线程通过它获取任务结果。 |

> ### 1. 可变参数模板（Variadic Templates）
>
> C++11 引入的**可变参数模板**允许模板接收**任意数量、任意类型**的模板参数，核心语法是 `typename... Args`（模板参数包）和 `Args&&... args`（函数参数包）。
>
> #### （1）模板参数包：`typename... Args`
>
> - `...` 是**参数包展开符**，`Args` 是一个 “参数包”，代表**零个或多个类型**（比如 `int`、`std::string`、`double&` 等）。
> - 示例：如果调用 `submit(func, 1, "hello", 3.14)`，则：
>   - `F` 推导为 `func` 的类型（比如 `void(*)(int, const char*, double)`）；
>   - `Args` 推导为参数包 `int, const char*, double`。
>
> #### （2）函数参数包：`Args&&... args`
>
> - `Args&&...` 是**万能引用（Universal Reference）** 结合参数包，用于接收任意数量、任意值类别（左值 / 右值）的参数。
> - `args` 是函数参数包，代表 “零个或多个参数”，与模板参数包 `Args` 一一对应。
> - 注意：参数包必须通过 `...` 展开才能使用（比如 `f(args...)` 就是展开参数包，将所有参数传递给 `f`）。
>
> #### 可变参数模板的关键特点
>
> - 支持 “任意数量参数”：比如 `submit(f)`（无参数）、`submit(f, 1)`（1 个参数）、`submit(f, 1, 2.0)`（2 个参数）都能匹配。
> - 类型推导自动适配：无需为不同参数数量写多个重载版本。
>
> ------
>
> ### 2. 尾返回类型（Trailing Return Type）
>
> 语法：`auto 函数名(参数列表) -> 返回类型`，是 C++11 引入的返回类型声明方式，解决传统返回类型声明的两个核心问题：
>
> #### （1）传统返回类型的痛点
>
> 如果返回类型依赖于函数参数（比如本例中返回类型依赖 `f` 和 `args` 的类型），传统写法无法直接引用参数（因为返回类型声明在函数名前，参数还未声明）：
>
> ```cpp
> // 错误：返回类型中使用的f/args还未声明
> template <typename F, typename... Args>
> std::future<decltype(f(args...))> submit(F&& f, Args&&... args) { ... }
> ```
>
> #### （2）尾返回类型的优势
>
> - 把返回类型写在 `->` 后面，此时函数参数（`f`、`args`）已经声明，可以直接引用。
> - `auto` 是 “占位符”，告诉编译器 “返回类型在 `->` 后面”。
>
> #### 本例中的尾返回类型
>
> ```cpp
> auto submit(F&& f, Args&&... args) -> std::future<decltype(f(args...))>
> ```
>
> - `auto`：占位符，实际返回类型是 `->` 后的 `std::future<...>`。
> - 核心：返回类型是 `std::future`，其模板参数是 `f(args...)` 的调用结果类型（由 `decltype` 推导）。
>
> ------
>
> ### 3. `decltype(f(args...))` 语法
>
> `decltype` 是 C++11 引入的**类型推导关键字**，作用是 “推导表达式的类型，且不执行表达式”。
>
> #### （1）基本语法
>
> ```cpp
> decltype(表达式)  // 推导表达式的类型
> ```
>
> - 示例：`int a=1; decltype(a) b;` → `b` 的类型是 `int`。
> - 关键：`decltype` 只做 “类型分析”，不执行表达式（比如 `decltype(f(args...))` 不会真的调用 `f`，只是推导调用后的返回类型）。
>
> #### （2）本例中 `decltype(f(args...))` 的含义
>
> - `f`：传入的可调用对象（函数、lambda、函数对象等）。
> - `args...`：展开的参数包（所有传入的参数）。
> - `f(args...)`：模拟 “用 args 调用 f” 的表达式。
> - `decltype(...)`：推导这个调用表达式的返回类型。
>
> #### 示例拆解
>
> ```cpp
> // 定义一个函数
> int add(int a, double b) { return a + b; }
> 
> // 调用 submit
> auto fut = submit(add, 1, 2.0);
> ```
>
> - `f` 是 `add`（类型为 `int(*)(int, double)`）。f 返回int 类型， f 是 int* 类型，要加上参数类型～～～
> - `args...` 是 `1`（`int`）和 `2.0`（`double`）。
> - `f(args...)` 即 `add(1, 2.0)`，表达式的返回类型是 `int`。
> - `decltype(f(args...))` 推导为 `int`。
> - 最终 `submit` 的返回类型是 `std::future<int>`。
>
> #### （3）为什么不用 `std::result_of`？
>
> C++11 还有 `std::result_of<F(Args...)>::type` 也能推导可调用对象的返回类型，但：
>
> - `decltype(f(args...))` 更直观（直接模拟调用）。
> - C++17 后 `std::result_of` 被标记为**废弃**，推荐用 **`std::invoke_result_t<F, Args...>`**（等价于 `decltype(std::invoke(f, args...))`）。
> - 本例中 `decltype(f(args...))` 是最简洁的写法（前提是 `f` 可直接调用）。



```cpp
using ReturnType = decltype(f(args...));
```

* 推导任务的返回类型
  * `decltype(f(args...))`：编译期推导 “调用 `f(args...)` 后的返回类型”（比如 `f` 是 `square`，`args` 是 `2`，则 `ReturnType = int`）；
  * 用 `using` 定义别名，简化后续 `packaged_task` 的类型书写（避免重复写 `decltype(f(args...))`）。



```cpp
auto task = std::make_shared<std::packaged_task<ReturnType()>>(
    std::bind(std::forward<F>(f), std::forward<Args>(args)...) // 绑定函数和参数
);
```

* 这是核心步骤 —— 将 “带参数的任务” 转换成 “无参任务”，包装任务为 `packaged_task`，并关联 `future `🔥🔥

| 代码部分                           | 含义                                                         |
| ---------------------------------- | ------------------------------------------------------------ |
| `std::packaged_task<ReturnType()>` | 任务包装器：- 模板参数 `ReturnType()` 表示 “无参数、返回值为 `ReturnType` 的可调用对象”；- `packaged_task` 的核心作用：将任务的执行结果存储到内部的 `promise` 中，供 `future` 获取。 |
| `std::bind(...)`                   | 绑定函数与参数：- 将任务函数 `f` 和参数 `args...` 绑定，生成一个**无参可调用对象**（比如 `bind(square, 2)` 后，调用时无需传参，直接执行 `square(2)`）；- `std::forward`：完美转发，保留参数的左值 / 右值属性（避免拷贝开销，支持移动语义的参数）。 |
| `std::make_shared<...>`            | 用智能指针包装 `packaged_task`：- `packaged_task` 不支持拷贝（只能移动），但后续要将其放入 lambda 捕获列表（lambda 按值捕获时要求对象可拷贝）；- 用 `shared_ptr` 包装后，捕获的是指针（拷贝指针是允许的），且能保证 `packaged_task` 的生命周期直到任务执行完毕。 |

* 这里的auto -> `std::shared_ptr<std::packaged_task<ReturnType()>>`
* **创建一个可共享的、封装了 “无参数 / 返回 ReturnType” 可调用对象的异步任务，通过 shared_ptr 托管其生命周期，以便在多线程间安全传递和执行**。`()`里面就是这个可调用对象



```cpp
std::future<ReturnType> fut = task->get_future();
```

- `packaged_task` 内部关联了一个 `promise`，`get_future()` 会返回这个 `promise` 对应的 `future`；
- 这个 `fut` 最终会返回给主线程，主线程调用 `fut.get()` 就能获取任务执行结果（如果任务未执行完，`get()` 会阻塞等待）。



```cpp
{
    std::lock_guard<std::mutex> lock(mtx_);
    task_queue_.emplace([task]() { (*task)(); });
  	// *task 解引用 shared_ptr, (*task)() 调用 packaged_task 的 operator()
}
```

* `[task]() { (*task)(); }`

  * lambda 表达式（核心包装逻辑）：

    \- `[task]`：**按值捕获** `shared_ptr<packaged_task>`（拷贝指针，而非 `packaged_task` 本身）；

    \- `()`：无参数（符合 `Task = std::function<void()>` 的要求）；

    \- `(*task)()`：解引用智能指针，调用 `packaged_task`（执行绑定好的任务，比如 `square(2)`）。



```cpp
cv_.notify_one(); // 唤醒工作线程
return fut;       // 返回 future 给主线程
```

- `cv_.notify_one()`：通知条件变量，唤醒一个阻塞的工作线程（工作线程被唤醒后会从队列取任务执行）；
- `return fut`：将 `future` 返回给调用者（比如主线程 `auto fut1 = pool.submit(square, 2)`），主线程通过这个 `fut` 最终获取结果。

# 线程池实现2

```cpp
#include <iostream>
#include <vector>
#include <queue>
#include <thread>
#include <mutex>
#include <condition_variable>
#include <future>
#include <functional>
#include <stdexcept> // for std::runtime_error
#include <memory> // for std::unique_ptr

// 线程池类
class ThreadPool {
public:
    // 构造函数：创建n个工作线程
    explicit ThreadPool(size_t thread_num) 
        : stop_flag_(false) { // 初始时线程池未停止
        // 检查线程数量是否合法
        if (thread_num == 0) {
            throw std::invalid_argument("线程池线程数量不能为0！");
        }

        // 创建thread_num个工作线程
        for (size_t i = 0; i < thread_num; ++i) {
            workers_.emplace_back(
                [this]() { // 每个线程的工作函数
                    while (true) { // 线程循环执行任务
                        // 任务对象：用unique_ptr包装，避免拷贝
                        std::unique_ptr<std::function<void()>> task;

                        // ---------- 临界区：操作任务队列 ----------
                        {
                            // 加锁（unique_lock支持手动解锁）
                            std::unique_lock<std::mutex> lock(this->mtx_);

                            // 等待条件：任务队列不为空 或 线程池停止
                            this->cv_.wait(lock, 
                                [this]() { 
                                    return this->stop_flag_ || !this->tasks_.empty(); 
                                });

                            // 若线程池停止 且 任务队列为空，线程退出
                            if (this->stop_flag_ && this->tasks_.empty()) {
                                return;
                            }

                            // 从队列取出一个任务（移动语义，避免拷贝）
                            task = std::move(this->tasks_.front());
                            this->tasks_.pop();
                        }
                        // ---------- 临界区结束 ----------

                        // 执行任务（此时已解锁，其他线程可操作队列）
                        (*task)();
                    }
                }
            );
        }
    }

    // 禁止拷贝构造和拷贝赋值
    ThreadPool(const ThreadPool&) = delete;
    ThreadPool& operator=(const ThreadPool&) = delete;

    // 析构函数：停止线程池并等待所有工作线程结束
    ~ThreadPool() {
        // ---------- 临界区：修改停止标志 ----------
        {
            std::unique_lock<std::mutex> lock(mtx_);
            stop_flag_ = true; // 设置停止标志
        }
        // ---------- 临界区结束 ----------

        cv_.notify_all(); // 唤醒所有等待的工作线程

        // 等待所有工作线程执行完毕
        for (std::thread& worker : workers_) {
            if (worker.joinable()) {
                worker.join();
            }
        }
    }

    // 提交任务到线程池，返回std::future用于获取任务结果
    // 支持任意参数和返回值的函数/可调用对象
    template<class F, class... Args>
    auto submit(F&& f, Args&&... args) -> std::future<typename std::result_of<F(Args...)>::type> {
        // 任务的返回值类型
        using ReturnType = typename std::result_of<F(Args...)>::type;

        // 用packaged_task包装任务（将任务与future绑定）
        // 注意：用shared_ptr包装packaged_task，避免拷贝（packaged_task不可拷贝）
        auto task = std::make_shared<std::packaged_task<ReturnType()>>(
            std::bind(std::forward<F>(f), std::forward<Args>(args)...)
        );

        // 获取与任务关联的future（用于后续获取结果）
        std::future<ReturnType> res = task->get_future();

        // ---------- 临界区：将任务加入队列 ----------
        {
            std::unique_lock<std::mutex> lock(mtx_);

            // 若线程池已停止，禁止提交新任务
            if (stop_flag_) {
                throw std::runtime_error("线程池已停止，无法提交新任务！");
            }

            // 关键修改：先构造function<void()>，再用make_unique包装成unique_ptr
            // 避免直接用lambda构造unique_ptr（类型不匹配）
            auto func = [task]() { (*task)(); }; // 先创建function对象
            tasks_.emplace(std::make_unique<std::function<void()>>(std::move(func))); // 用make_unique创建unique_ptr
        }
        // ---------- 临界区结束 ----------

        cv_.notify_one(); // 唤醒一个等待的工作线程执行任务

        return res; // 返回future
    }

private:
    std::vector<std::thread> workers_;       // 工作线程列表
    std::queue<std::unique_ptr<std::function<void()>>> tasks_; // 任务队列（无参函数）
    std::mutex mtx_;                         // 保护任务队列和stop_flag的互斥锁
    std::condition_variable cv_;             // 线程同步的条件变量
    bool stop_flag_;                         // 线程池停止标志
};


// -------------------------- 测试代码 --------------------------
int main() {
    try {
        // 1. 创建线程池（4个工作线程）
        ThreadPool pool(4);
        std::cout << "线程池初始化完成（4个工作线程）\n" << std::endl;


        // 2. 提交不同类型的任务
        std::vector<std::future<int>> futures; // 存储任务的future

        // 提交5个任务（计算1~n的累加和）
        for (int i = 1; i <= 5; ++i) {
            futures.emplace_back(
                pool.submit(
                    [](int n) -> int {
                        // 模拟耗时操作（休眠100ms）
                        std::this_thread::sleep_for(std::chrono::milliseconds(100));
                        
                        int sum = 0;
                        for (int j = 1; j <= n; ++j) sum += j;
                        
                        // 打印任务执行线程ID和结果
                        std::cout << "线程ID: " << std::this_thread::get_id() 
                                  << " | 计算1~" << n << "的和: " << sum << std::endl;
                        
                        return sum;
                    }, 
                    i // 传递参数i
                )
            );
        }


        // 3. 获取所有任务的结果
        std::cout << "\n等待所有任务执行完成...\n" << std::endl;
        int total = 0;
        for (auto& fut : futures) {
            total += fut.get(); // get()会阻塞直到任务完成
        }
        std::cout << "\n所有任务执行完毕，结果总和: " << total << std::endl;


        // 4. 测试线程池停止后提交任务（会抛异常）
        // pool.submit([](){ return 1; }); // 取消注释会触发异常
    } 
    catch (const std::exception& e) {
        std::cerr << "异常：" << e.what() << std::endl;
    }

    return 0;
}
```

### `explicit` 签名

```cpp
explicit ThreadPool(size_t thread_num) 
    : stop_flag_(false) { // 初始时线程池未停止
```

- `explicit`：防止隐式类型转换（比如避免`ThreadPool pool = 5;`这种不直观的写法），强制显式构造`ThreadPool pool(5);`。

> `explicit` 是 C++ 中的**关键字**，仅用于修饰**单参数构造函数**（C++11 后也支持修饰多参数但带默认值的构造函数），核心作用是**禁止构造函数的隐式类型转换**，强制必须显式调用构造函数创建对象。
>
> ```cpp
> class ThreadPool {
> public:
>     // 加 explicit 禁止隐式转换
>     explicit ThreadPool(size_t thread_num) : stop_flag_(false) {}
> private:
>     bool stop_flag_;
> };
> 
> void func(ThreadPool pool) {}
> 
> int main() {
>     // 错误：无法将 int 隐式转换为 ThreadPool
>     // func(5); 
> 
>     // 正确：显式调用构造函数创建对象
>     func(ThreadPool(5)); 
>     // 或直接定义对象后传入
>     ThreadPool pool(5);
>     func(pool);
>     return 0;
> }
> ```
>
> | 场景           | 不加 `explicit`                  | 加 `explicit`                        |
> | -------------- | -------------------------------- | ------------------------------------ |
> | 单参数构造函数 | 允许隐式类型转换（如 `func(5)`） | 禁止隐式转换，必须显式构造           |
> | 代码可读性     | 低（易误读、易出错）             | 高（意图明确，强制显式调用）         |
> | 适用场景       | 简单值类型（如 `std::string`）   | 复杂对象（如线程池、容器、自定义类） |



### 已 join 的线程再次 join：必出问题

```cpp
if (worker.joinable()) { 
    worker.join(); // 只有可join时才执行join，避免非法调用
}
```

这是线程池析构 / 停止时的标准写法，目的是**安全等待所有工作线程退出**。

- **行为定义**：C++ 标准明确规定，对已 `join()` 或已 `detach()` 的线程调用 `join()`，属于**未定义行为**（UB）；
- **实际表现**：不同编译器 / 平台的报错形式不同，但核心是程序异常：
  - Linux/gcc：通常触发 `std::system_error` 异常（错误码 `resource_deadlock_would_occur` 或 `invalid_argument`），或直接段错误（SIGABRT）；
  - Windows/msvc：抛出 `std::invalid_argument` 异常，提示 “线程不可 join”。



### 任务入队：类型适配

```cpp
auto func = [task]() { (*task)(); }; // 先创建function对象
tasks_.emplace(std::make_unique<std::function<void()>>(std::move(func))); // 用make_unique创建unique_ptr
```

线程池的任务队列 `tasks_` 定义为 `std::queue<std::unique_ptr<std::function<void()>>>`，因此需要将包装后的任务转为该类型：

- `auto func = [task]() { (*task)(); }`：lambda 捕获 `shared_ptr` 类型的 `task`，调用 `(*task)()` 等价于执行包装的任务（触发 `packaged_task` 执行，结果存入 `future`）；
- `std::make_unique<std::function<void()>>(std::move(func))`：将 lambda 转为 `std::function<void()>`，并用 `std::unique_ptr` 包装（避免拷贝，符合队列类型要求）；
- `tasks_.emplace(...)`：直接在队列尾部构造对象，比 `push` 更高效（避免临时对象拷贝）。
