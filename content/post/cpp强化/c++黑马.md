##### 静态成员

静态成员就是在成员变量和成员函数前面加上关键字static，称为静态成员。

**静态成员分为**：

- 静态成员变量
  - 所有对象共享同一份数据
  - 在编译阶段分配内存
  - **类内声明，类外初始化**⚠️
- 静态成员函数
  - 所有成员共享同一个函数
  - 静态成员函数只能访问静态成员变量

```cpp
#include<iostream>
using namespace std;

class Person
{
private:
    // 私有静态成员变量
    static int private_age;
    // 私有静态成员函数
    static void private_func()
    {
        cout << "私有静态函数：private_func调用" << endl;
    }

public:
    // 公有成员函数（静态）：作为访问私有静态成员的接口
    static void access_private_static()
    {
        // 访问私有静态变量
        private_age = 200;
        cout << "通过公有接口访问私有静态变量：" << private_age << endl;
        
        // 调用私有静态函数
        private_func();
    }

    // 也可以用非静态公有成员函数访问 --》静态成员
    void access_private_static_nonstatic()
    {
        private_age = 300;
        cout << "非静态公有接口访问私有静态变量：" << private_age << endl;
        private_func();
    }
};

// 私有静态成员变量的类外定义（必须！即使是private也需要定义）
int Person::private_age = 0;

void test01()
{
    // 通过类名调用公有静态接口，间接访问私有静态成员
    Person::access_private_static();

    // 通过对象调用非静态公有接口，间接访问私有静态成员
    Person p;
    p.access_private_static_nonstatic();
}

int main(void)
{
    test01();
    system("pause");
    return 0;
}
/*
通过公有接口访问私有静态变量：200
私有静态函数：private_func调用
非静态公有接口访问私有静态变量：300
私有静态函数：private_func调用*/
```





#### C++对象模型和this指针⚡️⚡️

##### 成员变量和成员函数分开存储

在C++中，类内的成员变量和成员函数分开存储



**只有非静态成员变量才属于类的对象上。**

（只有非静态成员变量的大小算进类的大小中，其他的都不算。）

🌟 **只有非静态成员变量属于类的对象实例，其他成员（静态成员变量、非静态成员函数、静态成员函数）均独立于对象实例存储**。



**空对象的大小是1，为的是区分不同类在内存中的占用位置。**

> **解释**：
>
> 在 C++ 中，类的成员变量和成员函数**分开存储**是内存管理的重要特性，核心规则是：**只有非静态成员变量属于类的对象实例，其他成员（静态成员变量、非静态成员函数、静态成员函数）均独立于对象实例存储**。以下结合代码详细解释：
>
> ### 1. 非静态成员变量：属于对象实例
>
> 类中的**非静态成员变量**（如代码中的`m_A`）是每个对象实例独有的数据，会直接占用对象的内存空间。
>
> - 每个`Person`对象都有自己的`m_A`，因此对象的大小至少包含所有非静态成员变量的大小之和（可能因内存对齐略有增加）。
> - 代码中`Person`类包含一个`int`型`m_A`（占 4 字节），因此`test02()`中`sizeof(p)`的结果是**4**。
>
> ### 2. 静态成员变量：属于类，不属于对象
>
> 静态成员变量（如代码中的`m_B`）被所有类对象共享，存储在**全局 / 静态存储区**，而非某个对象的内存中。
>
> - 无论创建多少个`Person`对象，`m_B`只有一份拷贝，不占用对象的内存空间。
> - 因此`sizeof(p)`不会包含`m_B`的大小。
>
> ### 3. 成员函数（静态 / 非静态）：属于类，存储在代码区
>
> 成员函数（包括非静态的`func()`和静态的`func2()`）的代码是共享的，存储在**程序的代码段（代码区）**，而非对象内存中：
>
> - **非静态成员函数**：虽然通过对象调用（如`p.func()`），但函数本身不占用对象空间，只是编译器会隐式传递对象的`this`指针，让函数知道操作哪个对象的成员变量。
> - **静态成员函数**：不需要`this`指针，直接属于类，同样不占用对象空间。
>
> 因此，无论类中有多少成员函数，对象的大小都不会因此增加。
>
> ### 4. 空对象的内存占用
>
> 如果类中没有任何非静态成员变量（如`test01()`中若移除`m_A`），空对象的`sizeof`结果为**1**。
>
> 这是 C++ 编译器的特殊处理：为每个空对象分配 1 字节的 “占位符”，确保每个对象有唯一的内存地址，区分不同对象实例。
>
> ### 总结：对象大小的计算规则
>
> 类的对象大小 = **所有非静态成员变量的大小之和**（含内存对齐） +（空对象时的 1 字节占位符）。
>
> 静态成员变量、成员函数（静态 / 非静态）均不影响对象的大小，因为它们独立于对象存储。
>
> 代码中`test01()`若`Person`无`m_A`，`sizeof(p)`为 1；`test02()`因包含`int m_A`，`sizeof(p)`为 4，充分验证了这一规则。



> 补充：一个对象的内存空间中包含的内容主要取决于其所属类的定义，核心包含以下部分（以 C++ 为例）：
>
> ### 1. 非静态成员变量（属性）
>
> 对象的内存空间首先会存储类中定义的**所有非静态成员变量**（包括从父类继承的非静态成员变量，即使是父类的私有成员也会被包含）。
>
> - 普通成员变量（`int`/`float`/`指针`/`自定义类型`等）都会占据对象的内存。
> - 从父类继承的成员变量会按继承顺序排列在子类对象的内存中（可通过内存布局验证）。
>
> **示例**：
>
> ```cpp
> class A {
> private:
>     int a; // 私有成员，会被包含在子类对象内存中
> };
> class B : public A {
>     int b;
> };
> // B对象的内存包含A的a和B的b，大小通常为8字节（两个int）
> ```
>
> ### 2. 虚函数相关的额外空间（若类有虚函数）
>
> 如果类中定义了**虚函数**（或继承了虚函数），编译器会为对象添加一个**虚函数表指针（vptr）**，指向该类的虚函数表（vtable）。
>
> - 虚函数表指针通常占 4 字节（32 位系统）或 8 字节（64 位系统），属于对象内存的一部分。
> - 目的是实现多态（运行时动态绑定函数调用）。
>
> **示例**：
>
> ```cpp
> class C {
> public:
>     virtual void func() {} // 虚函数
> };
> // C对象的内存包含vptr（8字节，64位），大小为8字节
> ```
>
> ### 3. 成员变量的内存对齐（padding）
>
> 为了提高内存访问效率，编译器会对成员变量进行**内存对齐**，在成员变量之间或末尾填充空白字节。
>
> - 对齐规则通常遵循 “成员变量中最大基本类型的大小”（比如最大是`double`则按 8 字节对齐）。
> - 填充的空白字节也属于对象的内存空间，但不属于任何成员变量。
>
> **示例**：
>
> ```cpp
> class D {
>     char c; // 1字节
>     int i;  // 4字节
> };
> // D对象的内存大小不是5字节，而是8字节（char后填充3字节对齐）
> ```
>
> ### 4. 不包含在对象内存中的内容
>
> 以下内容**不属于单个对象的内存空间**，而是属于类的全局共享部分：
>
> - **静态成员变量**：所有对象共享，存储在全局 / 静态存储区，不占单个对象内存。
> - **成员函数（包括静态成员函数）**：函数代码存储在代码段，对象中仅保存调用地址（虚函数通过 vptr 间接调用），函数本身不占对象内存。
> - **类的访问权限标记（public/protected/private）**：仅编译器编译时检查，不占内存空间。
>
> ### 总结
>
> 对象的内存空间 = **非静态成员变量（含继承的）** + **虚函数表指针（若有虚函数）** + **内存对齐填充字节**。
>
> 简单来说：**对象的内存主要存储 “数据”（成员变量），而 “行为”（成员函数）是共享的代码，不占对象内存**。

**(谁调的，this就指向谁)**



this指针是隐含每个非静态成员函数内的一种指针。

##### 空指针返回成员函数

C++中空指针也是可以调用成员函数的，但是也要注意有没有用到this指针，如果用到this指针，需要加以判断来保证代码的健壮性。

> 解释：
>
> ### 空指针调用成员函数的原理与解析
>
> #### 1. 成员函数的本质
>
> C++ 中，类的**非静态成员函数**并不存储在对象中，而是存储在代码段（全局区）。每个对象仅包含成员变量，成员函数是所有对象共享的。调用成员函数时，编译器会隐式传递对象的地址作为 **`this`指针 **（成员函数的第一个参数）。
>
> 对于成员函数：
>
> ```cpp
> void Person::ShowClassName() { ... }
> ```
>
> 编译器实际处理为：
>
> ```cpp
> void ShowClassName(Person* const this) { ... }
> ```
>
> （Person* const this， 这是指针常量，右定向，可以改变指向的值，不能改变指向的对象） 
>
>  🔥更准确地说，this 是指向类对象的`const`指针
>
> #### 2. 空指针调用成员函数的可行性
>
> 当用空指针（`Person* p = NULL`）调用成员函数时：
>
> - 如果函数内部**未使用`this`指针**（如`ShowClassName()`）：
>
>     由于不需要访问对象的成员变量，仅执行函数逻辑，因此调用是合法的（编译器不会报错）。
>
> - 如果函数内部**使用了`this`指针**（如`ShowPersonAge()`中的`this->m_Age`）：
>
>   空指针的 this 指向无效内存，直接访问 this->m_Age ， 会导致内存访问错误（崩溃）。
>
>   #### 3. 代码中的处理逻辑
>
> ```cpp
>void ShowPersonAge()
> {
>    if (this == NULL)  // 检查this指针是否为空
>     {
>         return;       // 空指针则直接返回，避免后续非法访问
>     }
>     cout << this->m_Age << endl;
> }
> ```
> 
> 通过判断`this == NULL`，提前终止函数执行，避免对空指针的解引用操作，从而**保证代码健壮性**。
> 
> #### 4. 关键结论
>
> - **空指针可以调用成员函数**：因为成员函数不依赖对象存在，仅依赖`this`指针传递对象地址。
>- **必须检查`this`指针**：若成员函数中访问成员变量（隐含`this->`），需先判断`this`是否为空，否则会引发崩溃。
> - **静态成员函数例外**：静态成员函数没有`this`指针，空指针调用静态成员函数完全合法（但无实际意义）。
>
> #### 5. 底层视角
> 
> 空指针调用成员函数时，编译器仅传递`NULL`作为`this`参数，函数执行时若未使用`this`，则不会触发错误；若使用`this`访问成员，则等同于**`NULL->m_Age`**，触发段错误（操作系统终止进程）。🔥
>
> 综上，空指针调用成员函数的核心风险在于`this`指针的非法解引用，通过显式判断`this`是否为空可有效规避。

##### const修饰成员函数

**常函数**：

- 成员函数后加const后我们称这个函数为**常函数**
- 常函数不可以修改成员属性
- 成员属性声明时加关键字`mutable`后，在常函数中依然可以修改💦

**常对象**：

- 声明对象前const称该对象为常对象。
- 常对象只能调用常函数。

```cpp
#include<iostream>
using namespace std;
//常函数
class Person
{
public:
    //常函数必须初始化列表初始化所有成员变量，
    //通过显式定义构造函数并在初始化列表中初始化成员变量，即可解决 “常变量需要初始化” 的报错。
    Person() :m_a(0), x(100), m_b(0) {}

	//this指针的本质是指针常量，指针的指向是不可以修改的
	//就相当于Person *const this;
	//在成员函数后面加const修饰的是this指向，让指针指向的值也不可以修改
	void showPerson() const//加个const就不允许修改了
	{
		this->m_b = 100;
		//this = NULL;this指针是不可以修改指针的指向的
	}
	int m_a;
    const int x;
	mutable int m_b;//加了mutable修饰的特殊变量，即使在常函数,常对象中，也可以修改这个值🔥

	void func()
	{
		m_a = 100;//在普通成员函数中是可以修改的
	}
};
void test()
{
	Person P;
	P.showPerson();
}
//常对象
void test1()
{
	const Person p;//在对象前加const，变为常对象
	//p.m_a = 100;
	p.m_b = 100;
	//常对象只能调用常函数 
	p.showPerson();
	//p.func();常对象不能调用普通成员函数，因为普通成员函数可以修改属性。
	
}
int main(void)
{
	test();
	test1();
	return 0;
}
```

- 总结：
  - **const 成员函数**：通过修饰`this`指针，限制函数内对成员变量的修改（`mutable`除外），体现 “只读” 行为。
- **常对象**：限制对象本身的修改权限，仅能调用 const 成员函数，保证对象状态的不可变性（`mutable`除外）。

> ⚠️const 常量必须初始化，所以当类中成员变量有引用或者常量，必须建议用初始化列表

#### 友元

可客厅就是Public，你的卧室就是Private

客厅所有人都可以进去，但是你的卧室只有和你亲密的人可以进。

在程序中，有些私有属性也想让类外特殊的一些函数或者类进行访问，就需要用到友元技术。

友元的目的就是让一个函数或者类 访问另一个类中的私有元素。



**友元的关键字——friend**

友元的三种实现

- 全局函数做友元
- 类做友元
- 成员函数做友元

> 🔥 友元声明的作用是**告知编译器 “某个外部类 / 函数可以访问当前类的私有成员”**，它本质是一种 “权限声明”，而非类的成员声明（比如成员变量、成员函数）。因此，类的访问控制符（`public`/`private`/`protected`）对友元声明本身无效。



##### 全局函数做友元

**就是将此函数在类的最上面写一个声明，前面加一个friend。**（习惯上）

```cpp
friend void goodgay(Building* building);
```



##### 类做友元

**一个类在另一个中friend class xx**

```cpp
#include<iostream>
#include<string>
using namespace std;
//在前面先声明一下
class Building;

class GoodGay
{
public:
	GoodGay(); //构造函数
public:
	void visit();//参观函数 访问Building中的属性
private:
	Building* building; //指向Building的指针
};


class Building
{
	//GoodGay是Building类的好朋友，可以访问其私有属性
	friend class GoodGay; //🔥
public:
	Building();
public:
	string m_SittingRoom;
private:
	string m_BedRoom;
};

//在类外写成员函数
Building::Building()
{
	m_SittingRoom = "客厅";
	m_BedRoom = "卧室";
}

GoodGay::GoodGay() //构造函数
{
	//创建一个Building对象
	building = new Building; //在堆区创建Building对象，为什么不加（）？---因为C++14标准后可以省略
}

void GoodGay::visit()
{
	cout << "好基友正在访问你的" << building->m_SittingRoom << endl; //为什么不需要解引用？---因为是指针直接用->
	cout << "好基友正在访问你的" << building->m_BedRoom << endl;
}

void test()
{
	GoodGay gy;
	gy.visit();
}

int main(void)
{
	test();
	return 0;
}
```

##### 左移运算符重载

**作用**：可以输出自定义的类型

```cpp
#include<iostream>
using namespace std;

class Person
{
	friend ostream& operator<<(ostream& cout, Person& p);
public:
	Person(int a, int b): m_A(a), m_B(b){}
	//利用成员函数重载左移运算符p.operator<<(cout)，简化版本p<<cout， 为什么可以省略operator关键字？---因为成员函数调用时可以省略operator关键字
	//一般我们不会利用成员函数来重载<<运算符，因为无法实现cout在左边
	/*void operator<<(ostream &cout,Person &p)
	{
		cout << p.m_A << endl;
		cout << p.m_B << endl;
	}*/
private:
	int m_A;
	int m_B;
};

//只能利用全局函数来重载左移运算符
ostream& operator<<(ostream &cout, Person &p) //这样写的本质就是operator<<(cout,p)，简化版本就是cout<<p; 
{
	cout << p.m_A << endl;
	cout << p.m_B << endl;
	return cout;
}

void test()
{
	Person p(10,10);
	cout << p << "hello world" << endl; // 链式调用
}

int main(void)
{
	test();
	return 0;
}
```

> 解释**`ostream& operator<<(ostream &cout, Person &p)`**
>
> ### 1. 函数整体作用
>
> 这是对 **左移运算符 `<<`** 的全局重载，目的是让 `cout` 能够直接输出自定义的 `Person` 类对象（即支持 `cout << p` 语法）。
>
> ### 2. 逐部分解析
>
> #### （1）`ostream&`（返回值类型）
>
> - `ostream` 是 C++ 标准输出流的类型（`cout` 就是 `ostream` 类的对象）。
> - 返回 `ostream&`（输出流的引用）是为了支持**链式调用**（比如 `cout << p << "hello"`）。
>   - 如果不返回引用，`cout << p` 执行后无法继续拼接后续输出，因为返回值会是临时对象（或无返回值）。
>
> #### （2）`operator<<`（函数名）
>
> - C++ 中运算符重载的固定语法：用 `operator` 关键字 + 要重载的运算符（这里是 `<<`），表示这是对 `<<` 的重载函数。
>
> #### （3）`(ostream &cout, Person &p)`（函数参数）
>
> - **第一个参数 `ostream &cout`**：
>   - 接收输出流对象（如 `cout`）的引用，避免拷贝（`ostream` 对象不允许拷贝）。
>   - 注意：这里的参数名 `cout` 只是习惯命名，也可以写成 `os` 或其他名称（比如 `ostream &os`）。
> - **第二个参数 `Person &p`**：
>   - 接收要输出的 `Person` 类对象的引用，直接操作原对象，避免不必要的拷贝。
>   - 如果希望输出 `const` 对象（如 `const Person p`），可以写成 `const Person &p`（更严谨）。
>
> ### 3. 为什么需要全局重载（而非成员函数）
>
> - 如果用 `Person` 的**成员函数**重载 `<<`，成员函数的第一个参数会是隐含的 `this` 指针（指向 `Person` 对象），函数形式会变成：
>
>   ```cpp
>   void Person::operator<<(/* Person* const this ，*/ostream &cout) { ... } //（隐含this指针）
>   ```
>
>   此时调用语法会是
>
>   ```cpp
>   p << cout // 实际上完整是p.operator<<(cout) ，这是 C++ 运算符重载的语法糖设计
>   ```
>
>   （对象在左，cout在右），不符合我们习惯的cout << p 写法。
>
> - 因此必须用全局函数重载，让 `ostream` 对象作为第一个参数，才能实现 `cout << p` 的自然语法。
>
> ### 4. 友元的配合（类内声明）
>
> - 由于 `Person` 的成员变量 `m_A`、`m_B` 是 `private` 的，全局重载函数需要访问这些私有成员，因此需要在 `Person` 类内声明该函数为**友元**：
>
>   ```cpp
>   friend ostream& operator<<(ostream& cout, Person& p);
>   ```
>
> ### 5. 函数体的逻辑
>
> ```cpp
> cout << p.m_A << endl;
> cout << p.m_B << endl;
> return cout; // 返回输出流引用，支持链式调用
> ```
>
> - 自定义输出格式：这里输出 `Person` 对象的 `m_A` 和 `m_B` 成员，也可以根据需求改成其他格式（比如 `cout << "Person(" << p.m_A << "," << p.m_B << ")"`）。
> - `return cout`：返回传入的输出流引用，确保链式调用生效。
>
> ### 总结
>
> 这个函数的设计核心是：
>
> 通过全局重载左移运算符，让自定义类适配 C++ 标准输出流的语法，同时利用引用参数和返回值保证效率与链式调用的支持。



##### 递增运算符重载

**作用**：通过重载递增运算符，实现自己的整型数据

```cpp
#include<iostream>
using namespace std;

//重载递增运算符
class MyInteger
{
	friend ostream& operator<<(ostream& cout, MyInteger myint);
public:
	MyInteger(): m_Num(0) {}

	//重载++运算符——前置
	//返回引用是为了一直对一个数据进行递增操作
	MyInteger& operator++() //简化版本++myint，等价于myint.operator++()
	{
		++m_Num;
		return *this;
	}

	//重载++运算符——后置
    //简化版本myint++，等价于myint.operator++(int)
	MyInteger operator++(int)//这个int在这里作为占位参数，用来区分前置递增和后置递增
	{
		MyInteger temp = *this;
		m_Num++;
		return temp;
		//后置递增要返回值，因为如果返回引用，这里相当于返回的是一个局部对象的引用。
		//局部对象在当前函数执行完毕之后就被释放掉了，还要返回引用就是非法操作。
	}

private:
	int m_Num;
};


//全局函数重载左移运算符
ostream& operator<<(ostream& cout, MyInteger myint)
{
	cout << myint.m_Num << endl;
	return cout;
 }

 
void test()
{
	MyInteger myint;
	cout << ++(++myint);//前置递增，连续两次递增
	cout << myint;
}

void test02()
{
	MyInteger myint;
	cout << myint++ << endl;//后置递增，先返回后递增
	cout << myint << endl;
}

int main(void)
{
	//test();
	test02();
    return 0;
}
```

**总结**:前置递增返回引用，后置递增返回值。



##### 赋值运算符重载 🔥

C++编译器至少给一个类添加4个函数(前三个之前已经讲过了)

1. 默认构造函数(无参，函数体为空)
2. 默认析构函数(无参，函数体为空)
3. 默认拷贝构造函数，对属性进行值拷贝
4. 赋值运算符operator=，对属性进行值拷贝

如果类中有属性指向堆区，做赋值操作时也会出现深浅拷贝问题。

```cpp
#include <iostream>
using namespace std;

class Person {
public:
    // 将age改为指针类型，才能实现深拷贝
    int* age;

    // 构造函数
    Person(int a) : age(new int(a)) {} 
    
    // 拷贝构造函数（深拷贝）
    Person(const Person& p) {
        // 判断指针是否为空，然后进行深拷贝
        if (p.age != nullptr) {
            age = new int(*(p.age));
        } else {
            age = nullptr;
        }
    }

    // 析构函数
    ~Person() {
        // 释放动态分配的内存
        if (age != nullptr) {
            delete age;
            age = nullptr;
        }
    }

    // 重载赋值运算符（深拷贝）
    Person& operator=(const Person& p) {
        // 防止自赋值
        if (this == &p) {
            return *this;
        }

        // 先释放当前对象的内存
        delete age;

        // 深拷贝
        age = new int(*(p.age));
        
        return *this;
    }

    // 打印年龄的方法
    void printAge() const {
        cout << "Age: " << *age << endl;
    }
};

// 测试代码
int main() {
    Person p1(20);
    p1.printAge();

    Person p2 = p1;  // 调用拷贝构造函数
    p2.printAge();

    Person p3(30);
    p3 = p1;         // 调用赋值运算符
    p3.printAge();

    return 0;
}
```



##### 关系运算符重载

**作用**：重载关系运算符，可以让两个自定义类型对象进行对比操作

```cpp
#include <iostream>
#include <string>
using namespace std;

class Person{
public:
    string name;
    int age;

    Person(string name, int age):name(name), age(age){} 

    bool operator==(const Person &p){
        return this->name == p.name && this->age == p.age;
    }

    bool operator!=(const Person &p) const{
        // if(this == &p)  return false; -- 这是判断地址是否相等，但是应该判断内容是否相等
        if(*this != p)  return true; 
        return false;
        // 或者直接 return !(*this == p);
    }

    bool operator<(const Person &p) const{
        if(this->age < p.age) return true;
        else if(this->age == p.age && this->name < p.name) return true;
        else return false;
    }
};
```



##### 函数调用运算符重载🔥

- 函数调用运算符`()`也可以重载

- 仿函数没有固定写法，非常灵活

```cpp

#include<string>

//函数调用运算符重载
class MyPrint

		cout << text << endl;
	}

	}

void test()
{
	MyPrint myprint; //创建函数对象,完整写法MyPrint myprint = MyPrint();是栈上创建对象的简写，等价于显式调用默认构造函数 MyPrint()。
	myprint("hello world"); //函数对象的使用方式和普通函数一样
	MyAdd myadd;
	cout << myadd(1, 2) << endl; //函数对象可以有返回值
	//匿名函数对象——特点:当前行被执行完立即释放
```

> 补充：**仿函数**🔥🔥
>
> 在 C++ 中，**仿函数（Functor）** 是指重载了**函数调用运算符 `()`** 的类（或结构体）的对象。由于其使用方式与普通函数类似，因此被称为 “仿函数”（也叫函数对象）。
>
> ### 一、仿函数的本质
>
> 仿函数的核心是通过重载 `operator()`，让类的对象可以像函数一样被调用。本质上，它是一个 “行为类似函数的对象”，但相比普通函数，仿函数可以**保存状态**（通过类的成员变量），且支持更灵活的定制。
>
> ### 二、仿函数的定义与使用
>
> #### 1. 基本定义
>
> 只需在类中重载 `operator()` 即可：
>
> ```cpp
> class MyAdd {
> public:
>     // 重载函数调用运算符
>     int operator()(int a, int b) {
>         return a + b;
>     }
> };
> ```
>
> #### 2. 使用方式
>
> 创建类的对象后，以 “函数调用” 的语法使用：
>
> ```cpp
> MyAdd add; // 创建仿函数对象  ---> MyAdd add = MyAdd(), 调用默认为构造函数，临时对象，再拷贝
> // 🔥但在实际编译中（尤其是 C++17 及以后），编译器会触发返回值优化（Return Value Optimization, RVO）（或更具体的命名返回值优化 NRVO）
> //直接省略临时对象的创建和拷贝：
> int result = add(1, 2); // 等价于 add.operator()(1, 2)，结果为3
> ```
>
> #### 3. 匿名仿函数对象
>
> 可直接创建匿名对象并调用，更简洁：
>
> ```cpp
> int result = MyAdd()(1, 2); // 匿名对象调用operator()
> ```
>
> ### 三、仿函数的核心优势
>
> #### 1. 可以保存状态（成员变量）
>
> 普通函数无法在调用间保存状态，但仿函数可以通过成员变量记录信息：
>
> ```cpp
> class Counter {
> private:
>     int count = 0; // 保存计数状态
> public:
>     int operator()() {
>         return ++count; // 每次调用计数+1
>     }
> };
> 
> Counter c;
> cout << c() << endl; // 输出1
> cout << c() << endl; // 输出2（状态被保存）
> ```
>
> #### 2. 可定制化（通过构造函数初始化）
>
> 可通过构造函数传递参数，定制仿函数的行为：
>
> ```cpp
> class Multiply {
> private:
>     int factor; // 乘数因子
> public:
>     Multiply(int f) : factor(f) {} // 构造函数初始化因子
>     int operator()(int x) {
>         return x * factor; // 用因子计算
>     }
> };
> 
> Multiply by2(2);   // 定制“乘以2”的仿函数
> Multiply by3(3);   // 定制“乘以3”的仿函数
> cout << by2(5) << endl; // 输出10
> cout << by3(5) << endl; // 输出15
> ```
>
> #### 3. 适配 STL 算法
>
> 仿函数是 STL 算法的重要组成部分，可作为算法的参数定制逻辑：
>
> ```cpp
> #include <vector>
> #include <algorithm>
> 
> class IsEven {
> public:
>     bool operator()(int x) {
>         return x % 2 == 0; // 判断偶数
>     }
> };
> 
> int main() {
>     vector<int> v = {1,2,3,4,5};
>     // 用仿函数查找第一个偶数
>     auto it = find_if(v.begin(), v.end(), IsEven());
>     cout << *it << endl; // 输出2
>     return 0;
> }
> ```
>
> ### 四、仿函数与普通函数 / 函数指针的区别
>
> | 特性       | 仿函数                   | 普通函数 / 函数指针    |
> | ---------- | ------------------------ | ---------------------- |
> | 状态保存   | 支持（成员变量）         | 不支持                 |
> | 定制化     | 高（构造函数传参）       | 低（参数固定）         |
> | 类型信息   | 有明确类型（类名）       | 无类型（仅函数签名）   |
> | STL 适配性 | 更友好（可作为模板参数） | 需包装（如`function`） |
>
> ### 五、现代 C++ 中的仿函数替代？
>
> C++11 引入的**Lambda 表达式**可以简化仿函数的编写（本质上 Lambda 也是仿函数的语法糖）：
>
> ```cpp
> // 用Lambda替代IsEven仿函数
> auto isEven = [](int x) { return x % 2 == 0; };
> auto it = find_if(v.begin(), v.end(), isEven);
> ```
>
> 但仿函数在需要复用、复杂状态管理的场景中仍不可替代。
>
> ### 总结
>
> 仿函数是 C++ 中 “用对象模拟函数行为” 的设计模式，核心是重载 `operator()`。它兼具**函数的调用语法**和**对象的状态管理能力**，是 STL 算法的基石之一，也是 C++ 泛型编程的重要工具。

##### 继承方式⚡️

```cpp
继承的语法——class 子类 :继承方式 父类
```



**继承方式一共有三种**：

- 公共继承
- 保护继承
- 私有继承

```cpp
#include<iostream>
using namespace std;

// 基类定义
class Base {
public:
    int pub;
protected:
    int pro;
private:
    int pri;
};

// 1. 公共继承
class PubSon : public Base {
public:
    void func() {
        pub = 10;  // 父类public -> 子类public
        pro = 20;  // 父类protected -> 子类protected
        // pri = 30; // 父类private -> 子类不可访问
    }
};

// 2. 保护继承
class ProSon : protected Base {
public:
    void func() {
        pub = 10;  // 父类public -> 子类protected
        pro = 20;  // 父类protected -> 子类protected
        // pri = 30; // 父类private -> 子类不可访问
    }
};

// 3. 私有继承
class PriSon : private Base {
public:
    void func() {
        pub = 10;  // 父类public -> 子类private
        pro = 20;  // 父类protected -> 子类private
        // pri = 30; // 父类private -> 子类不可访问
    }
};

// 验证私有继承的传递性
class GrandSon : public PriSon {
public:
    void func() {
        // pub/pro/pri 均不可访问（已成为PriSon的私有成员）
    }
};

// 权限总结
void summary() {
    cout << "继承方式权限总结：\n";
    cout << "1. 公共继承：\n";
    cout << "   父类public -> 子类public\n";
    cout << "   父类protected -> 子类protected\n";
    cout << "   父类private -> 子类不可访问\n\n";
    
    cout << "2. 保护继承：\n";
    cout << "   父类public -> 子类protected\n";
    cout << "   父类protected -> 子类protected\n";
    cout << "   父类private -> 子类不可访问\n\n";
    
    cout << "3. 私有继承：\n";
    cout << "   父类public -> 子类private\n";
    cout << "   父类protected -> 子类private\n";
    cout << "   父类private -> 子类不可访问\n";
}

int main() {
    summary();
    return 0;
}
```

> ### 三种继承方式的权限规则提炼：
>
> 1. **公共继承（public）**
>    - 父类`public`成员 → 子类`public`
>    - 父类`protected`成员 → 子类`protected`
>    - 父类`private`成员 → 子类不可访问
> 2. **保护继承（protected）**     🌞 即父类和其子孙类可以访问
>    - 父类`public`成员 → 子类`protected`
>    - 父类`protected`成员 → 子类`protected`
>    - 父类`private`成员 → 子类不可访问
> 3. **私有继承（private）**
>    - 父类`public`成员 → 子类`private`
>    - 父类`protected`成员 → 子类`private`
>    - 父类`private`成员 → 子类不可访问
>
> ### 核心要点：
>
> - 父类的`private`成员始终无法被子类直接访问（需通过父类接口）
> - 私有继承会将父类的非私有成员变为子类私有，无法再向下传递
> - 保护继承限制了父类 public 成员的外部访问，但允许子类内部和派生类访问
>   - （**保护继承会把父类的 `public` 成员降级为子类的 `protected` 成员**，导致这些成员在子类外部无法直接访问，但在子类内部以及子类的派生类（孙子类）中仍然可以访问。）
>
> | 修饰符      | 本类内部 | 同一包中其他类 | 不同包的子类 | 不同包的非子类 |
> | ----------- | -------- | :------------- | ------------ | -------------- |
> | `public`    | ✅        | ✅              | ✅            | ✅              |
> | `protected` | ✅        | ✅              | ✅            | ❌              |
> | `default`   | ✅        | ✅              | ❌            | ❌              |
> | `private`   | ✅        | ❌              | ❌            | ❌              |
>

##### 继承中的对象模型

**问题**：从父类继承过来的对象，哪些属于子类对象？（看前面`成员变量和成员函数分开存储`部分）



父类中所有的非静态成员属性都会被子类继承下去。

// 更正：  父类的所有非静态成员属性（指父类中属于实例的、非静态的字段 / 变量**）都会被子类继承（内存层面），但子类不一定能直接访问（语法层面）**

**父类中私有的成员属性是被编译器给隐藏了，因此访问不到，但是确实被继承下去了**

> 这句话的核心是：**子类会继承父类的所有非静态成员（包括私有成员），但父类私有成员会被编译器隐藏，子类无法直接访问**。下面从 “继承” 和 “访问权限” 两个层面详细解释：
>
> ### 1. 子类确实继承了父类的私有成员
>
> 从内存布局的角度来看，子类对象的内存空间中**包含了父类的所有成员**（包括私有成员）。父类的私有成员只是被编译器限制了访问，并非不存在于子类对象中。
>
> ### 2. 私有成员被编译器 “隐藏”，无法直接访问
>
> 父类的`private`成员被编译器标记为**仅父类内部可访问**，子类（即使是公有继承）也不能直接读写这些成员。但可以通过父类提供的`public/protected`接口间接访问。

##### 继承中构造和析构的顺序

**子类继承父类后，当创建子类时，也会调用父类的构造函数。**

问题：父类和子类的构造函数和析构顺序怎么样的呢？

**先构造父类，再构造子类**

**先析构子类，再析构父类**

**创建子类对象的同时也会创建一个父类对象**。

**总结**：继承中先调用父类构造函数，再调用子类构造函数，析构顺序与构造相反。

##### 菱形继承

**菱形继承概念**：

两个派生类继承同一个基类，又有某个类同时继承这两个派生类，这种继承称为菱形继承，或者钻石继承。



**菱形继承问题**：

1. 羊继承了动物的数据，驼同样继承了动物的数据，当草泥马使用数据时，就会产生二义性。
2. 草泥马继承动物的数据继承了两份，其实我们应该清楚，这份数据我们只需要一份就可以。



vbptr——虚基类

继承了两个指针，两个指针通过偏移量找到了唯一的数据。

```cpp
/*
虚继承解决棱形继承问题*/
#include<iostream>
using namespace std;

// 虚基类
class Animal {
public:
    int m_Age;
};

// 虚继承
class Sheep : virtual public Animal {};
class Tuo : virtual public Animal {};

// 菱形继承的最终子类
class SheepTuo : public Sheep, public Tuo {};

void test() {
    SheepTuo st;
    st.Sheep::m_Age = 18;
    st.Tuo::m_Age = 28;
    
    cout << st.Sheep::m_Age << endl; // 28（共享同一份数据）
    cout << st.Tuo::m_Age << endl;   // 28
    cout << st.m_Age << endl;        // 28
}

int main() {
    test();
    return 0;
}
```

> 虚继承通过**虚基类指针（vbptr）** 和**虚基类表（vbtable）** 实现：
>
> 1. 当 Sheep 和 Tuo **虚继承** Animal 时，这两个类的对象中会生成一个**虚基类指针（vbptr）**，指向各自的虚基类表；
> 2. 虚基类表中存储的是当前类对象到虚基类（Animal）成员的**偏移量**，确保无论通过哪个中间子类访问，最终都指向同一份 Animal 成员数据；
> 3. 最终子类 SheepTuo 中仅保留一份 Animal 的 m_Age，避免了菱形继承的数据冗余和二义性。
>
> 简单来说：虚继承让菱形继承中的 “公共祖先类” 只被继承一次，所有子类共享其成员，从而解决了数据重复和访问歧义问题。

> 虚继承会让`Sheep`和`Tuo`共享同一份`Animal`的`m_Age`，因此它们无法拥有各自独立的`age`。
>
> * SheepTuo 能不能再虚继承Sheep 和 Tuo
>
>   - **语法合法**：`SheepTuo`可以虚继承`Sheep`和`Tuo`；
>
>   - **效果有限**：若`Sheep`/`Tuo`无额外成员，这种设计无实际作用，只是冗余；
>
>   - **核心逻辑不变**：对`Animal`的共享由`Sheep`/`Tuo`的虚继承保证，与`SheepTuo`是否虚继承它们无关。

**总结**：

1. 菱形继承带来的主要问题是子类继承两份相同的数据，导致资源浪费以及毫无意义。
2. 利用虚继承可以解决菱形继承问题——**virtual**

#### 多态

**多态是C++面向对象三大特性之一**



##### 多态度的基本概念🔥

多态分为两种

- **静态多态:**  函数重载  和  运算符重载  属于静态多态，复用函数名  ----> 主要是重载函数，对函数名称的复用，根据参数确定调用
- **动态多态**:  派生类  和  虚函数  实现运行时多态

###### 静态多态和动态多态的区别

- 静态多态的函数地址早绑定 - 编译阶段确定函数地址
- 动态多态的函数地址晚绑定 - 运行阶段确定函数地址

> ### 一、静态多态（编译时多态）
>
> 静态多态是在**编译阶段**就确定函数调用地址的多态性，主要通过**函数重载**和**运算符重载**实现：
>
> #### 1. 函数重载
>
> 同一作用域内，函数名相同但参数列表（个数、类型、顺序）不同，编译器会根据调用时的实参匹配对应的函数：
>
> ```cpp
> #include <iostream>
> using namespace std;
> 
> void print(int a) {
>  cout << "整数：" << a << endl;
> }
> 
> void print(double a) {
>  cout << "浮点数：" << a << endl;
> }
> 
> int main() {
>  print(10);    // 编译时匹配print(int)
>  print(3.14);  // 编译时匹配print(double)
>  return 0;
> }
> ```
>
> 编译器在编译阶段就确定了调用哪个`print`函数，属于**地址早绑定**。
>
> #### 2. 运算符重载
>
> 对运算符赋予新的含义（如`+`用于自定义类型相加），编译时根据操作数类型确定调用的重载函数，本质也是静态多态。
>
> ### 二、动态多态（运行时多态）
>
> 动态多态是在**运行阶段**才确定函数调用地址的多态性，依赖**继承**和**虚函数**实现，满足以下条件：🔥🔥
>
> ```cpp
> //1. 子类继承父类；
> //2. 子类 重写（覆盖）父类的 虚函数（函数名、返回值、参数列表完全一致）；重写的意思就是除了函数体其他都一样
> //3. 通过 父类指针或引用 指向子类对象，调用虚函数。🌟
> ```
>
> 
>
> #### 你的代码分析：
>
> ```cpp
> // 父类虚函数
> virtual void speak() { cout << "动物在说话" << endl; }
> 
> // 子类重写虚函数
> void speak() { cout << "小猫在说话" << endl; } // Cat类
> void speak() { cout << "小狗在说话" << endl; } // Dog类
> 
> // 父类引用接收子类对象
> void doSpeak(Animal &animal) { animal.speak(); }
> ```
>
> - 当调用`doSpeak(cat)`时，`animal`是`Animal&`类型，但实际指向`Cat`对象；// Animal & animal = cat
> - 由于`speak()`是虚函数，**运行时**才根据对象实际类型（`Cat`/`Dog`）确定调用的函数，属于**地址晚绑定**。
>
> ### 静态多态 vs 动态多态
>
> | 特性     | 静态多态               | 动态多态                           |
> | -------- | ---------------------- | ---------------------------------- |
> | 确定时机 | 编译阶段（早绑定）     | 运行阶段（晚绑定）                 |
> | 实现方式 | 函数重载、运算符重载   | 继承 + 虚函数                      |
> | 灵活性   | 较低（编译时固定）     | 较高（运行时动态匹配）             |
> | 底层原理 | 编译器根据实参匹配函数 | 虚函数表（vtable）+ 虚指针（vptr） |



###### 动态多态的实现

```cpp
class Animal
{
public:         //🍉如果是虚函数，那么类里面存了一个虚函数表指针，类占4个字节，指向虚函数表，表中存放虚函数的地址🔥
    virtual void speak()  //如果是非静态成员函数void speak()，那么函数不在类上，空类占1个字节空间                    
    {
        cout << "动物在说话" << endl;
    }
};

class Cat:public Animal // 动态多态需要继承
{
public:
    void speak()   // 🍎动态多态必须对父类的虚函数进行重写 
    {
        cout << "小猫在说话" << endl;
    }
};

class Dog:public Animal
{
public:
    virtual void speak() //子类virtual可写可不写，也可以写 virtual void speak()，包括上面那个
    {
        cout << "小狗在说话" << endl;
    }
};

void doSpeak(Animal &animal)  // Animal & animal = cat //🍑动态多态必须有，父类指针或引用 指向子类对象，调用虚函数
{
    animal.speak();
}

void test01()
{
    Cat cat;
    doSpeak(cat);

    Dog dog;
    doSpeak(dog);
}
```

**总结**：

动态多态满足条件

- 有继承关关系
- 子类重写父类中的虚函数

动态多态的使用条件

* 父类指针或引用指向子类对象

重写:函数返回值类型 函数名 参数列表 完全一致称为重写



多态带来的好处

1. 组织结构清晰，哪出错了马上定位到。
2. 可读性强
3. 对于前期和后期扩展以及维护性高

**总结**：C++开发提倡利用多态设计程序框架，因为多态优点很多。

###### 多态原理🔥

> C++ 多态（尤其是动态多态）的实现依赖 ** 虚函数表（vtable）**和**虚指针（vptr）** 机制，这是编译器在底层自动完成的，具体原理可以分为以下几个层面：
>
> ### 一、虚函数表（vtable）与虚指针（vptr）
>
> 当类中声明了**虚函数**（或继承了虚函数），编译器会为该类做两件事：
>
> 1. **生成虚函数表（vtable）**：
>    - 这是一个全局的、只读的数组，存储该类所有虚函数的**地址**；
>    - 如果子类重写了父类的虚函数，子类的虚函数表中会用子类的函数地址覆盖父类对应位置的地址；
>    - 如果子类新增了虚函数，会追加到虚函数表的末尾。
> 2. **生成虚指针（vptr）**：
>    - 编译器会在该类的每个对象中隐含添加一个`vptr`成员（通常是对象的第一个成员）；
>    - `vptr`指向当前对象所属类的**虚函数表（vtable）**。
>
> ### 二、动态多态的执行流程（以你的代码为例）
>
> ```cpp
> class Animal {
> public:
>     virtual void speak() { ... } // 虚函数
> };
> class Cat : public Animal {
> public:
>     void speak() override { ... } // 重写虚函数
> };
> 
> // 使用时：
> Animal* ptr = new Cat();
> ptr->speak(); // 调用Cat::speak()
> ```
>
> 执行`ptr->speak()`的底层步骤：
>
> 1. **通过对象的 vptr 找到 vtable**：
>
>    `ptr`是`Animal*`类型，但实际指向`Cat`对象，`ptr`访问对象的`vptr`，找到`Cat`类的虚函数表。
>
> 2. **在 vtable 中查找虚函数地址**：
>
>    `speak()`是第一个虚函数，直接取 vtable 中第一个位置的函数地址（此时是`Cat::speak()`的地址）。
>
> 3. **调用函数**：
>
>    根据找到的地址，执行`Cat::speak()`。
>
> ### 三、父类指针 / 引用指向子类对象的原理
>
> 动态多态的核心是 “父类指针 / 引用指向子类对象，调用虚函数时执行子类的实现”，底层原因是：
>
> - 父类和子类都有`vptr`，但`vptr`指向的是各自类的`vtable`；
> - 当父类指针指向子类对象时，指针访问的是**子类对象的 vptr**，因此会找到子类的`vtable`，最终调用子类的虚函数。
>
> ### 四、具体示例拆解（结合你的代码）
>
> #### 1. Animal 类的 vtable 和对象布局
>
> ```cpp
> class Animal {
> public:
>     virtual void speak() { ... }
> };
> ```
>
> - 编译器为`Animal`生成**vtable**：`[&Animal::speak]`；
> - `Animal`对象的布局：`[vptr]`（指向 Animal 的 vtable）。
>
> #### 2. Cat 类的 vtable 和对象布局
>
> ```cpp
> class Cat : public Animal {
> public:
>     void speak() override { ... } // 重写父类虚函数
> };
> ```
>
> - 编译器为`Cat`生成**vtable**：`[&Cat::speak]`（覆盖父类的`speak`地址）；
> - `Cat`对象的布局：`[vptr]`（指向 Cat 的 vtable） + 其他成员（如果有）。
>
> #### 3. 调用过程
>
> ```cpp
> Animal& animal = Cat();
> animal.speak(); // 调用Cat::speak()
> ```
>
> - `animal`是`Animal&`，但实际绑定的是`Cat`对象；
> - 访问`animal`的`vptr`，找到`Cat`的 vtable；
> - 从 vtable 中取出第一个函数地址（`&Cat::speak`），执行该函数。
>
> ### 五、关键细节补充
>
> 1. **虚函数表的继承性**：
>
>    子类会继承父类的 vtable 结构，如果子类不重写虚函数，vtable 中会保留父类的虚函数地址；如果重写，则覆盖。
>
> 2. **多继承的 vtable**：
>
>    如果子类继承多个含虚函数的父类，会有多个`vptr`（每个父类对应一个），每个`vptr`指向对应父类分支的 vtable。
>
> 3. **虚析构函数的必要性**：
>
>    如果父类析构函数不是虚函数，用父类指针 delete 子类对象时，只会调用父类析构函数（内存泄漏）；
>
>    若析构函数是虚函数，子类 vtable 会覆盖析构函数地址，delete 时会通过 vtable 调用子类析构函数（再自动调用父类析构）。
>
> ### 总结
>
> 多态的本质是：**通过对象的虚指针找到所属类的虚函数表，再根据虚函数表中的地址动态调用函数**。
>
> 编译器通过 vtable 和 vptr，让 “父类指针 / 引用调用子类函数” 成为可能，这也是动态多态 “晚绑定” 的底层实现。

##### 纯虚函数和抽象类

在多态中，通常父类中虚函数的实现是毫无意义的，主要都是调用子类重写的内容。

因此可以将虚函数改为纯虚函数。

语法：

```cpp
纯虚函数语法virtual 返回值类型 函数名 (参数列表) = 0; // = 0
virtual void fun() = 0; 
```

当类中有了纯虚函数（或者有纯虚析构函数），这个类也称为抽象类。

**抽象类特点**:

- 无法实例化对象
- 子类必须重写抽象类中的纯虚函数，否则也属于抽象类

```cpp
//纯虚函数和抽象类
class Base
{
public:
	//只要有一个纯虚函数,这个类称为抽象类
	//特点;无法实例化对象
	virtual void func() = 0;//注意:不要忘掉virtual!
	//抽象类的子类必须要重写父类中的纯虚函数，否则也属于抽象类
};

class Son :public Base
{
public:
	void func()
	{
		cout << "func函数调用" << endl;
	}
};

void test()
{
	// Base b1; //抽象类无法实例化对象
	Son s1;//子类重写父类的虚函数，否则无法实例化对象, Son s1 = new Son();
	Base* abc = new Son;
	abc->func();
}
```

> ### `// Base b1; //抽象类无法实例化对象`
>
> - 这行被注释的代码展示了**抽象类的核心特性**：包含纯虚函数的抽象类（如`Base`）不能直接创建对象
> - 原因：抽象类是为了被继承而设计的，本身不完整（有未实现的纯虚函数）
>
> ### `Base* abc = new Son;`
>
> - **多态的体现**：用基类指针指向子类对象
> - 虽然`Base`是抽象类不能实例化，但可以定义**基类指针 / 引用**来指向子类对象（这是多态的关键用法）

纯虚函数和抽象类的设计目的：**强制子类实现接口，并支持多态调用**

| 函数类型   | 是否必须实现？                     | 用途                       |
| ---------- | ---------------------------------- | -------------------------- |
| 纯虚函数   | 基类不需要（可以没必要），子类必须 | 定义接口，强制子类实现     |
| 普通虚函数 | 基类建议实现（否则可能链接错误）   | 提供默认行为，子类可选重写 |

##### 虚析构和纯虚析构

多态使用的时候，如果子类中有属性开辟到堆区，那么父类指针在释放时无法调用到子类的析构代码

**解决方法**:将父类中的析构函数改为虚析构或者纯虚析构

虚析构和纯析构共性:

- 可以解决父类指针释放子类对象，
- 都需要有具体的含函数实现

> 🔥在 C++ 中，**虚析构函数的核心作用是解决多态场景下子类对象的正确销毁问题**。如果没有虚析构函数，通过基类指针删除子类对象时会导致**析构不完整**，进而引发内存泄漏或资源释放错误。
>
> C++ 中，析构函数默认**不具备多态性**。如果基类析构函数不是`virtual`，那么：
>
> - 通过**基类指针 / 引用**删除子类对象时，编译器只会调用**基类的析构函数**，而不会调用子类的析构函数；
> - 若子类持有动态资源（如`new`分配的内存、文件句柄等），这些资源将无法被释放，导致内存泄漏或资源泄露。

虚析构和纯虚构的区别：

- 如果是**纯虚析构**，该类属于抽象类，无法实例化对象

> 在 C++ 中，虚析构函数和纯虚析构函数是实现多态时管理对象生命周期的关键语法，下面分别详细解释：
>
> ### 一、虚析构函数（Virtual Destructor）
>
> #### 1. 语法格式
>
> ```cpp
> class 类名 {
> public:
>  virtual ~类名() {  // 虚析构函数声明（virtual关键字+析构函数）
>      // 析构逻辑（可空）
>  }
> };
> 
> // virtual ~类名() = default; // 虚析构函数（C++11起可用default，也可写{}）✅
> ```
>
> #### 2. 核心作用
>
> 当通过**基类指针 / 引用删除子类对象**时，确保**子类析构函数被调用**（而非仅调用基类析构函数），避免内存泄漏或资源释放不完整。
>
> #### 3. 示例说明
>
> ```cpp
> class Base {
> public:
>  virtual ~Base() {  // 虚析构函数
>      cout << "Base析构" << endl;
>  }
> };
> 
> class Derived : public Base {
> public:
>  ~Derived() override {  // 子类析构（override可选，增强可读性）
>      cout << "Derived析构" << endl;
>  }
> };
> 
> // 使用场景：基类指针指向子类对象
> Base* ptr = new Derived();
> delete ptr;  // 会先调用Derived析构，再调用Base析构
> ```
>
> **输出**：
>
> ```plaintext
> Derived析构
> Base析构
> ```
>
> ### 二、纯虚析构函数（Pure Virtual Destructor）
>
> #### 1. 语法格式
>
> ```cpp
> class 类名 {
> public:
>  virtual ~类名() = 0;  // 纯虚析构函数声明（=0标记）
> };
> 
> // 注意：纯虚析构函数必须提供实现（类外定义）！
> 类名::~类名() {
>  // 析构逻辑（可空）
> }
> ```
>
> #### 2. 核心特点
>
> - 包含纯虚析构函数的类会成为**抽象类**（无法实例化）；
> - 强制子类必须重写析构函数（或继承实现）；
> - 必须提供类外实现（因为销毁对象时，纯虚析构函数也需要被调用）。
>
> #### 3. 示例说明
>
> ```cpp
> class AbstractBase {
> public:
>     virtual ~AbstractBase() = 0;  // 纯虚析构函数
> };
> 
> // 纯虚析构函数的类外实现（必须！）
> AbstractBase::~AbstractBase() {
>     cout << "AbstractBase纯虚析构实现" << endl;
> }
> 
> class Concrete : public AbstractBase {
> public:
>     ~Concrete() override {  // 子类析构
>         cout << "Concrete析构" << endl;
>     }
> };
> 
> // 使用场景：基类指针指向子类对象
> AbstractBase* ptr = new Concrete();
> delete ptr;  // 调用Concrete析构 → 调用AbstractBase纯虚析构实现
> ```
>
> **输出**：
>
> ```plaintext
> Concrete析构
> AbstractBase纯虚析构实现
> ```
>
> ### 三、关键区别与注意事项
>
> | 特性             | 虚析构函数           | 纯虚析构函数                             |
> | ---------------- | -------------------- | ---------------------------------------- |
> | 类是否为抽象类   | 否（可实例化）       | 是（不可实例化）                         |
> | 是否需要实现     | 可在类内直接实现     | 必须在类外提供实现 🔥                     |
> | 子类是否必须重写 | 否（可继承基类实现） | 否（但子类若要实例化，需保证析构链完整） |
>
> #### 重要注意点：
>
> - 纯虚析构函数**必须提供实现**：因为对象销毁时，析构函数会沿继承链向上调用，即使是纯虚析构也需要执行体；
> - 抽象类中若没有其他纯虚函数，可通过纯虚析构函数将类设为抽象类（强制子类继承并实现析构逻辑）；
> - 只要类作为多态基类（用于基类指针指向子类对象），就必须声明虚析构或纯虚析构。

2. 如果子类中没有堆区数据，可以不写为虚析构或纯虚析构
3. 拥有纯虚析构函数的类也属于抽象类
