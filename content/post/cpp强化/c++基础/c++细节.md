### 一、`goto` 的基本语法

不同语言的语法略有差异，但核心逻辑一致：

1. 定义一个**标签**（Label）：用标识符加冒号（如 `label:`）标记目标位置；
2. 使用 `goto` + 标签名：跳转到该标签处执行

```c
#include <stdio.h>
int main() {
    int i = 0;

loop_start:  // 定义标签
    i++;
    printf("i = %d\n", i);
    if (i < 3) {
        goto loop_start;  // 跳转到loop_start标签
    }

    return 0;
}
```

输出

```c
i = 1
i = 2
i = 3
```

## 常量指针vs指针常量

要区分 **指针常量** 和 **常量指针**，核心秘诀是：**看 `const` 修饰的是谁 —— 修饰指针变量本身，就是指针常量；修饰指针指向的内容，就是常量指针**。

可以用一个简单口诀记忆：**“左定值，右定向”**

- `const` 在 `*` 左边：修饰 “指向的内容”（值不能改）→ 常量指针；
- `const` 在 `*` 右边：修饰 “指针变量本身”（指向不能改）→ 指针常量。

> 常量指针首先是一个常量，才是指针，所以首先其值不能变，然后由于是指针，所以指向的值不能变，但是可以改变指向；
>
> 指针常量，是一个指针，然后是常量，所以是一个指针并且不能改变指向，但是可以修改值;  int * const a = &x; a = &x, 可以修改x的值，因为常量的是a（假设 int x = 10；）

```cpp
#include<iostream>
using namespace std;

int main() {
    int a = 10, b = 20;
    
    // 定义常量指针：指向的内容不能改，指针本身能改
    const int *p = &a;  // p指向a（合法）
    
    // 1. 尝试通过指针修改指向的内容 → 编译报错（const修饰内容，值不能改）
    // *p = 100;  // 错误：assignment of read-only location '*p'
    
    // 2. 指针本身重新指向其他变量 → 合法（指针变量可以改）
    p = &b;  // p现在指向b（没问题）
    cout << *p << endl;  // 输出：20（能正常访问新指向的内容）
    
    return 0;
}
```

```cpp
#include<iostream>
using namespace std;

int main() {
    int a = 10, b = 20;
    
    // 定义指针常量：必须初始化，指向不能改，内容能改
    int *const p = &a;  // 初始化时绑定a的地址（必须这么写）
    
    // 1. 尝试修改指针的指向 → 编译报错（const修饰指针本身，指向不能改）
    // p = &b;  // 错误：assignment of read-only variable 'p'
    
    // 2. 通过指针修改指向的内容 → 合法（内容没被const修饰）
    *p = 100;  // 修改a的值（p还是指向a）
    cout << a << endl;  // 输出：100（a被成功修改）
    
    return 0;
}
```





> //const int& a =10;合法——编译器自动优化   ----》 常量引用才能右值字面量，普通引用不可以初始化幼稚字面量
>
> ```cpp
> int temp = 10;  // 1. 隐式创建一个匿名临时变量temp，赋值为10
> const int& a = temp;  // 2. 让常引用a绑定到temp（a是temp的别名）
> ```

## 1. 函数`memset`

在 C++ 中，`memset` 是一个用于<u>内存块初始化</u>的函数，定义在 `<cstring>`（或 `<string.h>`）头文件中。它的核心作用是将某一块内存的每个字节设置为指定的值，通常用于快速初始化数组、结构体或动态分配的内存。

```cpp
void* memset(void* ptr, int value, size_t num);
```

**参数说明**：

- `ptr`：指向要初始化的内存块的指针（可以是任意类型的指针）。
- `value`：要设置的值（虽然是 `int` 类型，但实际只使用其低 8 位，即 `unsigned char` 范围 `0~255`）。
- `num`：要设置的字节数（`size_t` 是无符号整数类型）。

**返回值**：返回指向内存块 `ptr` 的指针。

### 工作原理

`memset` 按**字节**逐字节初始化内存，因此：

- 若目标类型是单字节类型（如 `char`），可以直接使用任意值。
- 若目标类型是多字节类型（如 `int`、`float`、指针等），只能用 `0` 或 `0xFF`（-1）初始化，否则会得到意外结果（因为每个字节都被设置为同一值）。

### 代码案例

```cpp
int arr[5];
// 每个字节设为 0 → 整个 int 为 0
memset(arr, 0, sizeof(arr));
for (int x : arr) std::cout << x << " "; // 输出：0 0 0 0 0

// 每个字节设为 0xFF（即 -1 的补码）→ 整个 int 为 -1
memset(arr, -1, sizeof(arr));
for (int x : arr) std::cout << x << " "; // 输出：-1 -1 -1 -1 -1

int arr[2];
 // 错误：每个字节设为 1 → int 实际值为 0x01010101 = 16843009
 memset(arr, 1, sizeof(arr));
 for (int x : arr) std::cout << x << " "; // 输出：16843009 16843009
```

## 2. 函数`memcpy`

在 C++ 中，`memcpy` 是用于**内存块拷贝**的函数，定义在 `<cstring>`（或 `<string.h>`）头文件中。它的核心作用是将一块内存的内容逐字节拷贝到另一块内存，不区分数据类型，是高效的内存操作工具。

```cpp
void* memcpy(void* dest, const void* src, size_t num);
```

**参数说明**：

- `dest`：指向目标内存块的指针（拷贝的目的地）。
- `src`：指向源内存块的指针（拷贝的来源，用 `const` 保证不被修改）。
- `num`：要拷贝的字节数（`size_t` 是无符号整数类型）。

**返回值**：返回指向目标内存块 `dest` 的指针。

**与 `strcpy` 的区别**：

- `strcpy` 仅拷贝字符串（以 `\0` 结尾），遇到 `\0` 即停止。
- `memcpy` 拷贝指定字节数的内存，不关心内容（即使包含 `\0` 也会继续拷贝）。

### 工作原理

`memcpy` 按**字节**逐字节拷贝 `src` 指向的内存内容到 `dest` 指向的内存，直到拷贝完 `num` 个字节。它**不处理内存重叠**（若源和目标内存重叠，结果未定义），且不区分数据类型（可拷贝任意类型的内存，如 `int`、`char`、结构体等）。

### 代码示例

```cpp
//拷贝结构体
#include <cstring>
#include <iostream>

struct Person {
    char name[20];
    int age;
};

int main() {
    Person src = {"Alice", 25};
    Person dest;
    
    // 拷贝整个结构体
    memcpy(&dest, &src, sizeof(Person));
    
    std::cout << dest.name << " " << dest.age << std::endl; // 输出：Alice 25
    return 0;
}
```

#### 总结

`memcpy` 是高效的内存拷贝工具，适用于任意类型的内存块拷贝，但需注意**内存不重叠**和**目标内存足够大**的前提。在 C++ 中，若涉及类型安全或容器操作，优先使用标准库算法（如 `std::copy`）或容器自身的拷贝机制，更易维护且安全。





### strcpy 函数详细解释

`strcpy` 是 C 标准库 `<cstring>`（或 C 中的 `<string.h>`）提供的**字符串拷贝函数**，核心功能是将一个字符串（源字符串）的内容复制到另一个字符串（目标字符串）中，直到遇到源字符串的终止符 `'\0'`（空字符）为止。

####  函数原型

```cpp
char* strcpy(char* destination, const char* source);
```

- **参数 1：destination**

  指向目标字符串的指针（必须是可修改的内存空间，如堆内存、栈数组，不能是字符串常量`const char*`），用于存储拷贝后的结果。

- **参数 2：source**

  指向源字符串的指针（用`const`修饰，表示源字符串内容不会被修改），拷贝会从该地址开始，直到遇到 '\0'结束（'\0'也会被拷贝到目标字符串）。

- **返回值**：返回 `destination` 的指针（方便链式调用，如 `strlen(strcpy(dst, src))`）。

  - 在 C/C++ 中，`strlen` 函数的核心特性就是**计算字符串中有效字符的长度，不包含末尾的空字符 `'\0'`**

> - 若源字符串长度（含 `'\0'`）超过目标字符串的内存容量，会导致**缓冲区溢出**（覆盖目标字符串后面的内存数据），可能引发程序崩溃、内存 corruption 甚至安全漏洞。
> - 替代方案：C11 标准推荐使用更安全的 `strncpy`（指定最大拷贝长度），或 C++ 中直接使用 `std::string`（自动管理内存，无需手动处理拷贝）。





## 3.`std::copy` 函数解析

```cpp
// 函数原型 （源起始,源结束,目标起始）
std::copy(data, data+len, beginWrite());
```

作用：**把一段内存的数据，拷贝到另一段内存**。

它等价于**安全版的 memcpy**，但更通用、更 C++。（注意和memcpy函数进行对比）

> ### ① `data`
>
> - 要写入缓冲区的**外部数据首地址**
> - 比如你要发送的消息、网络包的起始地址
>
> ### ② `data + len`
>
> - 源数据**结束地址**（左闭右开：不包含这个地址）
> - 表示：从 data 开始，往后数 len 个字节
>
> ### ③ `beginWrite()`
>
> - 返回：`buffer_.begin() + writerIndex_`
> - 也就是**缓冲区当前可写位置的指针**
> - 数据就从这里开始往里写

## C/C++ 宏定义 **完整语法规则**

### 1. 基本宏（对象宏）

```cpp
#define 名字 替换文本
```

- 预处理阶段**直接文本替换**
- 无类型、无作用域、无检查

### 2. 带参数宏（函数宏）

```cpp
#define 宏名(参数1,参数2,...) 替换体
```

- 调用时像函数：`宏名(a,b);`
- 本质还是**文本替换**

### 3. 多行宏：必须用 `\` 续行

```cpp
#define ABC(x) \
    {           \
        x++;    \
    }
```

- **`\` 后面不能有任何空格 / 字符**，必须直接换行 🔥
- ⚠️ 最后一行没有`\`，可以理解成将前面所有行的代码排成一行，所以最后一行不需要
- 你的日志宏就是典型多行宏

### 4. 可变参数宏 `...` + `__VA_ARGS__`

```
#define LOG(fmt, ...) printf(fmt, __VA_ARGS__)
```

- `...` 表示 “任意多个参数”
- `__VA_ARGS__` 会被替换成那一堆参数

### 5. `##` 连接符 / 消除逗号

```
printf(fmt, ##__VA_ARGS__);
```

- 如果可变参数为空，`##` 会**自动删掉前面的逗号**，避免语法错误
- 否则编译报错

### 6. 宏内不能直接定义多行语句块，否则会炸语法

* 这就是为什么必须用 `do { ... } while(0)`：循环只执行一次，将多行语句变成一个整体
* **目的**：将多条语句封装成一个**独立的语法块**，确保宏在任何上下文中（如if后无大括号）都能安全使用，且行为像一个独立语句。

## `#ifdef` 条件编译的核心流程

`#ifdef` 是 C/C++ 预处理指令（编译前执行），核心作用是**根据「是否定义了某个宏」来决定是否编译某段代码**。针对你这段 `LOG_DEBUG` 宏，完整执行流程如下：

```cpp
#ifdef MUDEBUG	// 第一条件分支
  #define LOG_DEBUG(logmsgFormat, ...)                      \
      do                                                    \
      {                                                     \
          Logger &logger = Logger::instance();              \
          logger.setLogLevel(DEBUG);                        \
          char buf[1024] = {0};                             \
          snprintf(buf, 1024, logmsgFormat, ##__VA_ARGS__); \
          logger.log(buf);                                  \
      } while (0)
#else	// 第二条件分支
  #define LOG_DEBUG(logmsgFormat, ...)
#endif	
```

**预处理阶段（编译第一步）**

编译器先扫描代码中的预处理指令（以 `#` 开头的指令），此时会检查：

- **第一步**：判断是否定义了 `MUDEBUG` 这个宏（注意：是 “定义过” 即可，哪怕宏的值是空，比如 `#define MUDEBUG` 或 `#define MUDEBUG 1` 都算 “定义了”）。

- **第二步**：根据判断结果选择执行哪段代码：

  - ✅ 如果 `MUDEBUG` 已定义：使用 `#ifdef` 块内的 `LOG_DEBUG` 宏定义（即包含完整的日志输出逻辑）；
  - ❌ 如果 `MUDEBUG` 未定义：使用 `#else` 块内的 `LOG_DEBUG` 宏定义（即空宏，啥也不做）。

- #### 关键细节说明：

  1. **分支 1（定义 MUDEBUG）**：
     - `LOG_DEBUG` 和 `LOG_INFO`/`LOG_ERROR` 逻辑完全一致，调用时会正常创建日志缓冲区、格式化字符串、输出调试日志。
     - 典型场景：开发 / 调试阶段，我们会在代码开头加 `#define MUDEBUG`，此时所有 `LOG_DEBUG("xxx")` 都会输出调试信息。
  2. **分支 2（未定义 MUDEBUG）**：
     - `#define LOG_DEBUG(logmsgFormat, ...)` 没有任何替换体，意味着：
       - 预处理阶段，所有 `LOG_DEBUG("调试信息：%d", num)` 会被直接替换成**空**；
       - 编译阶段不会生成任何日志相关的代码，运行时也不会有任何开销（比如不会创建缓冲区、不会调用 Logger）。
     - 典型场景：生产 / 发布阶段，我们删掉 `#define MUDEBUG`，此时所有 `LOG_DEBUG` 调用都会 “消失”，既不输出日志，也不影响程序性能。

## 4. `snprintf` 标准语法

```c
// 安全的格式化字符串函数,核心是「限制写入长度」避免溢出；
int snprintf(char *str, size_t size, const char *format, ...);
```

- **参数**：

  - `str`：输出缓冲区（字符数组 / 指针）；
  - `size`：缓冲区大小（限制写入字节数，防止溢出）；
  - `format`：格式化字符串（含`%d`/`%s`/`%f`等占位符）；
  - `...`：可变参数，与`format`中的占位符一一对应；

- **返回值**：

  - 成功：格式化后的字符串总长度（若未截断）；
  - 截断：返回「本应写入的总长度」（大于等于`size`）；
  - 失败：返回负数（如格式错误）；

- **核心特性**：

  - 无论是否截断，都会在缓冲区末尾添加`\0`，是比`sprintf`更安全的替代方案（`sprintf`无长度限制，易缓冲区溢出）。

- 举例：`snprintf(buf, 1024, logmsgFormat, ##__VA_ARGS__)`

  - 该行代码的整体作用

    将 `logmsgFormat`（格式化字符串）与 `##__VA_ARGS__`（可变参数）进行格式化拼接，结果写入`buf`缓冲区，且最多写入 1023 个有效字符（留 1 个字节给`\0`），避免缓冲区溢出。
