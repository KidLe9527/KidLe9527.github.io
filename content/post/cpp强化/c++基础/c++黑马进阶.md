### 模板

#### 模板的概念

模板就会通用的模具，大大提高复用性。

例如生活中的一寸照片、PPT模板。

**模板的特点**：

- 模板不可以直接使用，它只是一个框架
- 模板的通用并不是万能的

#### 函数模板

- C++另一种编程思想称为**泛型编程**，主要利用的技术就是模板
- C++提供两种模板机制，**函数模板**和**类模板**。

##### 函数模板语法

函数模板作用:
建立一个通用的函数，其函数返回值类型和形参类型可以不具体制定，用一个**虚拟的类型**来代表。

```cpp
template<typename T>
函数声明或定义
```

> * 在 C++ 中，**模板声明（`template<...>`）必须紧邻其修饰的模板定义 / 声明**，核心是：模板参数列表必须直接出现在模板实体（类、函数等）的上方，形成语法上的关联。
> * `template<class T1, class T2>` 必须直接出现在 `class Person` 之前，中间只能有空白符（空格、换行、注释），不能插入其他代码（如变量定义、函数声明等）。

```cpp
/函数模板
//声明一个模板,告诉编译器后面的代码中紧跟着的T不要报错，T是一个通用数据类型
template<class T>
void MySwap(T& a, T& b)
{
	T Temp = a;
	a = b;
	b = Temp;
}

//1.自动类型推导
MySwap(a, b);
//显示指定类型
MySwap<double>(c, d);
```

* **解释**:

  * template——声明创建模板

  * typename——表明其后面的 符号为一种数据类型，可以用class代替。

  * T——通用的数据类型，名称可以替换，通常为大写字母。

##### 函数模板注意事项

- 自动类型推导，必须推导出一致的数据类型T才能使用
- 模板必须要确定出T的数据类型，才可以使用

##### 普通函数与函数模板的区别

- 普通函数调用时可以发生自动类型转换(隐式类型推导) 
- 函数模板调用时，如果利用自动类型推导，不会发生隐式类型转换
- 如果利用显式指定类型的方式，可以发生隐式类型转换，`MySwap<int>(10, 'a') = 10 + 99 = 109` ---> a的ascall是99

**总结**:建议使用显式指定类型的方式，调用函数模板，因为可以自己确定通用类型T



##### 普通函数与函数模板的调用规则

1. 如果函数模板和普通函数都可以实现，优先调用普通函数。普通函数只有声明会报错

2. 可以通过空模板参数列表来强制调用函数模板 

   ```cpp
   //通过空模板的参数列表强制调用函数模板
   myPrint<>(a,b);
   ```

3. 函数模板也可以发生重载

4. 如果函数模板可以产生更好的匹配，优先调用函数模板

**总结**:既然提供了函数模板，最好就不要提供普通函数，否则容易出现二义性。



##### 模板的局限性

模板的通用性并不是万能的。

> 模板并非能处理所有数据类型，当遇到自定义类型（如`Person`类）或不支持模板默认逻辑的类型时，默认的模板实现会失效，必须通过**模板具体化**来解决。
>
> 模板的泛化性决定了它只能处理**通用规则**，无法适配特定类型的**特殊业务逻辑**。

**总结**：

- 利用具体化的模板，可以解决自定义类型的通用化

  ```cpp
  //对比两个数据是否相等
  template<class T>
  bool myCompare(T& a, T& b)
  {
  	return a == b;
  }
  
  //利用具体化Person的版本来实现代码，具体优化调用
  template<>bool myCompare(Person& p1, Person& p2)
  {
  	if (p1.m_Name == p2.m_Name && p1.m_Age == p2.m_Age) return true;
    return false;
  }
  ```

- 学习模板并不是为了写模板，而是在STL能够运用系统系统的模板



#### [类模板](https://so.csdn.net/so/search?q=类模板&spm=1001.2101.3001.7020)

##### 类模板语法

```cpp
//类模板
template<class NameType,class AgeType>
class Person
{
public:
	Person(NameType name, AgeType age)
	{
		this->m_Age = age;
		this->m_Name = name;
	}
	void showPerson()
	{
		cout << this->m_Name << this->m_Age << endl;
	}
	NameType m_Name;
	AgeType m_Age;
};

//调用
Person<string, int>p1("张三",10); // <>中是模板的参数列表
```

类模板作用:

- 建立一个通用类， 类中成员数据可以不具体指定，用一个虚拟的类型来代表

**总结**：

类模板和函数模板语法相似，在声明模板template后面加类，此类称为类模板。



##### 类模板与函数模板的区别

类模板与函数模板的区别主要有两点:

1. 类模板没有自动类型推导的使用方式

2. 类模板在模板参数列表中可以有默认参数

   ```cpp
   template<class NameType = string, class AgeType = int>//默认参数
   class Person{...};
   
   //调用
   Person<> p("wang", 23); //使用默认参数，因为两个参数都有默认值，如果没有默认，就会报错！！！
   Person<string,int> p2("李四", 13);//只能用显示指定类型
   ```



##### 类模板中的[成员函数](https://so.csdn.net/so/search?q=成员函数&spm=1001.2101.3001.7020)创建实际

类模板中成员函数和普通类中成员函数创建实际是有区别的:

- **普通类中的成员函数一开始就可以创建**

  > - 编译器处理普通类时，能明确知道类的所有成员和函数实现，因此会直接为这些函数生成机器码。
  > - 即使某个成员函数从未被调用，它依然会被编译到目标代码中（除非被编译器优化移除）。
- 类模板中的成员函数在 **实例化 且 调用** 时才创建

  > - 编译器处理类模板定义时，**不会立即为成员函数生成代码**，因为模板参数`T`的具体类型尚未确定，无法确定函数的具体行为（比如`obj.showPerson1()`是否合法，取决于`T`是否有`showPerson1()`）。
  > - 只有当模板被**实例化（指定具体类型）\**且\**成员函数被调用**时，编译器才会根据实际类型生成该成员函数的代码。

**总结**：
类模板中的成员函数并不是一开始就创建的，在调用时才去创建。

| 特性         | 普通类的成员函数                | 类模板的成员函数               |
| ------------ | ------------------------------- | ------------------------------ |
| 创建时机     | 编译类定义时直接创建            | 模板实例化且函数被调用时才创建 |
| 依赖条件     | 无需依赖外部类型，直接确定      | 依赖模板参数的具体类型         |
| 错误检测时机 | 编译类定义时检测语法 / 逻辑错误 | 调用函数时检测类型匹配错误     |

##### 类模板对象做函数参数

学习目标:
**类模板实例化出的对象，向函数传参的方式**

一共有三种传入方式

1. 指定传入的类型——直接显式对象的数据类型
2. 参数模板化——将对象中的参数变为模板参数进行传递
3. 整个类模板化——将这个对象类型，模板化进行传递

```cpp
template<class T1,class T2>
class Person{...};

//1.指定传入类型
void PrintPerson1(Person<string,int>&p) //PrintPerson1是全局函数
  
//2.参数模板化
template<class T1,class T2>
void PrintPerson2(Person<T1, T2>&p)
  
//3.整个类模板化
template<class T>
void PrintPerson3(T &p)
```

**总结**：

- 通过类模板创建的对象，可以有三种方式向函数中进行传参
- 使用比较广泛得是第一种，指定传入的类型

##### 类模板与继承

当类模板碰到继承时，需要注意一下几点：

- 当子类继承的父类是一个类模板时，子类在声明的时候，要指定出父类中T的类型
- 如果不想指定，编译器无法给子类分配内存
- 如果想灵活指定出父类中T的类型，子类也需要变为类模板

```cpp
template<class T>
class Base { T m; }; // m 是成员变量，类型是T模版

class Son :public Base<int>//必须要知道父类中T的数据类型才能继承给子类
{ };

//如果想灵活指定父类中T类型，子类也需要变类模板
template<class T1,class T2>
class Son2 :public Base<T2>{
  T1 obj; //T1 是Son2的成员变量，Son2也成为类模版
}
```

**总结**：
如果父类是类模板，子类需要指定出父类中T的数据类型。



##### 类模板的成员函数的类外实现

类模板中成员函数类外实现时，需要**加上模板参数列表。**

```cpp
//类模板成员函数的类外实现
template<class T1,class T2 >
class Person {
	Person(T1 name, T2 age);
	void showPerson();
	T1 m_Name;
	T2 m_Age;
};

//构造函数类外实现
template<class T1,class T2>
Person<T1,T2>::Person(T1 name, T2 age){...} // 作用域也要加上类模版参数

//成员函数类外实现
template<class T1,class T2>
void Person<T1,T2>::showPerson() {...}
```

**总结**：

主流的解决方式是第二种，将类模板成员函数写到一起，并将后缀名改为.hpp

##### 类模板与友元

**学习目标**：
掌握类模板配合友元函数的类内和类外实现

全局函数类内实现，直接在类内声明友元即可、

全局函数类外实现，需要提前让编译器知道全局函数的存在

> ```cpp
> #include<iostream>
> #include<string>
> using namespace std;
> 
> template<class T1, class T2>
> class Person
> {
>     // 类内实现友元函数,属于是全局函数（因为void PrintPerson本身是一个全局函数）
>   	//类内的友元函数会自动绑定外层类模板的参数
>     friend void PrintPerson(Person<T1, T2> p)
>     {
>         cout << "类内实现：姓名=" << p.m_Name << "，年龄=" << p.m_Age << endl;
>     }
> 
>     // 全局函数类外实现友元函数（提前声明+空模板参数）
>   	//类外实现的友元函数（如PrintPerson2）脱离了类模板的作用域，无法直接复用T1,T2，因此必须显式声明模板参数（template<class U1, U2>），让编译器知道它是一个独立的模板函数。
>     template<class U1, class U2>
>     friend void PrintPerson2(Person<U1, U2> p);
> 
> public:
>     Person(T1 name, T2 age) : m_Name(name), m_Age(age) {}
> 
> private:
>     T1 m_Name;
>     T2 m_Age;
> };
> 
> // 类外实现友元函数
> template<class U1, class U2>
> void PrintPerson2(Person<U1, U2> p)
> {
>     cout << "类外实现：姓名=" << p.m_Name << "，年龄=" << p.m_Age << endl;
> }
> 
> int main()
> {
>     Person<string, int> p1("张三", 20), p2("李四", 25);
>     PrintPerson(p1);
>     PrintPerson2(p2);
>     return 0;
> }
> ```
>
> * 类内的友元函数会隐式成为模板函数（与类模板参数绑定），编译器在实例化类模板时会同时生成该友元函数的实例。
> * 类外的函数模板需要与类模板参数显式绑定，编译器在实例化类模板时会根据参数匹配生成对应的函数模板实例。

**总结**：

建议全局函数做类内实现，用法简单，而且编译器可以直接识别。

| 实现方式 | 语法要点                                                     | 注意事项                                   |
| -------- | ------------------------------------------------------------ | ------------------------------------------ |
| 类内实现 | 直接在类内定义友元函数，并实现                               | 无需提前声明，函数作用域与类绑定           |
| 类外实现 | 1. 前声明类模板2. 提前声明函数模板3. 友元声明加`<>`(引用类外模版) | 必须保证模板声明的顺序，否则编译器无法解析 |

## SLT初识

#### STL基本概念

- STL(Standard Template Library,标准模板库)
- STL从广义上分为:容器(container)算法(algorithm)迭代器(iterator)
- 容器和算法之间通过迭代器进行无缝连接
- STL几乎所有的代码都采用了模板类或者模板函数

#### STL六大组建

STL大体分为六大组件，分别是：容器、算法、迭代器、仿函数、适配器(配接器)、空间配置器。

> 容器:各种数据结构，如vector、list、deque、set、map等，用来存放数据。
> 算法:常用的各种算法，如sort、find、copy、for_each等
> 迭代器:扮演了容器与算法之间的胶合剂
> 仿函数:行为类似函数，可作为算法的某种策略
> 适配器:一种用来修饰容器或者仿函数或迭代器结构的东西。
> 空间配置器:负责空间的配置与管理

* 容器：

  * **序列式容器**：强调值的排序，序列式容器中的每个元素均有固定的位置

  * **关联式容器**：二叉树结构体，各元素之间没有严格上的物理上的顺序关系

* 算法

  * 质变算法:是指运算过程中会更改区间内元素的内容。例如拷贝、查找、删除等等
  * 非质变算法:是指在运算过程中不会更改区间内的元素内容，例如查找、计数、遍历、寻找极值等等

* **迭代器**：容器和算法之间的的粘合剂

  * 提供一种方法，使之能够依序寻访某个容器所含的各个元素，而又无需暴露该容器的内部表示方式。
  * 每个容器都有自己专属的迭代器。迭代器的使用非常类似于指针，初学阶段我们可以先理解迭代器为指针。
  * 常用的容器中迭代器种类为双向迭代器，和随机访问迭代器。

### String  字符串

#### 常用API

> `const char* str = "hellow world";`
>
> - **`char`**：基础数据类型，表示单个字符（占 1 字节）；
> - **`char*`**：指向字符的指针，通常用于表示字符串（C 风格字符串本质是`char`数组，以`\0`结尾，指针指向数组首元素）；
> - **`const`**：修饰符，表示指针指向的内容**不可修改**（即字符串常量），但指针本身可以指向其他地址。
> - `str`保存的是字符串常量首字符`'h'`的内存地址，而非字符串本身（字符串内容在只读区，`str`只是指向它的指针）。
>   - 字符串常量本质是一个以`'\0'`结尾的`char`数组，`str`指向的是这个数组的首元素（`h`）地址，但整个字符串的范围是从首地址开始，直到遇到第一个`'\0'`为止

> ```cpp
> const char* p = "hello, world";
> cout << p << endl;// 输出字符串，为什么不需要解引用？--- 因为cout重载了const char*类型的输出 运算符
> //完整写法 cout.operator<<(p);
> cout << *p << endl;// 输出第一个字符'h'
> ```

#### String**和c-style字符串转换**

```cpp
// string 转 const char*（正确用法）
string str = "it";

```

> Q：为了修改string字符串的内容，下标操作符[]和at都会返回字符的引用。但当字符串的内存被重新分配之后，可能发生错误.
>
> `string`的底层实现是**动态字符数组**，当赋值的新字符串长度超过当前数组容量时，`string`会：
>
> 1. 申请一块**新的更大的内存**（如 0x2000）；
> 2. 将新字符串内容拷贝到新内存；
> 3. 释放原内存（0x1000）；
> 4. 让`s`指向新内存（0x2000）。
>
> 此时，之前的引用`a`和`b`仍然指向**已被释放的原内存地址（0x1000）**，变成了**悬空引用**（无效引用）。 
>
> 
>
> ### 核心结论：引用与 string 内存管理的矛盾
>
> `[]`或`at()`返回的字符引用**仅在`string`内存未重分配时有效**。一旦`string`发生以下操作导致内存重分配，引用会立即失效：
>
> - 赋值更长的字符串；
> - 调用`resize()`/`reserve()`扩展容量；
> - `append()`等操作导致容量不足；
> - `string`对象被移动 / 拷贝后析构原对象。
>
> 因此，**不要长期持有 string 字符的引用**，尤其是在可能修改`string`长度的操作之后，否则会引发悬空引用风险。



### Vector 动态数组

> 要理解`resize`、`capacity`、`reserve`的区别，我们可以从**功能目标**、**对容器元素 / 内存的影响**、**使用场景**三个维度拆解：
>
> ### 1. `resize(int num)` / `resize(int num, elem)`
>
> **核心作用**：**调整容器的实际元素数量（size）**，直接影响容器中元素的个数。
>
> - **容器变长**：若`num > 当前size`，会新增元素填充至`num`个。
>   - 无`elem`参数时：新增元素用**默认构造函数**初始化（如`int`默认 0，`string`默认空）。
>   - 有`elem`参数时：新增元素统一用`elem`初始化。
> - **容器变短**：若`num < 当前size`，直接删除末尾超出`num`的元素。
> - **对容量（capacity）的影响**：如果新增元素需要更多内存，容器可能自动扩容（capacity 增大）；但如果`num ≤ capacity`，capacity 不会变化。
>
> **示例**：
>
> ```cpp
> vector<int> v{1,2,3};
> v.resize(5);        // size=5，新增2个元素为0 → [1,2,3,0,0]，capacity可能≥5
> v.resize(2);        // size=2，删除末尾元素 → [1,2]，capacity不变
> v.resize(4, 9);     // size=4，新增2个元素为9 → [1,2,9,9]
> ```
>
> ### 2. `capacity()`
>
> **核心作用**：**获取容器当前已分配的内存容量（能容纳的最大元素数，无需再次扩容）**，仅反映内存状态，与实际元素数量（size）无关。
>
> - capacity ≥ size，且只有当容器需要扩容时（如`push_back`超出当前 capacity）才会增大。
> - 不同容器的扩容策略不同（如`vector`通常按 2 倍或 1.5 倍扩容）。
>
> **示例**：
>
> ```cpp
> vector<int> v{1,2,3};
> cout << v.size();    // 3（实际元素数）
> cout << v.capacity();// 可能为3（初始分配3个空间）
> v.push_back(4);      // size=4，若capacity原为3，则扩容后capacity可能为6
> ```
>
> ### 3. `reserve(int len)`
>
> **核心作用**：**预留内存空间（调整 capacity）**，仅分配内存但**不初始化元素**，也不改变实际元素数量（size）。
>
> - 若`len > 当前capacity`：扩容至至少`len`，capacity 变为`len`（或更大，取决于容器实现）。
> - 若`len ≤ 当前capacity`：无任何操作（不会缩容）。
> - 预留的空间不可直接访问（因为没有元素），需通过`push_back`/`emplace`等添加元素后才能使用。
>
> **使用场景**：提前预留足够空间，避免频繁扩容（扩容会导致内存重新分配 + 元素拷贝，影响性能）。
>
> **示例**：
>
> ```cpp
> vector<int> v{1,2,3};
> v.reserve(10);       // capacity≥10，size仍为3 → [1,2,3]（后7个空间未初始化）
> cout << v[5];        // 未定义行为（访问不存在的元素）
> v.push_back(4);      // size=4，使用预留空间，无需扩容
> ```
>
> ### 核心区别总结
>
> | 操作       | 影响对象         | 是否改变元素数量 | 是否初始化新内存 | 典型用途               |
> | ---------- | ---------------- | ---------------- | ---------------- | ---------------------- |
> | `resize`   | size（元素数）   | 是               | 是（新增元素）   | 直接调整容器的元素个数 |
> | `capacity` | 无（仅查询）     | 否               | 否               | 查看当前内存容量       |
> | `reserve`  | capacity（容量） | 否               | 否               | 提前预留内存，避免扩容 |
>
> ### 关键注意点
>
> - `reserve`只分配内存，不创建元素，因此不能直接访问预留位置（如`v[5]`）；
> - `resize`会创建元素，即使是默认值，也可以直接访问（如`resize(5)`后`v[4]`有效）；
> - 容器的`size`是 “实际元素数”，`capacity`是 “最大可容纳元素数（无需扩容）”。

### deque 双端队列

- `deque`是**双端队列**，不是普通队列；
- 内存管理基于连续**分段数组 + 中控器**，不是链表（链表是节点离散存储，而`deque`是分段连续）。

* 链表（如`list`）的优势是任意位置插入 / 删除高效，但随机访问低效；而`deque`兼顾了两端操作高效和随机访问高效，是两者的折中设计。

### queue 普通队列

* Queue所有元素的进出都必须符合”先进先出”的条件，只有queue的顶端元素，才有机会被外界取用。Queue不提供遍历功能，也不提供迭代器
* C++ 中的 `std::queue` 是一种**容器适配器**（container adapter），它本身不直接管理内存，而是依赖于底层的容器（默认是 `std::deque`，也可以指定 `std::list` 等）来实现内存管理。因此，`queue` 的内存管理本质上是**底层容器的内存管理机制**。
* `queue` 基于 `deque` 实现时，入队（`push`）操作对应 `deque` 的尾部插入，出队（`pop`）操作对应 `deque` 的头部删除，内存管理完全由 `deque` 自动处理。

### list 双向循环链表

* 特点
  * 采用动态存储分配，不会造成内存浪费和溢出
  * 链表执行插入和删除操作十分方便，修改指针即可，不需要移动大量元素
  * 链表灵活，但是空间(指针域)和时间(遍历)额外耗费较大。
  * List有一个重要的性质，插入操作和删除操作都不会造成原有list迭代器的失效。这在vector是不成立的，因为vector的插入操作可能造成记忆体重新配置，导致原有的迭代器全部失效，甚至List元素的删除，也只有被删除的那个元素的迭代器失效，其他迭代器不受任何影响。
  * 由于链表的存储方式并不是连续的内存空间，因此链表list中的迭代器只支持前移和后移，属于双向迭代器。
    * list容器中不可以通过[ ]或者at方式访问数据

```cpp
reverse();//反转链表，比如lst包含1,3,5元素，运行此方法后，lst就包含5,3,1元素。
sort(); //list排序
```

### Set/multiset 集合

* 特点：
  * Set的特性是。所有元素都会根据元素的键值自动被排序。Set的元素不像map那样可以同时拥有实值和键值，set的元素即是键值又是实值。Set不允许两个元素有相同的键值
  * set拥有和list某些相同的性质，当对容器中的元素进行插入操作或者删除操作的时候，操作之前所有的迭代器，在操作完成之后依然有效，被删除的那个元素的迭代器必然是一个例外。
  * multiset特性及用法和set完全相同，唯一的差别在于它允许键值重复。set和multiset的底层实现是红黑树.

```cpp
find(key);//查找键key是否存在,若存在，返回该键的元素的迭代器；若不存在，返回set.end();
count(key);//查找键key的元素个数
lower_bound(keyElem);//返回第一个key>=keyElem元素的迭代器。
upper_bound(keyElem);//返回第一个key>keyElem元素的迭代器。
equal_range(keyElem);//返回容器中key与keyElem相等的上下限的两个迭代器。
```

### map/multimap容器

* 特点：
  * Map的特性是，所有元素都会根据元素的键值自动排序。
  * Map所有的元素都是pair,同时拥有实值和键值，pair的第一元素被视为键值，第二元素被视为实值，map不允许两个元素有相同的键值。
  * 不可以通过map的迭代器改变map的键值, 因为map的键值关系到map元素的排列规则，任意改变map键值将会严重破坏map组织。
  * 如果想要修改元素的实值，那么是可以的。
  * Map和list拥有相同的某些性质，当对它的容器元素进行新增操作或者删除操作时，操作之前的所有迭代器，在操作完成之后依然有效，当然被删除的那个元素的迭代器必然是个例外。
  * Multimap和map的操作类似，唯一区别multimap键值可重复。
  * Map和multimap都是以红黑树为底层实现机制。

### STL容器使用时机

| .            | vector   | deque    | list     | set    | multiset | map             | multimap      |
| ------------ | -------- | -------- | -------- | ------ | -------- | --------------- | ------------- |
| 典型内存结构 | 单端数组 | 双端数组 | 双向链表 | 二叉树 | 二叉树   | 二叉树          | 二叉树        |
| 可随机存取   | 是       | 是       | 否       | 否     | 否       | 对key而言：不是 | 否            |
| 元素搜寻速度 | 慢       | 慢       | 非常慢   | 快     | 快       | 对key而言：快   | 对key而言：快 |
| 元素安插移除 | 尾端     | 头尾两端 | 任何位置 | -      | -        | -               | -             |

* vector的使用场景：比如软件历史操作记录的存储，我们经常要查看历史记录，比如上一次的记录，上上次的记录，但却不会去删除记录，因为记录是事实的描述。

* deque的使用场景：比如排队购票系统，对排队者的存储可以采用deque，支持头端的快速移除，尾端的快速添加。如果采用vector，则头端移除时，会移动大量的数据，速度慢。
  * vector与deque的比较：
    一：vector.at()比deque.at()效率高，比如vector.at(0)是固定的，deque的开始位置 却是不固定的。
    二：如果有大量释放操作的话，vector花的时间更少，这跟二者的内部实现有关。
    三：deque支持头部的快速插入与快速移除，这是deque的优点。

* list的使用场景：比如公交车乘客的存储，随时可能有乘客下车，支持频繁的不确实位置元素的移除插入。

* set的使用场景：比如对手机游戏的个人得分记录的存储，存储要求从高分到低分的顺序排列。

* map的使用场景：比如按ID号存储十万个用户，想要快速要通过ID查找对应的用户。二叉树的查找效率，这时就体现出来了。如果vector容器，最坏的情况下可能要遍历完整个容器才能找到该用户。

## 函数对象

总结：
1、函数对象通常不定义构造函数和析构函数，所以在构造和析构时不会发生任何问题，避免了函数调用的运行时问题。
2、函数对象超出普通函数的概念，函数对象可以有自己的状态
3、函数对象可内联编译，性能好。用函数指针几乎不可能
4、模版函数对象使函数对象具有通用性，这也是它的优势之一



#### （1）谓词（Predicate）

谓词是**返回值为`bool`类型的函数 / 函数对象**，用于描述 “条件判断” 或 “关系比较”，分为：

- **一元谓词**：接收 1 个参数（如`GreaterThenFive`的`operator()(int num)`）；
- **二元谓词**：接收 2 个参数（如`MyCompare`的`operator()(int num1, int num2)`）。

**作用**：为 STL 算法提供判断 / 比较逻辑（如`find_if`用一元谓词指定查找条件，`sort`用二元谓词指定排序规则）。

#### （2）函数对象（Functor）

函数对象是**重载了`operator()`的类 / 结构体的实例**，也叫 “仿函数”—— 它是一个对象，但能像函数一样被调用（`obj(args)`等价于`obj.operator()(args)`）。

**本质**：用对象封装函数逻辑，可携带状态、支持模板泛化，比普通函数更灵活。

| 维度         | 谓词（Predicate）                                    | 函数对象（Functor）                    |
| ------------ | ---------------------------------------------------- | -------------------------------------- |
| **定义**     | 返回`bool`的 “可调用实体”（函数 / 对象）             | 重载`operator()`的类 / 结构体实例      |
| **核心特征** | 强调 “判断逻辑”（返回`bool`）                        | 强调 “对象可被调用”（行为封装）        |
| **范围**     | 是函数对象的**子集**（仅当`operator()`返回`bool`时） | 范围更广（`operator()`可返回任意类型） |

##### 联系

- 谓词可以是函数对象（当函数对象的`operator()`返回`bool`时，它就是谓词）；
- 函数对象不一定是谓词（比如`operator()`返回`int`的函数对象，就不是谓词）；
- STL 算法中，谓词常以函数对象的形式传递（如`MyCompare`既是函数对象，也是二元谓词）。

> 函数对象的类型是编译期确定的，核心原因在于**函数对象是类 / 结构体的实例，其类型由类 / 结构体本身决定，而类 / 结构体的定义是编译期可见的**。
>
> **可携带状态**：函数对象可通过成员变量保存上下文（普通函数只能用全局变量，不优雅）
>
> | 特性         | 函数对象                   | 普通函数（依赖全局变量）         |
> | ------------ | -------------------------- | -------------------------------- |
> | 状态存储     | 成员变量（对象私有）       | 全局 / 静态变量（共享）          |
> | 多实例独立性 | 不同对象可存不同状态       | 全局变量被所有调用共享，冲突风险 |
> | 线程安全     | 天然安全（对象私有）       | 需加锁，复杂且低效               |
> | 代码优雅性   | 高（状态与逻辑封装在一起） | 低（逻辑依赖外部变量）           |



#### 内建函数对象🔥

STL内建了一些函数对象。分为:算数类函数对象,关系运算类函数对象，逻辑运算类仿函数。这些仿函数所产生的对象，用法和一般函数完全相同，当然我们还可以产生无名的临时对象来履行函数功能。使用内建函数对象，需要引入头文件`#include <functional>`

###### 位运算类（C++11 起）

封装按位与、或、异或等操作：

| 函数对象     | 功能     | 对应操作 |
| ------------ | -------- | -------- |
| `bit_and<T>` | 按位与   | `a & b`  |
| `bit_or<T>`  | 按位或   | `a ｜ b` |
| `bit_xor<T>` | 按位异或 | `a ^ b`  |
| `bit_not<T>` | 按位取反 | `~a`     |

###### 内建函数对象的优势

1. **通用性**：模板化设计，支持任意可操作的类型（如 `int`、`float`、自定义类型）。
2. **适配性**：可与标准算法（`std::sort`、`std::transform`）、函数适配器（`std::bind`、`std::not1`）结合使用。
3. **可读性**：语义化命名（如 `greater<T>` 比手写 lambda 更直观）。
