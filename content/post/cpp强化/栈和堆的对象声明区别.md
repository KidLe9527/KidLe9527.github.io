在 C++ 中，堆上创建对象时`new person()`的括号可省略，而栈上`person p = person()`的括号不能省略（或省略后语义不同），核心原因是**栈对象的初始化规则与堆对象的内存分配逻辑差异**，以及 C++ 对 “显式构造调用” 和 “默认初始化” 的语法区分。

### 一、堆上：`new person` 与 `new person()` 的区别

堆对象通过`new`创建时，**括号的作用是区分 “默认初始化” 和 “值初始化”**，但无论是否加括号，都会调用构造函数（或执行零初始化）：

- `person* p = new person;`：执行**默认初始化**

  如果 person 有用户定义的默认构造函数，则调用它；如果是 POD 类型（如内置类型 / 简单结构体），内存内容为未定义（随机值）。

- `person* p = new person();`：执行**值初始化**

  无论是否有用户定义的默认构造函数，都会先零初始化内存（内置类型设为 0，类类型调用默认构造），再调用构造函数（若存在）。

**为什么括号可省略？**

因为`new`表达式的语法允许省略括号，且省略后仍能正确触发对象构造（只要类有默认构造函数）。编译器明确将`new T`和`new T()`视为合法的对象创建方式，仅初始化规则不同，不影响对象的合法性。

### 二、栈上：`person p` 与 `person p = person()` 的区别

栈对象的初始化规则更严格，**括号的省略会导致语义完全变化**：

1. `person p;`：执行**默认初始化**
   - 若`person`有用户定义的默认构造函数，调用它；
   - 若`person`是 POD 类型，内存未初始化（随机值）；
   - 这是栈对象的 “直接声明”，属于变量定义，而非 “构造函数显式调用”。
2. `person p = person();`：执行**拷贝 / 移动初始化**
   - `person()`是**匿名临时对象的显式构造**（必须加括号，否则语法错误）；
   - 再通过拷贝 / 移动构造函数将临时对象赋值给`p`（C++17 后会优化为直接构造，即 “返回值优化”）。

**为什么`person p = person;`不行？**

`person`是类型名，不是表达式，`person p = person`会被编译器解析为 “尝试将类型名赋值给对象”，属于语法错误。必须用`person()`显式调用构造函数创建临时对象，这是 C++ 语法对 “类型标识” 和 “表达式” 的严格区分。

此外，若写成`person p();`，会被编译器误解为**函数声明**（声明一个返回`person`、无参数的函数`p`），而非对象定义 —— 这就是经典的 “最令人头痛的解析（Most Vexing Parse）”，进一步要求栈上显式构造临时对象时必须保留括号。

### 三、核心原因总结

| 场景             | 省略括号的语义             | 保留括号的语义                  | 语法合法性               |
| ---------------- | -------------------------- | ------------------------------- | ------------------------ |
| 堆（`new`）      | 默认初始化（调用默认构造） | 值初始化（零初始化 + 默认构造） | 均合法，仅初始化规则不同 |
| 栈（直接声明）   | 默认初始化（变量定义）     | 函数声明（Most Vexing Parse）   | 括号非法（被解析为函数） |
| 栈（拷贝初始化） | 语法错误（类型名无法赋值） | 显式构造临时对象 + 拷贝初始化   | 必须保留括号             |

本质上：

- 堆对象由`new`运算符管理内存，编译器对括号的解析聚焦于 “初始化方式”，而非语法合法性；
- 栈对象的声明受限于 C++ 的 “类型 - 表达式” 区分和 “最令人头痛的解析” 规则，括号的省略会导致语法歧义或错误，因此必须保留。
