C++11 及后续标准引入了丰富的并发编程工具，为多线程开发提供了原生支持。以下是你提到的核心并发组件的详细解释：

> https://blog.csdn.net/qq_42974718/article/details/140421615?spm=1001.2014.3001.5506

### 1. `std::thread`

`std::thread`是 C++11 标准库中用于**创建和管理线程**的类，定义在`<thread>`头文件中，它封装了操作系统的原生线程（如 POSIX 线程 pthread 或 Windows 线程），提供了跨平台的线程操作接口。

* ### `std::thread`的核心作用

  - **创建新线程**：将一个可调用对象（函数、lambda 表达式、函数对象等）作为参数传入`std::thread`构造函数，即可在新线程中执行该对象。
  - **管理线程生命周期**：支持等待线程结束（`join()`）、分离线程（`detach()`）、判断线程状态（`joinable()`）等操作。
  - **封装原生线程**：屏蔽不同操作系统的线程 API 差异，实现跨平台。

- **核心功能**：

  - 通过构造函数传入可调用对象（函数、lambda、函数对象等）创建线程。
  - **`join()`**：阻塞当前线程（如主线程），等待`std::thread`对象关联的子线程执行完毕。调用后，线程变为**非 joinable 状态**，析构时不会触发异常。执行后对象不再表示可运行线程（becomes non-joinable）
  - **`detach()`**：将子线程与`std::thread`对象分离，子线程变为 “后台线程”（守护线程），由操作系统接管生命周期。分离后线程不可再`join()`，且`joinable()`返回`false`。

  - **`joinable()`**：判断线程是否处于 “可连接状态”（即是否关联了一个未完成的线程）。新创建的线程默认是`joinable`的，调用`join()`或`detach()`后变为非`joinable`。

    - `true` → 有效线程，必须由开发者负责 join/detach

      `false` → 已 join、detach、默认构造、移动过的线程

  - **`get_id()`**：返回线程的唯一标识符（`std::thread::id`类型），用于区分不同线程。

    | 方法                         | 适用场景                                  |
    | ---------------------------- | ----------------------------------------- |
    | `thread_obj.get_id()`        | 主线程中获取子线程的 ID（需持有线程对象） |
    | `std::this_thread::get_id()` | 线程内部获取自身 ID（无需要线程对象）     |

- **示例**：

  ```cpp
  #include <thread>
  #include <iostream>
  
  void task(int x) {
      std::cout << "Thread: " << x << std::endl;
  }
  
  int main() {
      std::thread t1(task, 1); // 创建线程并执行task(1)
      t1.join(); // 等待t1完成
      return 0;
  }
  ```

  > #### `joinable`状态的析构规则（重点！）
  >
  > 如果`std::thread`对象析构时仍处于**joinable 状态**（未调用`join()`或`detach()`），会直接调用`std::terminate()`终止进程（如你之前代码中的崩溃现象）。这是 C++ 标准的强制要求，目的是避免 “僵尸线程” 或资源泄漏。
  
  > 补充：
  >
  > * C++ 标准明确将 `std::thread` 的**拷贝构造函数**和**拷贝赋值运算符**声明为**删除**（`= delete`），禁止拷贝操作。因为：
  >   * 线程所有权只能唯一持有
  >   * 避免多个对象指向同一线程导致不可管理的生命周期问题
  > * **支持移动**，移动后，原 `std::thread` 对象会变为 “空状态”（不再关联任何线程），新对象接管原线程的所有权；
  >   * 这既保证了线程资源的唯一归属，又允许 `std::thread` 对象在函数间传递、存入容器等灵活操作。
  >
  > ```cpp
  > #include <thread>
  > #include <iostream>
  > 
  > void work() {
  >     std::cout << "线程运行中，ID：" << std::this_thread::get_id() << "\n";
  > }
  > 
  > int main() {
  >   	// 临时std::thread对象（右值），移动构造给t1
  >     std::thread t1{ std::thread(work) }; // 😫这里最好花括号初始化--->不然被编译器认为是函数声明
  > 
  >     // 或更简洁的写法：利用隐式移动（C++11起）
  >     std::thread t2(work);  // t2直接关联work线程
  >     std::thread t3;        // t3为空（不关联任何线程）
  > 
  >     // 移动赋值：t1的线程所有权转移给t3，t1变为空
  >     t3 = std::move(t1);  
  > 
  >     // t1已空，无需join；t3接管了线程，需要join
  >   	t3.join();
  >     t2.join();  
  >     // t1.join();  // 错误！t1已无关联线程，join会崩溃 😊
  > 
  >     return 0;
  > }
  > ```

### 2. `std::mutex`

`std::mutex`是 C++11 引入的互斥锁类（定义在`<mutex>`头文件中），实现了**独占式互斥**：同一时刻只能有一个线程持有锁，适用于 “读写都需要互斥” 的场景。

* `std::mutex`是不可复制、不可移动的，确保锁的所有权唯一。

- **核心功能**：
  | 函数         | 作用                                                         |
  | ------------ | ------------------------------------------------------------ |
  | `lock()`     | 加锁：若锁已被占用，则阻塞当前线程，直到获取锁；若加锁失败（如死锁），会抛出异常。 |
  | `try_lock()` | 尝试加锁：若锁未被占用则成功获取（返回`true`），否则立即返回`false`（不阻塞）。 |
  | `unlock()`   | 解锁：释放锁，需确保当前线程持有锁，否则行为未定义（可能崩溃）。 |
- **注意**：需手动确保`lock()`和`unlock()`配对，否则可能导致死锁或资源泄漏。

> 手动调用`lock()`和`unlock()`存在风险：若线程在持有锁时抛出异常或提前退出，会导致锁无法释放（死锁）。
>
> ```cpp
> std::mutex mtx;  // 全局互斥锁，保护共享资源
> int shared_data = 0;  // 共享资源
> 
> void increment() {
>     for (int i = 0; i < 100000; ++i) {
>         mtx.lock();  // 加锁：独占共享资源
>         shared_data++;  // 安全操作共享资源
>         mtx.unlock();  // 解锁：释放锁
>     }
> }
> ```

### 3. `std::lock_guard`

`std::lock_guard`是**RAII 风格的锁管理器**：构造时自动加锁，析构时自动解锁（即使发生异常），避免手动解锁的遗漏。

- **核心特性**：

  - 构造时自动调用`mutex::lock()`，析构时自动调用`mutex::unlock()`。
  - 不可复制、不可移动，确保作用域内独占锁，确保锁的生命周期与作用域严格绑定。

- **示例**：

  ```cpp
  std::mutex mtx;
  int shared_data = 0;
  
  void increment() {
      for (int i = 0; i < 100000; ++i) {
          std::lock_guard<std::mutex> lock(mtx);  // 构造时lock()，析构时unlock()
          shared_data++;
      }  // lock_guard析构，自动解锁
  }
  ```
  



#### `std::unique_lock`(看后面)

`std::unique_lock`是 C++11 引入的**灵活锁管理工具**（定义在`<mutex>`头文件），相比`std::lock_guard`提供了更精细的锁控制能力，核心优势是支持**动态锁操作**和**与条件变量配合**

### 4. `std::atomic`

`std::atomic`用于定义**原子类型**，支持原子操作（不可中断的操作），避免对共享变量的非原子访问导致的数据竞争。

- **核心特性**：

  - 支持常见操作（如`++`、`+=`、赋值等）的原子化，无需显式加锁。
  - 模板类，可实例化为`std::atomic<int>`、`std::atomic<bool>`等。

- **示例**：

  ```cpp
  #include <atomic>
  #include <thread>
  
  std::atomic<int> counter(0);
  
  void increase() {
      for (int i = 0; i < 1000; ++i) {
          counter++; // 原子操作，无需锁
      }
  }
  
  int main() {
      std::thread t1(increase);
      std::thread t2(increase);
      t1.join();
      t2.join();
      // 结果一定是2000，无数据竞争
      return 0;
  }
  ```

  

### 5. `std::async` & `std::future`

`std::async`用于**异步执行任务**，返回`std::future`对象以获取任务结果或状态；`std::future`是异步操作的 “结果载体”，用于等待和获取异步任务的结果。

- **核心功能**：

  - `std::async`可指定启动策略（`std::launch::async`立即创建异步线程，`std::launch::deferred`延迟执行）。
  - `std::future::get()`：阻塞等待任务完成并获取结果（只能调用一次）。
  - `std::future::wait()`：阻塞等待任务完成，但不获取结果。
  - `std::future::valid()`：检查是否关联有效任务。

- **示例**：

  ```cpp
  #include <future>
  #include <iostream>
  
  int compute() {
      return 42; // 模拟耗时计算
  }
  
  int main() {
      // 异步执行compute，返回future对象
      std::future<int> fut = std::async(std::launch::async, compute);
      // 阻塞获取结果
      std::cout << "Result: " << fut.get() << std::endl; // 输出42
      return 0;
  }
  ```




### 6. `std:: ref()`

`std::ref`是 C++ 标准库中的一个函数模板（定义在`<functional>`头文件中），核心作用是**创建一个可拷贝的 “引用包装器”**，解决 “可变引用无法被拷贝传递” 的问题，常用于线程参数传递、函数绑定（`std::bind`）等场景

> ### 一、为什么需要`std::ref`？
>
> C++ 中**普通引用（`T&`）是不可拷贝的**—— 引用本质是对象的别名，无法独立存在，因此不能作为参数被拷贝传递（比如`std::thread`的构造函数会拷贝参数，若直接传引用会编译失败）。
>
> 而`std::ref`的出现，就是为了让 “引用语义” 能通过**值传递**的方式传递，同时保证操作的是原对象。
>
> ### 二、`std::ref`的本质：返回`std::reference_wrapper`
>
> `std::ref`本身只是一个 “工厂函数”，它的返回值是`std::reference_wrapper<T>`类型的对象 —— 这是一个**轻量级包装器**，可以理解为 “可拷贝的引用”。
>
> #### `std::reference_wrapper`的核心特性：
>
> 1. **存储原对象的指针**：内部保存指向原对象的指针，而非拷贝原对象；
> 2. **隐式转换为原类型引用**：可以像普通引用一样使用（如赋值、调用成员函数）；
> 3. **可拷贝 / 可移动**：包装器本身是值类型，支持拷贝和移动，解决了普通引用不可拷贝的问题。

```cpp
void func(int& x) {
    x += 10;
}

int main() {
    int a = 0;
    // 用std::ref绑定a的引用
    auto f = std::bind(func, std::ref(a));  
    f();
    std::cout << a;  // 输出10
}
```

### 总结

C++ 的并发组件覆盖了**线程管理**（`std::thread`）、**资源同步**（`std::mutex`/`std::lock_guard`）、**原子操作**（`std::atomic`）和**异步任务**（`std::async`/`std::future`），支持从底层线程控制到高层异步编程的多样化需求。使用时需注意线程安全（如避免死锁、数据竞争），并根据场景选择合适的工具（如原子类型替代锁以提升性能）。

## `assert()函数`

`assert`是 C/C++ 中的一个宏（定义在`<cassert>`/`<assert.h>`头文件中），用于**调试阶段验证程序的假设条件**，确保关键逻辑符合预期。它的核心作用是 “断言某个条件必须为真，否则触发错误并终止程序”，是调试和错误检测的常用工具。

### 一、`assert`的基本用法

语法：

```cpp
assert(condition);
```

- `condition`是一个布尔表达式（如`x > 0`、`ptr != nullptr`）；
- 如果`condition`为**真**，`assert`什么都不做，程序继续执行；
- 如果`condition`为**假**，`assert`会触发错误：打印包含**文件名、行号、失败表达式**的错误信息，然后调用`abort()`终止程序。

### 二、`assert`的工作机制

1. **条件检查**

   运行时计算`condition`的布尔值：

   - 条件为真：无操作，程序正常执行；
   - 条件为假：触发断言失败。

2. **错误信息输出**

   断言失败时，会向标准错误流（`stderr`）打印类似如下的信息：

   ```plaintext
   Assertion failed: (condition), function func, file test.cpp, line 10.
   ```

   包含关键信息：失败的表达式、所在函数、源文件、行号，方便定位问题。

   

3. **终止程序**

   打印错误后，`assert`会调用`abort()`函数（属于 C 标准库），强制终止程序进程（类似`std::terminate()`，但更底层），且不会执行后续代码。

### 三、示例：`assert`的实际使用

```cpp
#include <cassert>
#include <iostream>

int divide(int a, int b) {
    // 断言：除数不能为0
    assert(b != 0 && "Divisor cannot be zero");
    return a / b;
}

int main() {
    int x = 10, y = 0;
    std::cout << divide(x, y) << std::endl;  // 触发断言
    return 0;
}
```

运行结果（断言失败）：

```plaintext
Assertion failed: (b != 0 && "Divisor cannot be zero"), function divide, file test.cpp, line 6.
zsh: abort      ./a.out
```

### 四、`assert`的特点与注意事项

#### 1. 仅在调试模式生效（可禁用）

`assert`是**调试工具**，若定义了宏`NDEBUG`（“No Debug”），则所有`assert`会被编译器忽略，不会生成任何代码。

例如：

```cpp
#define NDEBUG  // 定义后，assert失效
#include <cassert>

int main() {
    assert(1 == 2);  // 无任何反应，程序继续执行
    return 0;
}
```

因此，`assert`通常只用于**开发调试阶段**，发布版本（Release）会通过定义`NDEBUG`禁用，避免性能开销或不必要的终止。

#### 2. 不要用于 “运行时错误处理”

`assert`的目的是**验证 “必须成立” 的假设**（如 “指针非空”“数组索引合法”），而非处理预期的运行时错误（如用户输入错误、文件打开失败）。原因：

- 发布版本中`assert`会被禁用，导致错误检查失效；
- 断言失败直接终止程序，无法优雅恢复。

例如，不应使用`assert`检查文件是否打开：

```cpp
// 错误用法：发布版本中assert被禁用，file可能为nullptr但程序继续执行
FILE* file = fopen("data.txt", "r");
assert(file != nullptr);

// 正确用法：运行时错误处理
if (file == nullptr) {
    perror("Failed to open file");
    return 1;
}
```

#### 3. 避免在`assert`中执行关键操作

`assert`的条件表达式若包含赋值、函数调用等副作用，可能导致调试 / 发布版本行为不一致：

```cpp
int x = 0;
assert(++x > 0);  // 调试模式：x变为1；发布模式：x仍为0，逻辑出错
```

### 五、`assert`与异常的区别

很多人会混淆`assert`和异常（`throw`），但二者定位完全不同：

| 特性     | `assert`                       | 异常（`throw`/`try-catch`）     |
| -------- | ------------------------------ | ------------------------------- |
| 用途     | 调试阶段验证假设，检测逻辑错误 | 运行时处理预期错误，允许恢复    |
| 生效阶段 | 仅调试模式（`NDEBUG`禁用）     | 调试 / 发布模式均生效           |
| 处理方式 | 直接终止程序                   | 可捕获并处理，程序可继续执行    |
| 适用场景 | 内部逻辑断言（如 “指针非空”）  | 外部错误处理（如 “文件不存在”） |

### 六、总结

`assert`是**调试利器**，用于强制验证程序的关键假设，帮助开发者在早期发现逻辑错误。但需注意：

- 仅用于调试，不替代运行时错误处理；
- 避免副作用表达式；
- 发布版本通过`NDEBUG`禁用，确保性能。

简单来说：`assert`是 “开发者的契约”—— 断言条件必须成立，否则程序存在 bug，需立即修复。

## `std::unique_lock` ---> 锁包装器，区别`std::shared_lock`

### 一、`std::unique_lock`的核心特点

#### 1. 支持多种锁定策略（延迟 / 尝试 / 超时锁定）

`std::unique_lock`的构造函数支持传入**锁定策略**，实现不同的加锁方式：

- **延迟锁定（`std::defer_lock`）**：构造时不立即加锁，后续通过`lock()`手动加锁；
- **尝试锁定（`std::try_to_lock`）**：构造时尝试加锁，成功则持有锁，失败则不阻塞；
- **超时锁定（`std::try_lock_for`/`std::try_lock_until`）**：尝试在指定时间内加锁，超时后放弃（需配合`std::timed_mutex`等支持超时的互斥锁）。

**示例：延迟锁定**

```cpp
#include <mutex>
#include <thread>

std::mutex mtx;
int data = 0;

void func() {
    // 构造时不加锁（std::defer_lock标记）
    std::unique_lock<std::mutex> lock(mtx, std::defer_lock);
    
    // 后续手动加锁
    lock.lock();
    data++;
    lock.unlock();  // 可提前解锁
    
    // 再次加锁（支持重复加锁/解锁）
    lock.lock();
    data *= 2;
}  // 析构时若持有锁，自动解锁
```

**示例：尝试锁定**

```cpp
void func() {
    std::unique_lock<std::mutex> lock(mtx, std::try_to_lock);
    if (lock.owns_lock()) {  // 判断是否成功获取锁
        data++;
    } else {
        // 加锁失败，执行其他逻辑（不阻塞）
    }
}
```

**示例：超时锁定（需`std::timed_mutex`）**

```cpp
#include <timed_mutex>

std::timed_mutex tmtx;

void func() {
    std::unique_lock<std::timed_mutex> lock(tmtx, std::defer_lock);
    // 尝试加锁500毫秒，超时返回false
    if (lock.try_lock_for(std::chrono::milliseconds(500))) {
        data++;
    }
}
```

#### 2. 可手动释放锁与转移所有权

- **手动解锁（`unlock()`）**：无需等到析构，可提前释放锁，减少锁持有时间（提升并发性能）；
- **所有权转移**：`std::unique_lock`支持**移动语义**（不可拷贝），可通过`std::move`转移锁的所有权（`std::lock_guard`不支持）。

**示例：手动解锁与所有权转移**

```cpp
// 手动解锁
void func1() {
    std::unique_lock<std::mutex> lock(mtx);
    data++;
    lock.unlock();  // 提前释放锁，后续代码无需锁保护
    // 其他非临界区操作
}

// 所有权转移
std::unique_lock<std::mutex> create_lock() {
    std::unique_lock<std::mutex> lock(mtx);
    return lock;  // 移动返回，转移所有权
}

void func2() {
    auto lock = create_lock();  // 获取锁所有权
    data *= 2;
}
```

#### 3. 与条件变量配合（核心用途）

条件变量（`std::condition_variable`）的`wait()`操作要求锁支持**原子解锁 + 阻塞**和**唤醒后重新加锁**，而`std::unique_lock`的灵活性恰好满足这一需求（`std::lock_guard`无法做到）。

**原理**：`wait()`会先解锁，让其他线程操作共享资源；当被唤醒时，自动重新加锁并检查条件。

示例：条件变量配合`std::unique_lock`

```cpp
#include <mutex>
#include <condition_variable>
#include <thread>
#include <iostream>

// 全局互斥锁：保护共享变量ready的访问，避免数据竞争
std::mutex mtx;
// 条件变量：用于线程间的等待-通知同步机制
std::condition_variable cv;
// 共享标志位：标记生产者是否完成任务（false未就绪，true已就绪）
bool ready = false;

// 生产者线程函数：模拟生产过程，完成后通知消费者
void producer() {
    // 模拟生产耗时操作（如数据生成、文件读取等）
    std::this_thread::sleep_for(std::chrono::seconds(1));
    
    {
        // 加锁修改共享变量，确保线程安全
        std::lock_guard<std::mutex> lock(mtx);
        ready = true;  // 标记生产完成，更新共享状态
    }  // lock_guard析构自动解锁，释放互斥锁
    
    // 发送通知：唤醒一个等待在该条件变量上的线程（消费者）
    cv.notify_one();
}

// 消费者线程函数：等待生产完成后执行消费逻辑
void consumer() {
    // 用unique_lock而非lock_guard，因为条件变量wait需要灵活的锁操作（解锁/加锁）
    std::unique_lock<std::mutex> lock(mtx);
    
    // 等待条件满足：
    // 1. 先解锁让生产者线程能获取锁修改ready，并阻塞，直到被notify_one()唤醒
    // 2. 唤醒后重新加锁，检查lambda条件（ready是否为true）
    // 3. 条件不满足则重新解锁并阻塞（防止虚假唤醒），满足则退出等待，继续执行后续代码
    cv.wait(lock, []{ return ready; });
    
    // 条件满足后执行消费逻辑
    std::cout << "条件满足，执行消费逻辑\n";
}

int main() {
    // 创建生产者线程t1和消费者线程t2
    std::thread t1(producer);
    std::thread t2(consumer);
    
    // 等待子线程执行完毕，避免主线程提前退出导致程序终止
    t1.join();
    t2.join();
    
    return 0;
}
```

### 二、`std::unique_lock`与`std::lock_guard`的对比

| 特性           | `std::unique_lock`                         | `std::lock_guard`                      |
| -------------- | ------------------------------------------ | -------------------------------------- |
| 灵活性         | 高（支持延迟 / 尝试 / 超时锁定、手动解锁） | 低（构造加锁，析构解锁，不可手动操作） |
| 性能           | 略低（额外状态管理）                       | 高效（轻量级封装）                     |
| 与条件变量配合 | 支持（必须用`unique_lock`）                | 不支持                                 |
| 所有权转移     | 支持（移动语义）                           | 不支持                                 |

### 三、使用场景

- **需要精细控制锁的生命周期**（如提前解锁、重复加锁）；
- **与条件变量配合**（唯一选择）；
- **需要尝试锁定或超时锁定**；
- **需要转移锁所有权**（如函数返回锁）。

如果仅需 “构造加锁、析构解锁” 的简单场景，优先用`std::lock_guard`（更高效）；若需灵活操作，用`std::unique_lock`。

### 总结

`std::unique_lock`是**全能型锁管理器**，通过支持动态锁操作和条件变量配合，解决了`std::lock_guard`的局限性。其核心价值在于**灵活性**，代价是轻微的性能开销，是 C++ 多线程同步中不可或缺的工具。

## 避免死锁之一次多锁

> 需要获取多个时，使用std::lock。可以一次锁住两个或者两个以上的互斥量。失败了会解锁已锁上的。

当需要同时获取多个互斥锁时，直接依次调用`lock()`可能导致**死锁**（例如线程 1 持有锁 A 等待锁 B，线程 2 持有锁 B 等待锁 A）。`std::lock`可以解决这个问题：它能一次性锁住多个互斥量，若其中一个锁无法获取，则自动释放已获取的锁，避免死锁。

### 示例场景

模拟两个线程同时操作两个共享资源（如账户转账），需要同时锁住两个互斥锁，用`std::lock`保证原子性加锁。

### 代码示例

```cpp
#include <iostream>
#include <thread>
#include <mutex>
#include <stdexcept>

// 两个共享资源的互斥锁
std::mutex mtx1;
std::mutex mtx2;

// 模拟转账操作：需要同时锁住两个账户的锁
void transfer(int from, int to, int amount) {
    // 使用std::lock一次性锁住多个互斥锁，避免死锁
    // 若其中一个锁无法获取，会自动释放已获取的锁
    std::lock(mtx1, mtx2);

    // 用std::adopt_lock标记：表示互斥锁已被手动锁住，交由lock_guard接管所有权
    std::lock_guard<std::mutex> lock1(mtx1, std::adopt_lock);
    std::lock_guard<std::mutex> lock2(mtx2, std::adopt_lock);

    // 模拟转账逻辑（此处简化为打印）
    std::cout << "从账户" << from << "转账" << amount << "到账户" << to << "\n";

    // lock_guard析构时自动解锁，无需手动操作
}

int main() {
    // 创建两个线程，分别执行转账操作（可能涉及相同的两个锁）
    std::thread t1(transfer, 1, 2, 100);
    std::thread t2(transfer, 2, 1, 200);

    t1.join();
    t2.join();

    return 0;
}
```

### 关键说明

1. **`std::lock`的作用**

   `std::lock(mtx1, mtx2)`会按**避免死锁的顺序**尝试获取所有传入的互斥锁：

   - 若所有锁都成功获取，则继续执行；
   - 若某个锁无法获取（已被其他线程占用），则自动释放已获取的锁，重新尝试，直到全部获取成功。

2. **配合`std::lock_guard`接管锁**

   `std::lock`仅负责加锁，需手动保证解锁。因此用`std::lock_guard`并传入`std::adopt_lock`标记：

   - `std::adopt_lock`表示 “互斥锁已被当前线程锁住，`lock_guard`直接接管所有权”；
   - 这样`lock_guard`析构时会自动解锁，避免手动解锁的遗漏。

3. **避免死锁的原理**

   `std::lock`内部通过算法保证获取多个锁的顺序一致（无论传入顺序如何），从而避免 “线程 1 锁 A 等 B，线程 2 锁 B 等 A” 的死锁场景。

### 扩展：`std::scoped_lock`（C++17 简洁替代）

C++17 引入`std::scoped_lock`，可直接替代`std::lock + lock_guard`，更简洁且安全：

```cpp
void transfer(int from, int to, int amount) {
    // std::scoped_lock直接锁住多个互斥锁，析构时自动解锁
    std::scoped_lock lock(mtx1, mtx2);

    std::cout << "从账户" << from << "转账" << amount << "到账户" << to << "\n";
}
```

`std::scoped_lock`是`std::lock`的 RAII 封装，无需手动处理锁的接管，推荐优先使用（C++17 及以上）。

### 总结

`std::lock`是多锁场景下的 “死锁克星”，通过原子化获取多个锁 + 自动回滚已获取的锁，保证线程安全。配合`lock_guard`或`scoped_lock`可实现自动解锁，避免资源泄漏。

## `std::once_flag`与`std::call_once`的核心作用

* #### ----> 保护共享数据的初始化过程

`std::once_flag`是一个标记类型，`std::call_once`通过这个标记确保**无论多少线程调用，指定函数仅被执行一次**（或直到函数成功执行完毕）。这是实现线程安全的 “一次性初始化” 的高效方案，常用于单例模式、全局资源初始化等场景。

### 一、核心作用

- **`std::once_flag`**：是一个标记类型，用于记录函数是否已成功执行过，是`std::call_once`的 “状态标记器”。
- **`std::call_once`**：通过`std::once_flag`的状态，确保**无论多少线程调用，关联的函数仅被执行一次**（或直到函数成功执行完毕）。

### 二、基本用法

#### 1. 语法格式

```cpp
// 定义once_flag（全局/静态/成员变量，确保所有线程共享）
std::once_flag flag;

// 调用call_once：flag标记状态，f是要执行的函数，args是函数参数
std::call_once(flag, f, args...);
```

#### 2.示例

```cpp
// 定义once_flag标记（全局或静态，确保所有线程共享）
std::once_flag init_flag;

// 需要只执行一次的初始化函数
void init_function(int num, const std::string& msg) {
    std::cout << "call_once: 初始化函数执行！参数：" << num << ", " << msg << "\n";
    // 模拟初始化逻辑（如加载配置、创建单例对象等）
}

// 线程函数：每个线程都会尝试调用init_function，但仅第一次有效
void thread_task(int id) {
    std::cout << "线程" << id << "尝试调用初始化函数...\n";
    
    // 调用call_once：确保init_function仅执行一次
    std::call_once(init_flag, init_function, 100, "hello call_once");
    
    std::cout << "线程" << id << "初始化完成（或跳过）\n";
}
```

### 三、关键特性

#### 1. 唯一性：函数仅执行一次

- 第一个调用`std::call_once`的线程会执行目标函数，并将`once_flag`标记为 “已完成”；
- 后续所有线程调用时，检测到标记为 “已完成”，直接跳过函数执行（**即使参数不同**）。

#### 2. 异常容错：失败后允许重试

- 若目标函数执行时抛出异常，`once_flag`不会被标记为 “完成”；重置～
- 其他线程仍可继续调用`std::call_once`，直到某线程成功执行完函数。

#### 3. 线程安全：无数据竞争

- 底层通过**原子操作**检查`once_flag`状态，避免多个线程同时执行函数；
- 使用**内存屏障**保证所有线程看到一致的标记状态，无需手动加锁。

# C++11 std::future 系列详解（含代码示例）

## 一、核心概念总览

`std::future` 是 C++11 异步编程的核心组件，本质是**异步操作结果的 “占位符”** —— 它不直接存储结果，而是关联一个异步任务（线程、函数等），允许我们在未来某个时间点获取任务的返回值或异常。

### 1.1 std::future 的三种状态

| 状态                  | 含义                               | 典型操作场景                        |
| --------------------- | ---------------------------------- | ----------------------------------- |
| 未就绪（empty）       | 异步任务尚未执行完成               | 任务刚启动，未调用 `get()`/`wait()` |
| 就绪（ready）         | 异步任务完成，结果已存储但未被获取 | 任务执行结束，未调用 `get()`        |
| 已获取（valid=false） | 结果通过 `get()` 取出，future 失效 | 调用 `get()` 后                     |

> 关键特性：`std::future` 只能**移动语义**（不能复制，避免多个线程同时取结果）；若需多线程共享结果，用 `std::shared_future`（支持复制）。

### 1.2 同步 vs 异步、阻塞 vs 非阻塞（核心区别）

很多人混淆这两组概念，用表格和通俗语言区分：

| 维度                   | 核心关注     | 通俗解释                                                     |
| ---------------------- | ------------ | ------------------------------------------------------------ |
| 同步（Synchronous）    | 任务执行顺序 | 调用者必须等待任务完成才能继续（“你做完我再干”）             |
| 异步（Asynchronous）   | 任务执行顺序 | 调用者无需等待，任务在后台执行（“你做你的，我做我的”）       |
| 阻塞（Blocking）       | 线程状态     | 线程暂停执行，等待某个条件（如任务完成、I/O 就绪）（“原地等，啥也不干”） |
| 非阻塞（Non-blocking） | 线程状态     | 线程不暂停，立即返回结果（“不等了，先干别的，回头再查”）     |

#### 四种组合示例（结合日常场景）

1. **同步阻塞**：打电话问快递员 “我的快递到了吗？”，拿着电话一直等对方查完回复（你啥也干不了）。
2. **同步非阻塞**：打电话问快递员，对方说 “正在查，你 10 分钟后再打过来”，你挂电话继续工作，10 分钟后主动查询（轮询）。
3. **异步阻塞**：用快递 APP 下单后，一直盯着 APP 刷新等取件通知（你啥也干不了，没必要，浪费异步优势）。
4. **异步非阻塞**：用快递 APP 下单后，继续做自己的事，等 APP 推送取件通知（最高效，充分利用资源）。

## 二、std::future 的三种创建方式（含代码）

`std::future` 不能直接构造，必须通过以下三种方式间接创建，分别对应不同的异步场景：

### 2.1 方式 1：std::async（最常用，自动管理线程）

`std::async` 是 “一站式异步工具”：自动创建线程（或延迟执行）、包装任务、返回 `std::future`，无需手动管理线程生命周期。

#### 核心语法

```cpp
template <class Fn, class... Args>
std::future<std::result_of_t<std::decay_t<Fn>(std::decay_t<Args>...)>>
async( std::launch policy, Fn&& fn, Args&&... args );
```

- `policy`：启动策略（可选，默认由系统决定）
  - `std::launch::async`：强制创建新线程执行任务（真正异步）
  - `std::launch::deferred`：延迟执行（调用 `get()`/`wait()` 时才在当前线程执行，无新线程）
- `fn`：可调用对象（函数、lambda、函数对象）
- `args`：`fn` 的参数

#### 代码示例（std::async 基本用法）

```cpp
#include <iostream>
#include <future>
#include <chrono>

// 模拟耗时任务：计算a+b，耗时1秒
int add(int a, int b) {
    std::this_thread::sleep_for(std::chrono::seconds(1)); // 模拟耗时
    std::cout << "add任务执行线程ID：" << std::this_thread::get_id() << std::endl;
    return a + b;
}

int main() {
    std::cout << "主线程ID：" << std::this_thread::get_id() << std::endl;

    // 1. 强制异步（std::launch::async）：创建新线程执行add
    std::future<int> fut1 = std::async(std::launch::async, add, 10, 20);
    // 2. 延迟执行（std::launch::deferred）：调用get()时才执行，无新线程
    std::future<int> fut2 = std::async(std::launch::deferred, add, 30, 40);

    std::cout << "主线程继续执行，无需等待任务完成" << std::endl;

    // 获取fut1结果（阻塞主线程，直到add执行完成）
    int res1 = fut1.get(); // 阻塞1秒左右
    std::cout << "10+20=" << res1 << std::endl;

    // 获取fut2结果（此时才执行add，在主线程中）
    int res2 = fut2.get(); 
    std::cout << "30+40=" << res2 << std::endl;

    return 0;
}
```

#### 关键说明

- `std::async` 无需手动创建 `std::thread`，自动管理线程（避免线程泄漏）。
- `get()` 是 “消费型” 接口：调用一次后，`future` 失效（再次调用 `get()` 会崩溃）。
- 若未指定策略（`std::async(add, 10,20)`），系统可能选择延迟执行（如资源紧张时）。

### 2.2 方式 2：std::packaged_task（包装任务，手动调度线程）

`std::packaged_task` 是 “任务包装器”—— 将可调用对象包装成一个 “可在任意线程执行” 的任务，包装后会关联一个 `std::future`，用于获取结果。

核心场景：**解耦任务定义和执行**（比如先定义任务，再提交到线程池执行）。

#### 核心语法

```cpp
template <class Ret, class... Args>
class packaged_task<Ret(Args...)>;
```

- `Ret`：任务返回值类型
- `Args`：任务参数类型

#### 关键方法

- `get_future()`：获取关联的 `std::future`（只能调用一次）。
- `operator()`：执行包装的任务（会触发 `future` 状态变为就绪）。

#### 代码示例（std::packaged_task 用法）

```cpp
#include <iostream>
#include <future>
#include <thread>
#include <chrono>

// 模拟耗时任务：计算阶乘
long long factorial(int n) {
    std::this_thread::sleep_for(std::chrono::milliseconds(500));
    long long res = 1;
    for (int i = 1; i <= n; ++i) res *= i;
    return res;
}

int main() {
    // 1. 包装任务（返回值long long，参数int）
    std::packaged_task<long long(int)> task(factorial);
    // 2. 获取关联的future
    std::future<long long> fut = task.get_future();

    // 3. 手动创建线程执行任务（任务也可在主线程执行：task(5)）
    std::thread t(std::move(task), 5); // packaged_task只能移动

    // 4. 主线程做其他事
    std::cout << "主线程等待阶乘结果..." << std::endl;

    // 5. 获取结果（阻塞，直到任务执行完成）
    long long res = fut.get();
    std::cout << "5的阶乘是：" << res << std::endl;

    t.join(); // 等待线程结束
    return 0;
}
```

#### 关键说明

- `packaged_task` 本身是 “可调用对象”（可作为线程函数参数）。
- 必须通过 `std::move` 传递 `packaged_task`（它不可复制）。
- 若任务未执行就调用 `get()`，会一直阻塞（直到线程执行任务）。

### 2.3 方式 3：std::promise（手动设置结果，线程间通信）

`std::promise` 用于**线程间传递结果或异常**：一个线程（生产者）通过 `promise` 设置值 / 异常，另一个线程（消费者）通过关联的 `future` 获取结果。

核心场景：生产者 - 消费者模式（需手动同步任务执行状态）。

#### 关键方法

| 方法                 | 功能                                   | 注意事项                        |
| -------------------- | -------------------------------------- | ------------------------------- |
| `get_future()`       | 返回关联的 `std::future`（仅调用一次） | 多次调用会抛异常                |
| `set_value(T value)` | 设置结果（使 future 变为就绪）         | 仅调用一次，调用后 promise 失效 |
| `set_exception(ex)`  | 设置异常（如 `std::runtime_error`）    | 消费者调用 `get()` 时会捕获异常 |

#### 代码示例（std::promise 线程通信）

```cpp
#include <iostream>
#include <future>
#include <thread>
#include <chrono>
#include <stdexcept>

// 生产者线程：计算结果并通过promise设置
void producer(std::promise<int> prom) {
    std::this_thread::sleep_for(std::chrono::seconds(1)); // 模拟耗时计算
    try {
        int result = 100 * 2; // 计算结果
        prom.set_value(result); // 设置正常结果
        // 若发生错误，设置异常：
        // prom.set_exception(std::make_exception_ptr(std::runtime_error("计算失败")));
    } catch (...) {
        // 捕获函数内异常，传递给消费者
        prom.set_exception(std::current_exception());
    }
}

// 消费者线程：通过future获取结果
void consumer(std::future<int> fut) {
    std::cout << "消费者等待结果..." << std::endl;
    try {
        int res = fut.get(); // 阻塞，直到获取结果或异常
        std::cout << "消费者获取到结果：" << res << std::endl;
    } catch (const std::exception& e) {
        std::cout << "消费者捕获异常：" << e.what() << std::endl;
    }
}

int main() {
    // 1. 创建promise和关联的future
    std::promise<int> prom;
    std::future<int> fut = prom.get_future();

    // 2. 启动生产者和消费者线程（promise必须移动）
    std::thread t_producer(producer, std::move(prom));
    std::thread t_consumer(consumer, std::move(fut));

    // 3. 等待线程结束
    t_producer.join();
    t_consumer.join();

    return 0;
}
```

#### 输出结果（正常情况）

```plaintext
消费者等待结果...
消费者获取到结果：200
```

#### 异常场景测试

若取消 `producer` 中 `set_exception` 的注释，输出会变为：

```plaintext
消费者等待结果...
消费者捕获异常：计算失败
```

#### 关键说明

- `std::promise` 只能移动（不可复制），确保结果唯一传递。
- `set_value`/`set_exception` 必须调用一次（未调用则消费者 `get()` 一直阻塞；调用多次抛异常）。

## 三、std::future 关键方法详解

### 3.1 get ()：获取结果（核心方法）

- 功能：阻塞当前线程，直到 `future` 就绪，返回结果（或抛出异常）。
- 特性：**消费型**—— 调用一次后，`future` 失效（`valid()` 返回 `false`），再次调用会崩溃。

#### 代码示例（异常传递）

```cpp
#include <iostream>
#include <future>
#include <stdexcept>

int divide(int a, int b) {
    if (b == 0) {
        throw std::runtime_error("除数不能为0");
    }
    return a / b;
}

int main() {
    auto fut = std::async(divide, 10, 0); // 除数为0，会抛异常
    try {
        int res = fut.get(); // 捕获divide抛出的异常
    } catch (const std::runtime_error& e) {
        std::cout << "捕获异常：" << e.what() << std::endl; // 输出：除数不能为0
    }
    std::cout << "future是否有效？" << (fut.valid() ? "是" : "否") << std::endl; // 输出：否
    return 0;
}
```

### 3.2 wait ()：等待任务完成（不获取结果）

- 功能：阻塞当前线程，直到 `future` 就绪（任务完成），但不获取结果。
- 适用场景：只想等待任务完成，不需要结果（如确保资源释放）。

#### 代码示例

```cpp
#include <iostream>
#include <future>
#include <chrono>

void task() {
    std::this_thread::sleep_for(std::chrono::seconds(2));
    std::cout << "任务完成！" << std::endl;
}

int main() {
    auto fut = std::async(task);
    std::cout << "等待任务完成..." << std::endl;
    fut.wait(); // 阻塞2秒，直到任务完成
    std::cout << "主线程继续执行" << std::endl;
    return 0;
}
```

### 3.3 wait_for ()：超时等待（非阻塞核心）

- 功能：等待指定时间，返回 `future_status` 枚举（表示等待结果）。
- 枚举值：
  - `std::future_status::ready`：任务已完成。
  - `std::future_status::timeout`：超时（任务未完成）。
  - `std::future_status::deferred`：任务是延迟执行（`std::launch::deferred`），未启动。

#### 代码示例（超时等待）

```cpp
#include <iostream>
#include <future>
#include <chrono>

void long_task() {
    std::this_thread::sleep_for(std::chrono::seconds(3)); // 任务耗时3秒
}

int main() {
    auto fut = std::async(std::launch::async, long_task);
    std::cout << "等待任务完成（最多等待2秒）..." << std::endl;

    // 等待2秒
    auto status = fut.wait_for(std::chrono::seconds(2));

    switch (status) {
        case std::future_status::ready:
            std::cout << "任务已完成！" << std::endl;
            break;
        case std::future_status::timeout:
            std::cout << "等待超时，任务仍在执行！" << std::endl;
            break;
        case std::future_status::deferred:
            std::cout << "任务延迟执行，未启动！" << std::endl;
            break;
    }

    fut.wait(); // 继续等待任务完成
    std::cout << "任务最终完成" << std::endl;
    return 0;
}
```

#### 输出结果

```plaintext
等待任务完成（最多等待2秒）...
等待超时，任务仍在执行！
任务最终完成
```

### 3.4 valid ()：检查 future 是否有效

- 功能：判断 `future` 是否关联了异步任务（未调用 `get()`、未移动、未析构）。
- 返回值：`true`（有效）/`false`（无效）。

#### 代码示例

```cpp
#include <iostream>
#include <future>

int foo() { return 42; }

int main() {
    std::future<int> fut1 = std::async(foo);
    std::cout << "fut1有效？" << (fut1.valid() ? "是" : "否") << std::endl; // 是

    std::future<int> fut2 = std::move(fut1); // fut1移动给fut2，fut1失效
    std::cout << "fut1有效？" << (fut1.valid() ? "是" : "否") << std::endl; // 否
    std::cout << "fut2有效？" << (fut2.valid() ? "是" : "否") << std::endl; // 是

    fut2.get(); // fut2调用get()后失效
    std::cout << "fut2有效？" << (fut2.valid() ? "是" : "否") << std::endl; // 否

    return 0;
}
```

## 四、C++ 时间表示（std::chrono）

异步编程中经常需要 “超时等待”“休眠”，C++11 提供 `std::chrono` 库统一处理时间，避免平台差异。

### 4.1 核心时钟类型

| 时钟类型                             | 特点                                   | 适用场景                         |
| ------------------------------------ | -------------------------------------- | -------------------------------- |
| `std::chrono::system_clock`          | 系统时间（可被修改，如手动调时间）     | 获取当前日历时间（年 / 月 / 日） |
| `std::chrono::steady_clock`          | 稳定时钟（不可修改，单调递增）         | 计算时间间隔（如超时等待）       |
| `std::chrono::high_resolution_clock` | 高精度时钟（通常是 steady_clock 别名） | 需要高精度计时的场景             |

### 4.2 时间间隔（Duration）

`std::chrono::duration` 表示时间间隔，常用预定义类型：

- `std::chrono::nanoseconds`（纳秒）
- `std::chrono::microseconds`（微秒）
- `std::chrono::milliseconds`（毫秒）
- `std::chrono::seconds`（秒）
- `std::chrono::minutes`（分钟）
- `std::chrono::hours`（小时）

### 4.3 常用时间操作

#### （1）获取当前时间

```cpp
// 稳定时间（推荐用于时间间隔计算）
auto now_steady = std::chrono::steady_clock::now();
// 系统时间（用于日历时间）
auto now_system = std::chrono::system_clock::now();
```

#### （2）休眠线程

```cpp
#include <chrono>
#include <thread>

// 休眠100毫秒（当前线程暂停100ms）
std::this_thread::sleep_for(std::chrono::milliseconds(100));

// 休眠到指定时间点（比如当前时间+500ms）
auto wakeup_time = std::chrono::steady_clock::now() + std::chrono::milliseconds(500);
std::this_thread::sleep_until(wakeup_time);
```

#### （3）计算时间间隔

```cpp
#include <iostream>
#include <chrono>

int main() {
    auto start = std::chrono::steady_clock::now();

    // 模拟耗时操作
    std::this_thread::sleep_for(std::chrono::seconds(1));

    auto end = std::chrono::steady_clock::now();
    // 计算时间间隔（转换为毫秒）
    auto duration = std::chrono::duration_cast<std::chrono::milliseconds>(end - start).count();

    std::cout << "耗时：" << duration << "ms" << std::endl; // 输出约1000ms
    return 0;
}
```

## 五、总结：如何选择异步工具？

| 工具                 | 核心优势                | 适用场景                                 |
| -------------------- | ----------------------- | ---------------------------------------- |
| `std::async`         | 简单易用，自动管理线程  | 快速实现异步任务，无需手动管理线程       |
| `std::packaged_task` | 解耦任务定义和执行      | 自定义线程池、任务队列（需手动调度线程） |
| `std::promise`       | 手动控制结果 / 异常传递 | 复杂线程间通信（生产者 - 消费者模式）    |

## 六、常见坑点提醒

1. **`get()` 只能调用一次**：调用后 `future` 失效，再次调用会崩溃。
2. **`std::async` 默认策略不确定**：可能延迟执行，若需强制异步，显式指定 `std::launch::async`。
3. **`promise` 未设置结果**：消费者 `get()` 会一直阻塞，需确保生产者调用 `set_value`/`set_exception`。
4. **`future` 移动后失效**：`std::future` 不可复制，移动后原对象不再关联任务。
5. **避免异步阻塞**：异步任务的优势是 “非阻塞”，若立即调用 `get()`，会退化为同步阻塞（浪费资源）。

## 内存模型和原子操作

C++11 引入的`std::atomic`系列类型（如`std::atomic_int`、`std::atomic_bool`）是多线程编程中**无锁同步**的基础，其核心特点：

1. 操作原子性：对原子变量的读 / 写 / 修改操作不会被线程调度器打断，避免 "读 - 改 - 写" 中间状态暴露
2. 禁止隐式拷贝：原子变量的拷贝构造和拷贝赋值被禁用（本质是 "读 + 写" 的组合操作无法保证原子性）
3. 内存顺序控制：通过`memory_order`枚举控制操作的可见性和指令重排规则，平衡性能与正确性

### 原子操作基础用法（load/store）

原子变量不能直接用`=`赋值或拷贝，必须通过`load()`（读）和`store()`（写）成员函数操作，默认使用最强内存顺序`memory_order_seq_cst`。

#### 代码示例 1：基础原子操作

```cpp
// 原子整型变量（共享资源）
atomic_int shared_val(0);

// 写线程：循环自增
void writer() {
    for (int i = 0; i < 1000000; ++i) {
        // 写操作：store默认memory_order_seq_cst
        //shared_val.store(shared_val.load() + 1); 错的❌shared_val.load() + 1不是原子性的
      
        // 等价于 shared_val++（原子自增，内部封装了load+store的原子组合）
      	shared_val.fetch_add(1, memory_order_seq_cst);
    }
}

// 读线程：打印最终值
void reader() {
    // 读操作：load默认memory_order_seq_cst
    int val = shared_val.load();
    cout << "最终值：" << val << endl;
}
```

#### 关键说明：

- 直接写`shared_val = 42`或`int x = shared_val`在 C++ 中是允许的（编译器会隐式转换为`store`/`load`），但**不推荐**（显式调用更清晰，且便于指定内存顺序）
- 两个写线程并发自增，最终结果一定是`2000000`（原子操作保证无数据竞争）
- 若将`atomic_int`改为普通`int`，最终结果可能小于`2000000`（数据竞争导致写覆盖）

### 内存顺序模型深度解析

内存顺序（`memory_order`）的核心作用是**限制编译器和 CPU 的指令重排**，并保证多线程间操作的可见性。不同内存顺序的性能和约束强度不同，需根据场景选择。

### 四种核心内存顺序对比

| 内存顺序               | 核心约束                                                     | 适用场景                         | 性能成本 |
| ---------------------- | ------------------------------------------------------------ | -------------------------------- | -------- |
| `memory_order_seq_cst` | 全局序列一致：所有线程看到的原子操作顺序完全相同（默认）     | 需强一致性的场景（如全局计数器） | 最高     |
| `memory_order_relaxed` | 仅保证操作本身原子性，不限制重排，不保证跨线程可见性         | 独立原子变量（如统计访问次数）   | 最低     |
| `memory_order_acquire` | 读操作：禁止后续读 / 写操作重排到该操作之前；可见之前的 release 操作的写内容 | 线程间同步的 "读端"              | 中       |
| `memory_order_release` | 写操作：禁止之前读 / 写操作重排到该操作之后；写内容对后续 acquire 操作可见 | 线程间同步的 "写端"              | 中       |
| `memory_order_consume` | 读操作：仅禁止**依赖于该原子变量**的后续操作重排（弱于 acquire） | 依赖原子变量值的场景             | 中低     |

| 内存顺序 | 是否禁止重排                       | 是否提供跨线程同步    | 性能   | 典型用途     |
| -------- | ---------------------------------- | --------------------- | ------ | ------------ |
| seq_cst  | 最强                               | 是                    | 最慢   | 默认，简单   |
| acquire  | 不能把后面的读移到前面             | 是（与 release 配对） | 中     | 读取同步变量 |
| release  | 不能把前面的写移到后面             | 是                    | 中     | 写入同步变量 |
| acq_rel  | 上面两者结合                       | 是                    | 中     | RMW 操作     |
| relaxed  | 不禁止任何重排                     | 否                    | 最快   | 计数器       |
| consume  | 理论弱于 acquire，几乎等同 acquire | 是（理论）            | 未实现 | 废弃         |



### 代码案例

```cpp
#include <iostream>
#include <atomic>
#include <thread>
#include <vector>

std::atomic_bool ready(false);
std::vector<int> g_data;

void producer() {
    g_data.push_back(10);
    g_data.push_back(20);
    g_data.push_back(30);

    ready.store(true, std::memory_order_release);	// 设置ready为true，通知消费者数据已准备好
}

void consumer() {
    while (!ready.load(std::memory_order_acquire)) {
        // spin, 自旋锁，直到生产者设置ready为true，消费者才继续
    }

    std::cout << "数据大小：" << g_data.size() << std::endl; // 3

    for (int num : g_data) {
        std::cout << num << " "; // 10 20 30
    }
    std::cout << std::endl;
}

int main() {
    std::thread t2(consumer);
  	std::thread t1(producer);

    t1.join();
    t2.join();
}
```

`memory_order_release` 对生产者的约束有两个核心点：

- **原子性**：`ready`的赋值操作是原子的（不会被线程调度打断，要么没写，要么写完`true`，无中间状态）—— 这是所有原子操作的基础，避免消费者读到`ready`的 “半修改状态”（但原子性本身不解决可见性和重排序）。
- **释放语义（核心）**：**禁止所有在`store(release)`之前的写操作（包括非原子操作）被重排到`store`之后**。
  - 换句话说：生产者中所有 “在ready.store之前的代码”（即 3 次g_data.push_back），必须在ready被设为true之前“真正完成”（包括数据从 CPU 缓存刷到主存，或标记为 “其他线程可见”）。

用通俗的话讲：`release` 是生产者的 “承诺”——“我在设置`ready=true`之前，已经把所有要写的共享数据（`g_data`）都准备好了，并且这些数据对其他线程是可见的，不会有任何写操作被偷偷放到`ready=true`之后。”

#### 2. 消费者线程（`consumer`）：`ready.load(std::memory_order_acquire)`

`memory_order_acquire` 对消费者的约束也有两个核心点：

- **原子性**：`ready`的读取操作是原子的（避免读到中间状态）—— 同样是原子操作的基础。
- **获取语义（核心）**：**禁止所有在`load(acquire)`之后的读操作（包括非原子操作）被重排到`load`之前**。
  - 更关键的是：如果消费者的load(acquire)读取到了生产者store(release)写入的true，那么生产者在`store(release)`之前的所有写操作，对消费者在`load(acquire)`之后的所有读操作都是可见的。

用通俗的话讲：`acquire` 是消费者的 “约定”——“我只有读到`ready=true`，才会去读`g_data`；而且一旦读到`ready=true`，我就能看到生产者在设置`ready=true`之前写的所有`g_data`内容，不会读到旧数据。”
